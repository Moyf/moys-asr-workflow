# HTML 工具页设计与交互规范

适用范围：`tools/` 下所有由 Agent 编写或生成的浏览器工具页，包括确认页、核对页、对比页、审阅页和仪表盘。这类页面供维护者在本机长时间使用，多以 `file://` 单文件或 localhost 页面打开。新建页面必须遵循本规范；修改既有页面时，至少让改动部分遵循，不要顺手把整页推倒重写（整页改版需维护者明确要求）。

性能与测量约定见 [AGENTS.md](AGENTS.md)，本文不重复。参考实现是 `term-extract/term_extract/report.py` 的确认页模板，它在 20 条实测反馈后定型（台账见 `docs/logs/release1.11.0/261109_术语提取反馈/TEST_FEEDBACK_术语提取.md`）。下文每条规则都来自真实踩坑，「为什么」比「怎么做」更重要，遇到本文没写到的情况，按同样的理由推断。

---

## 1. 先定任务，再定布局

工具页通常只做一件事：**审阅一批条目 → 做选择 → 导出结果**。动手前先回答：

1. 用户的主操作是什么（勾选、核对、比较、改值）？整页围绕它组织，主操作必须一步可达。
2. 一次要处理多少条（10 条、100 条还是上千条）？这决定密度、分组和性能策略。
3. 判断一条需要看什么信息？只把这些信息放在首屏卡片上，其余收进「展开明细」。
4. 结果去哪里（下载、复制、回写文件）？导出入口必须常驻可见，并能预览导出内容。

不要从「把数据都摆出来」开始。原确认页的问题就是信息平铺：一行灰字堆满「独立事件 1 次 · 命中 3 次 · 平均置信度 1.00」，用户看不出重点。

## 2. 视觉基线：沿用 MAW Launcher 令牌

### 2.1 配色

- **底色和文字色照搬 Launcher**（`web/launcher/launcher.css` 顶部的 `:root` 与 `[data-theme="light"]`），不要另起一套。工具页是 MAW 的一部分，风格应与主产品一致。维护者已明确要求过「和 Launcher 保持一致」。
- **强调色同样照搬**：深色 `--accent:#f09a50`（橙）、浅色 `--accent:#c84545`（红），连同 `--accent-hover`、`--accent-text`。不要因为「红色和某种标注撞色」就自行换色；确有冲突时先把取舍告诉维护者，由维护者决定。
- **必须同时提供深色和浅色**：
  - 默认跟随系统 `prefers-color-scheme`，提供 ◐ 切换按钮，选择存入 `localStorage`（键名带工具前缀，如 `maw-term-report-theme`）；
  - 主题在 `<head>` 内用一段同步内联脚本设置 `data-theme`，**在首帧绘制前**完成，避免先白后黑的闪烁；
  - 每个主题写 `color-scheme: dark|light`，让原生控件（滚动条、select 下拉）跟着变。
- **所有颜色都走 CSS 变量**，样式规则里不出现裸色值。需要浅色底时用 `color-mix(in oklab, var(--accent) 14%, transparent)` 从令牌派生，而不是另写一个近似色。
- 语义色单独成组：`--good`（保留/加分）、`--bad`（排除/扣分）、`--warn`（不可用/警告），分级色单独成组（如 `--tier-rec/maybe/weak/noise`），深浅主题各给一套。
- 图像标注（OCR 框等）用独立的 `--mark` 与 `--mark-halo`（描边 + 反色外晕），保证在任何画面上都能看清。

### 2.2 字体与数字

- 字体栈沿用 Launcher 的 `--font-sans`（中文优先系统字体），数字和时间码用 `--font-mono` 加 `font-variant-numeric: tabular-nums`，让纵向排列的数字对齐。
- 标题一律正体，不用斜体。强调用字重、颜色或底色。
- 字号层级要拉开：条目主词 18px/700，正文 13–14px，辅助信息 12–12.5px。不要所有东西都是 12.5px 灰字。
- 统计数字（顶栏「77 候选」）用「大号等宽数字 + 小号标签」，数字是主角，标签是注释。

### 2.3 形状、间距与动效

- 圆角用令牌：`--r-sm:6px`（按钮、输入框）、`--r-md:9px`（卡片）、`--r-lg:14px`（面板）。
- 间距以 4px 为步长；相邻控件、卡片之间至少 8px（根 AGENTS.md「UI 间距约定」同样适用，验收要实测）。
- 徽章用**浅色底填充的胶囊**，不用细描边框。描边徽章在深色底上发虚，读起来像未完成的线框图。
- 过渡统一 `--t-fast:130ms ease-out`，只用于颜色、背景、边框、transform；必须有 `@media (prefers-reduced-motion: reduce)` 关闭过渡。

## 3. 页面骨架

```text
┌ 顶栏（吸顶）───────────────────────────────────────────┐
│ 标题  来源名（省略号截断）            数字统计  ◐ 主题 │
│ [搜索…] [分数 ≥|  ] [字数 ≤|12] [AI|全部▾] 重置筛选  ◯ 精简显示 │
├──────────────────────────────────────┬─────────────────┤
│ ▼ ● 推荐 ≥60 分 · 说明        2/5  全选本组 │ 导出栏（吸顶）  │
│ ┌ 卡片 ─────────────────────────────┐ │  预览词条 ×     │
│ │ ☐ [分数块] 主词 徽章        [缩略图] │ │ [导出] [复制]  │
│ │          指标组 / 上下文 / 明细▾    │ │ [勾推荐][清空] │
│ └──────────────────────────────────┘ │ 快捷键 / 来源   │
└──────────────────────────────────────┴─────────────────┘
```

- **顶栏**：第一行是标题、数据来源和数字统计（总数 / 当前显示 / 已选）；第二行是筛选条。`已选` 用强调色，让用户随时知道自己选了多少。
- **主列 + 右侧导出栏**（≥960px）：主列 `minmax(0,1fr)`，导出栏固定约 300px，`position: sticky`。导出栏超高时自身滚动（`max-height: calc(100vh - 顶栏高 - 余量); overflow: auto`），不能被视口截掉。
- **窄屏（<960px）**：导出栏改为**固定在底部的单行栏**，只放「已选 N 个 ▲ · 复制 · 导出」，点「已选 N 个」展开预览和次要操作。不要把桌面版面板原样堆到页面底部：实测原样堆放占约 220px，列表很短时下方会空出一大片（维护者反馈「下面空出来太多」）。改成单行栏后是 57px。
- **≤560px**：顶栏取消吸顶（`position: static`）。在手机上，吸顶的两行顶栏加底栏会挤掉一半以上的可视区域。
- 吸顶与吸底的偏移**不写死**：用 `ResizeObserver` 量出顶栏、底栏的实际高度，写进 `--top-stick`、`--dock-h`，供分组头吸顶、`scroll-margin`、页面底部留白和 toast 位置使用。顶栏会因换行改变高度，写死的偏移在某个宽度下必然错位。
- 页面级永不横向滚动：`html, body { overflow-x: clip }`；网格轨道用 `minmax(0,1fr)`；长词 `overflow-wrap: anywhere; min-width: 0`；长单行文本用省略号截断，并把全文放进 `title`。

## 4. 条目卡片

### 4.1 信息分层

卡片首屏只放「判断这一条需要的信息」，从左到右依次是：

1. **勾选框**（左列）；
2. **分数块**：分级色浅底的方块，大号数字下面写分级名（「44 / 待定」）。分数是做判断的第一依据，不能只是标题后面的一个小数字；
3. **主体**：主词（大号粗体）+ 徽章；下一行是**带单位的指标组**；再下一行是第一条上下文；
4. **证据缩略图**（右列）：首个证据帧常驻显示，多帧时加「N 帧」角标。不要藏在「展开」里，原版要展开才能看图，审阅效率很低。

其余内容（评分明细、变体、全部上下文、全部时间点、AI 理由、其他证据帧）放进折叠明细。

### 4.2 指标的写法

- 每个数字都带上能自解释的单位，用词贴近用户的理解：写「出现 3 次 · 采样 9 帧 · 置信 93% · 首现 00:01」，不写「独立事件 3 次 · 命中 9 次 · 平均置信度 0.93」。内部术语（事件、命中）用户需要猜含义。
- 比例用百分比，时间用 `mm:ss`。
- 每个指标加 `title`，用一句话解释口径（「同一段连续显示算一次」）。
- 标签用淡色，数字用正文色 + 等宽字体，形成「数字是主角」的节奏。

### 4.3 上下文与明细

- 上下文用**引文条**样式（左边线 + 浅底 + 单行截断），并用 `<mark>` 高亮命中词。不要写成「上下文 xxx」这种前缀小字。
- 明细入口是一个明确的**胶囊按钮**，并标出里面有什么：「证据与理由 · 3 条评分 ⌄」。原生 `▶ 证据与理由` 三角太弱，看不出可以点。
- 明细内部按「标签 | 内容」分行，行间用分隔线；时间点做成等宽小标签；加减分用 `+12`、`−20` 并分别着 `--good`、`--bad` 色。

### 4.4 状态

- **已选**：整卡换底色并加强调色边框，不只是复选框打勾。滚动浏览时要能一眼看出哪些已选。
- **不可用**（如超出热词限制不能导出）：降低不透明度，复选框禁用，徽章写明原因（「不可导出：含非 ASCII 字符时最多 15 个字符」），点击时 toast 提示原因，而不是没有反应。
- 分级色体现在左侧 3px 色条和分数块上，避免整卡染色导致满屏花哨。

## 5. 点击热区

维护者两次反馈热区问题（「只有小框不方便」「希望横着一整条」）。规则如下：

- **整行可点**：点击卡片任意空白处、主词或指标行都会切换勾选。复选框只用来显示状态，不是唯一入口。
- 整行点击必须排除这些元素：缩略图和证据帧（它们打开大图）、按钮、链接、`summary`、展开后的明细区、输入框，以及复选框所在的 label（它自己会触发 change，否则会翻转两次）。参考写法：

  ```js
  list.addEventListener("click", function (ev) {
    var t = ev.target, card = t.closest(".card");
    if (!card || t.closest(".pick,button,a,summary,.more-body,input")) return;
    if (String(window.getSelection())) return; // 用户在拖选复制文字，不算点击
    toggle(card);
  });
  ```

- **有文字选区时不触发**，否则用户想复制一个词，结果把它勾掉了。
- 复选框本身至少 24×24px，并用自绘样式（`appearance: none` + 伪元素对勾），保证深浅主题下都清晰，禁用态用虚线边框区分。
- **分组头整条可点**：折叠与展开的热区是整条组头（约 50px 高、横贯主列），不是标题文字。组头里的操作按钮（「全选本组」）点击时不能触发折叠，在 handler 里用 `ev.target.closest(".tier-pick")` 排除。
- 悬停反馈要覆盖整个热区（整卡或整条组头的背景变化），让用户在点击前就知道哪里可以点。

## 6. 分组

- 按用户的判断层级分组（如推荐 / 待定 / 观察 / 排除），每组有代表色、分数区间和一句说明。
- 噪声组（观察、排除）**默认折叠**；空组不渲染。
- 组头滚动时吸顶（`position: sticky; top: var(--top-stick)`，并给背景色），长列表里始终知道自己在哪一组。
- 组头显示「已选 / 总数」计数胶囊，并提供「全选本组 / 取消本组」。整组操作只作用于可用条目。
- 折叠状态保存在 JS 状态里，筛选重建列表后保持不变。
- 分组边界跟随生成参数（如 `--min-score`）计算，不写死。

## 7. 筛选

- 每个筛选项写成**带前缀标签的分段控件**（`[分数 ≥| 60 ]`），标签简短，完整说明放进 `title`。不要用零散的「最低分数 [  ]」文字加裸输入框。
- 数字输入：
  - 支持悬停滚轮步进：监听 `wheel`（`passive:false`）→ `preventDefault` → `stepUp/stepDown` → 派发 `change`；空值先落到默认值再开始步进；
  - 隐藏原生上下微调箭头（`::-webkit-inner-spin-button` 与 `-moz-appearance: textfield`），光标用 `ns-resize` 暗示可以滚动。
- **默认值不能让整组内容凭空消失**。原「最低分数」默认 0，把 ≤0 分的「排除」组整组挡掉，分组设计直接失效。默认应为「不限」（留空 + placeholder），把降噪交给分组和折叠。
- 搜索输入防抖约 180ms；聚焦搜索框时按 `Esc` 退出。
- 提供「重置筛选」按钮；结果为空时，空状态里也放一个重置按钮，并写明「当前筛选条件下没有候选」。
- 筛选会重建列表，因此**勾选状态不能存在 DOM 里**（见 8.1）。

## 8. 选择、预览与导出

### 8.1 唯一状态源

- 勾选状态存在一个 `Set`（条目索引）里。DOM 只是它的投影。重建列表时根据 `Set` 恢复勾选；修改时用 `setPicked(i, on)` 同步更新 `Set`、复选框和卡片 class。
- 原版把状态存在复选框上，一打搜索词勾选就全丢了，这是真实发生过的缺陷。

### 8.2 导出预览

- 预览和导出使用**同一个函数**生成内容（同样的去重、同样的顺序），保证「所见即所得」。
- 预览用词条（chip）展示，每个词条带 × 可以单独移除，不用回到列表里找。
- 没有可导出内容时，导出和复制按钮禁用（不是点了以后再弹窗说「请先勾选」）；「清空」在没有勾选时禁用；「勾选推荐项」在没有推荐项时禁用。

### 8.3 反馈

- **不用 `alert()`**。它会阻塞页面，打断审阅节奏。统一用 toast：固定在底部居中，`role="status" aria-live="polite"`，约 2.2 秒后消失，位置避开窄屏底栏（`bottom: calc(var(--dock-h) + 24px)`）。
- 每个批量操作都要有结果反馈：「已勾选 12 个推荐项」「已导出 30 个词到 hotwords.txt」「已复制 30 个术语」。
- 剪贴板：优先 `navigator.clipboard.writeText`，失败时回退到 `textarea + execCommand('copy')`，再失败则 toast 建议改用导出。

## 9. 图片与大图弹层

### 9.1 缩略图

- 写上真实宽高：生成端读出图片尺寸，输出 `width`/`height` 属性，并加 `loading="lazy" decoding="async"`。没有尺寸的图片在加载时会造成布局抖动。
- 尺寸约束**只约束一个方向**：缩略图用「定宽、高自动」或「定高、宽自动」。同时写 `max-width` 和 `max-height` 会在两个方向各自压缩，导致图片被压扁（真实事故：280×90，比例约 3.1:1，原图是 16:9）。
- 标注框用相对图片的百分比定位（生成端把像素坐标归一化成 0–1），这样缩略图和大图用同一份数据，纯 CSS 就能对齐。

### 9.2 大图弹层

- 打开：点缩略图、证据帧，或在聚焦卡片上按 `O` / `Enter`。
- 导航：‹ › 按钮加左右方向键，在**当前条目**的证据帧之间循环切换；只有一帧时隐藏按钮；预加载相邻帧。
- 信息栏：显示主词、「n / 总数」和帧时间，并提供**在弹层内直接勾选**的按钮（同时支持快捷键 `X`），看完图就能决定，不必关闭再找。
- 关闭：`Esc`、右上角 ×、点背景；点图片、导航按钮或信息栏里的按钮都不能关闭。
- 打开时锁定页面滚动（`body.overlay-open { overflow: hidden }`），并把焦点移到弹层上；关闭后**焦点回到原卡片**，键盘审阅可以接着进行。
- 弹层是 `role="dialog" aria-modal="true"`，按钮都有 `aria-label`。

## 10. 键盘审阅

审阅上百条时，键盘比鼠标快得多。至少提供：

| 键 | 作用 |
| --- | --- |
| `J` / `K` | 下一条 / 上一条（卡片可聚焦：`tabIndex=0`，滚动用 `scrollIntoView({block:"nearest"})`） |
| `X` / 空格 | 勾选当前条 |
| `O` / `Enter` | 打开当前条的证据大图 |
| `←` / `→`、`Esc` | 大图内切换、关闭 |
| `/` | 聚焦搜索 |
| `V` | 切换精简显示 |

必须遵守的守卫：

- 焦点在可输入控件上时（`input` 中除复选框外的类型、`select`、`textarea`、`contentEditable`），**不劫持任何按键**，方向键要留给光标移动；
- 有 `Ctrl` / `Meta` / `Alt` 修饰键时放行，不抢浏览器快捷键；
- 空格只在焦点本身是卡片时才勾选（否则会和按钮、开关的原生空格行为冲突）；
- J/K 只在可见卡片之间移动，跳过折叠分组；
- 快捷键清单写在页面上（导出栏下方的「快捷键」面板），不能只存在于文档里。

## 11. 密度切换（精简显示）

条目多时，用户需要先快速扫一遍，再细看。提供「精简显示」开关：

- 外观是带 `role="switch"` 的拨动开关，放在筛选条最右侧，快捷键 `V`；
- 实现是在根元素加 `.compact` class，纯 CSS 切换，不重建 DOM。卡片压成单行（勾选 / 分数 / 主词与徽章 / 右对齐的指标），隐藏缩略图、上下文和明细。实测卡片高度从 147px 降到 40px；
- 状态存进 `localStorage`，并在 `<head>` 的同步脚本中提前加上 class，避免闪烁；
- 精简模式下整行点击勾选和键盘审阅照常可用；窄屏的精简模式只保留最关键的两项指标；
- 切换时保持聚焦卡片在视口内。

## 12. 实现约定

### 12.1 单文件与生成

- 优先单文件 HTML（内联 CSS/JS），`file://` 能直接打开；资源用相对路径（如 `frames/xxx.jpg`），不依赖网络、CDN 或 `fetch`。
- 数据通过 `<script type="application/json" id="…-data">` 嵌入，序列化时把 `</` 转义为 `<\/`。占位符只出现在真实替换点（见 AGENTS.md）。
- **模板写在 Python 字符串里时，JS 里的反斜杠必须双写**：`"\n"` 在 Python 普通三引号字符串里会变成真实换行，进入 JS 字符串字面量后直接产生语法错误。这是真实事故，另一起是 HTML 字符串里的引号冲突（`Unexpected identifier 'badge'`）。两条防线：
  1. 测试里提取生成页的 `<script>`，跑 `node --check`（参考 `tests/test_term_extract_report.py::test_generated_script_has_valid_javascript_syntax`）；
  2. 大改模板时，先把模板写成独立的 `.html` 文件编辑调试，再用脚本拼回 Python（拼接时统一把 `\` 替换为 `\\`，并断言模板中不含 `"""`）。
- JS 用 `"use strict"` 的 IIFE，不污染全局。不要用和 `window` 内置属性同名的全局变量（`top`、`closed`、`name`、`status` 等）。

### 12.2 渲染与性能

- 每个条目的派生数据（证据帧分组、尺寸、计数）**在加载时预计算一次**，存进数组，渲染时直接取用，不在每次 `refresh()` 里重算。
- 条目到索引的映射用 `Map`，不在循环里调用 `array.indexOf`（O(n²)）。
- 列表用 `DocumentFragment` 一次性挂载；勾选、计数等局部变化做增量更新，不整表重建。
- 卡片加 `content-visibility: auto` + `contain-intrinsic-size: auto <估计高度>`，并配 `@media print` 覆盖（见 AGENTS.md）。精简模式要给出各自的估计高度。

### 12.3 可访问性底线

- 可点击的东西用 `<button type="button">`，不要给 `div` 绑 click 冒充按钮；折叠控件带 `aria-expanded`；
- 图标按钮都有 `aria-label` 和 `title`；
- 统一的 `:focus-visible` 描边（强调色 2px），不要 `outline: none` 了事；
- 图片带有意义的 `alt`（「证据帧 00:39」）。

## 13. 验证流程

工具页改动必须在真实浏览器里过一遍，不能只看测试结果。推荐使用 `agent-browser`（skill `agent-browser`）：

1. **先提交基线**：大改版前，先把当前可用版本提交，方便对照和回退。
2. **用真实数据生成页面**，不只用合成冒烟数据。真实数据会暴露长词、空字段、大量条目、极端分数等边界。
3. **截图自查**，至少覆盖：1440×900 深色、1440×900 浅色、375×812 窄屏（底栏收起与展开），以及弹层打开态。截图存到 `.artifacts/tmp/<工具>-*.png`。
4. **脚本化交互探针**：把探针 JS 写进 `.artifacts/tmp/*.js` 再 `eval (Get-Content -Raw …)` 执行，不要在 PowerShell 命令行里内联复杂 JS（引号嵌套极易出错）。探针返回一个 JSON，逐项断言：
   - 点击卡片空白处、主词、指标行能切换勾选；点击缩略图不勾选而是打开弹层；有文字选区时点击不勾选；
   - 组头整条可折叠，点组内操作按钮不折叠；
   - 筛选后勾选保留，预览与导出内容一致；
   - 键盘全链路：`J → J → X → O → → → X → Esc → /`，并检查焦点最终位置；
   - 热区尺寸实测（`offsetWidth/offsetHeight`），不要凭感觉说「已经变大了」。
5. **溢出检查**：每个宽度下 `document.documentElement.scrollWidth === clientWidth`。
6. **重排计时**：展开全部分组、清空会隐藏条目的筛选后，在 320–1440px 之间取 11 档强制重排（方法见 AGENTS.md），最大值应 < 8ms。
7. `agent-browser errors` 无报错。
8. 探针里避免使用和 `window` 内置属性同名的变量（曾用 `closed` 得到错误结论）。
9. 后台浏览器测不了真实的滚动帧率和触屏手感，交付时把这一项如实列为「未验证」。
