# HTML 工具页设计与交互规范

适用范围：当前维护的浏览器工具页及其生成模板，包括确认、核对、对比、编辑和看板。新页面遵循通用底线；修改既有页面时让改动部分遵循。历史报告、退休原型和既有生成物不因规范更新自动重写；整页改版须在维护者授权范围内。

**样式基准：[OCR 确认页](term-extract/term_extract/report.py)。** 复用控件时按其结构、尺寸、状态与焦点反馈复制，不自行另画近似版本、改变比例或重配颜色。任务布局和精简显示保留哪些信息按下述场景决定，不能把「布局按需」误读为允许重造控件样式。[人工核对清单](verification-checklist/README.md) 是核验任务示例；性能测量见 [AGENTS.md](AGENTS.md)。

本文区分 **必须满足的通用底线** 与 **按任务选用的模式**。不需要勾选的工具不加复选框，不导出的工具不加导出栏，没有证据图的工具不加弹层。

## 1. 先确定任务与适用模式

动手前明确：谁使用、主要动作是什么、一次处理多少数据、判断需要哪些信息、结果保存在哪里。围绕主任务排列入口，不从「把所有字段摆出来」开始。

| 类型 | 主任务 | 适合保留或选用的结构 |
| --- | --- | --- |
| 审阅 / 选择 | 判断条目、选择结果 | 分组、状态计数、整行选择、结果预览；量大时提供密度切换 |
| 核验清单 | 按步骤操作、打勾、备注 | 目录、分区进度、目的/操作/预期、备注与结果导出 |
| 对比 / 诊断 | 并排看差异、展开明细 | 多列对照、固定表头、局部横向滚动、差异筛选；不强加选择或导出 |
| 编辑器 | 编辑、预览、保存 | 编辑区与预览区、未保存状态、保存与冲突确认；保留文字编辑热区 |
| 看板 / 实验台 | 归类任务、调参、观察 | 看板列或可视化面板、状态选择、测量说明；不把图表变成审阅卡片 |

只读、空、加载、成功、失败和禁用状态按实际任务提供。没有异步操作的控件不需要虚构 loading 状态。

## 2. 通用视觉基线

### 2.1 主题与令牌

- MAW 工具沿用 [Launcher](../web/launcher/launcher.css) 的底色、文字、强调色、字体与圆角。深色炭灰配橙，浅色白灰配红；色值以当前源码为准，不在各页自行漂移。
- 同类控件以 OCR 页为直接样式参照，优先提取/复用源样式，不「参考之后重新设计」。特别是精简开关沿用 `.switch` → checkbox → `.switch-track` 的圆点轨道结构，尺寸、未选/已选状态和 focus-visible 均与原页对拍；禁止拿按钮底色或 box-shadow 假造开关。
- 共用基础资源在 [shared/tool-page.css](shared/tool-page.css) 和 [shared/tool-page.js](shared/tool-page.js)。静态页可用相对链接；独立生成页由生成器内联，离开仓库仍能使用。不要为复用放宽已有 CSP。
- 默认跟随系统，提供有名称的主题切换按钮，用户选择可记忆。首帧前设置主题；存储不可用不应阻止页面启动。关键工作进度保存失败须另行明确提示。
- 每个主题设置 `color-scheme`。颜色在令牌块集中定义，组件使用变量；状态色、数据系列色和图像标注可独立定义，但必须同时适配两主题。不要把图表系列色全部替换成强调色。
- 有文字的状态必须能靠文字或形状辨认，不能只靠红/绿。主按钮文字用相应的强调色前景令牌，不假定白字永远对比度足够。
- 不添加装饰渐变、外部字体、虚假统计或无意义动效。必要的图表刻度、异常纹理与图像标注属于数据编码，不视为装饰。

### 2.2 层次、密度与间距

- 使用系统中文字体；数字、编号和时间码适合等宽字体及 `tabular-nums`。不要让所有文字都成为同字号灰字，也不要把完整标题强制等宽。
- **严禁 11px 以下字号**：正文、标签、徽章、编号、时间码、图表刻度及伪元素文字都适用，精简/窄屏模式不得突破下限。11px 只是绝对底线，主要阅读内容建议 13–16px；验收既查源码也查实际计算字号，Canvas/SVG 文本单独检查，不能靠浏览器缩放补救。
- 主要对象、辅助指标和背景说明应有字重/字号层次；具体字号随页面密度选择，不写死所有卡片必须 18px。
- 徽章通常用浅填充胶囊；警告、禁用或其他有语义的描边可以保留。不要把「一律无描边」当成审美规则。
- 以 Launcher 圆角、4px 间距节奏为基线。新增控件与相邻元素至少留 8px，并实测；紧凑表格单元格、成组分段按钮不要求每个子元素都隔 8px。
- hover、active、focus-visible、disabled 应可辨。颜色/边框等过渡保持短暂，遵守 `prefers-reduced-motion`；标题使用正体。

## 3. 布局与窄屏

- 优先保留工具合理的既有结构。OCR 的「主列 + 导出栏」不适合所有页面：对比表保留并排，编辑器保留编辑/预览，看板保留任务列。
- 主操作易找到、可到达。长页的频繁操作可吸顶或常驻；不要求每页把所有操作固定在视口内。
- 窄屏先减少常驻内容、收纳次要操作，再考虑底栏。若使用底栏，只常显必要计数与主操作，其他放入可展开区；避免桌面大面板原样固定后占据大半视口。
- 固定/吸顶区域会换行时量其实际高度，供偏移与底部留白使用；短且高度稳定的条可以不引入观察器。考虑安全区与浏览器缩放，底栏不得遮住最后一项或焦点。
- 手机上过高的顶栏取消吸顶或收纳。断点按内容是否拥挤确定，不强制所有页面使用 960px/560px。
- 页面不应有意外的横向滚动。网格使用 `minmax(0,1fr)`，flex 子项允许 `min-width:0`，长词可换行；宽表格、时间轴和看板在自己的容器内滚动。`overflow-x:clip` 只是防线，不能靠裁掉内容通过验收。
- 编辑器窄屏可上下排列编辑与预览；诊断表可保持最小列宽并局部滚动，不能为了适配而隐藏关键证据。

## 4. 信息与交互热区

### 4.1 信息分层

- 首屏只放决策必要的信息；其余可展开。没有评分的工具不加分数块，有证据的工具才展示证据。
- 指标写明单位与口径，例如百分比、毫秒、段数。内部词汇必须在可见说明或提示中解释；不能用格式简化偷偷改变口径。
- 状态需在条目或区域上可辨，不能只改变一个很小的控件。不可用项说明原因。
- 明细入口应明确，必要时显示数量。展开和筛选不能丢掉用户选择、文本、备注或位置。

### 4.2 点击与键盘

- 单一布尔选择的条目适合整行可点；分组折叠适合整条标题可点。含多个编辑/决策动作的行不要绑定含混的默认操作。
- 扩大热区的同时排除按钮、链接、输入、原生 label、缩略图及展开后的可操作明细，防止一次点击执行两个动作。有文字选区时不执行行选择或折叠。
- 小图标、复选框的视觉尺寸和实际点击范围分别检查；密集桌面工具可用较小图标配大 label，触屏目标建议至少 44px。不要把图标必须 24px 当成所有密度的硬限制。
- 悬停反馈覆盖真正热区。用原生 `button`、`label`、`summary`；既有复杂网格用 role 时必须有对应键盘行为与 `aria-expanded`。
- 所有动作可用键盘操作。快捷键按工具任务决定，不强制 J/K/X/O/V；单字母快捷键不得抢输入、修饰键和原生按钮行为。已提供的快捷键需在页面可查。
- 筛选、折叠或重建后关注焦点归属；不要把焦点留在已移除节点。

## 5. 筛选、分组与密度（按场景）

- 搜索/筛选有可访问名称，标签简洁，复杂口径有说明。搜索造成重计算时防抖或增量渲染；重置应取消未执行的旧搜索，避免旧计时器覆盖重置结果。
- 默认筛选要符合工具目标。若默认隐藏某类数据，应明确可恢复的入口和数量；不要让一个设计为可展开的分组被另一默认值意外永久挡住。
- 空结果区别于未加载/加载失败，提供清除筛选或重试入口。重置筛选不应清空工作状态。
- 数字步进是可选模式：保留原生可操作入口；若额外支持滚轮，应说明条件、遵守 min/max/step，并评估抢页面滚动的风险。不要为所有工具强制悬停滚轮和隐藏微调按钮。
- 分组依据实际业务（状态、主题、文件等），不是固定四档评分。批量操作明确「当前可见项」还是「整个分组」，只操作可用条目；分组折叠状态不随搜索丢失。
- 精简显示必须实际减少信息，而不是仅缩小字号或间距。开关外观完全复用 OCR 页，数据、备注与导出范围不变，关闭精简可恢复完整内容；不需要密度切换的短页无需新增。
- 样式验收不只测控件存在：深/浅两主题分别对拍原 OCR 开关的轨道/圆点尺寸、位置、背景、选中位移和键盘焦点；核对精简前后可见字段，不能以总行数/根溢出断言代替内容可达性。
- **核对清单**：精简后每项只保留标题与勾选状态，隐藏操作/预期/说明及备注/复制等辅助入口，标题字号不缩小；已有备注和明细只是隐藏，不删除。打印恢复完整字段和备注。
- **开发看板**：精简卡片只保留标题、忽略/取消忽略按钮和状态选择；徽章、CI/作者/分支元信息和核验清单提示隐藏，切回完整视图再查看。原归类/忽略行为与存储不变。

## 6. 状态、预览与结果

- 状态存在工具自己的数据模型中（对象、Map、Set 等均可），DOM 是投影。使用稳定业务 ID，不能因排序/筛选换索引而串状态。不要为遵循规范重写有效的既有存储契约。
- 若页面有导出预览，预览和实际结果由同一数据派生，范围、去重、顺序一致。简单词表可用 chip，复杂 JSON/Markdown 可按需展开文本预览；不强制所有结果做成 chip 或常驻大框。
- 没有可导出内容时禁用按钮；编辑器有未保存修改时给明确状态。发起下载不等于文件已保存，不写「已保存到某路径」冒充浏览器证据。
- 非阻塞成功提示用行内状态或 toast，不使用 `alert()` 打断流程。重要错误持续可见；会丢进度的重置、覆盖、批量写盘保留明确确认，不因「不用 alert」而取消 `confirm` 或安全弹窗。
- 提示使用 `role="status"` / 合适的 live region；不能遮住当前输入与主操作。复制可优先 Clipboard API，再尝试兼容回退，失败提供替代路径。
- 主题、密度等偏好保存失败可容错；业务状态保存失败要警告并允许导出。更新模板保留现有存储键与稳定 ID；迁移必需时写清兼容办法。

## 7. 图片、图表与弹层（有这些内容时）

- 图片用真实尺寸或可信 `aspect-ratio` 预留空间；按需懒加载/异步解码。不要在宽高分别钳制时破坏比例；双边约束配 `object-fit:contain` 可以正确使用，不是一律禁止 `max-width` + `max-height`。证据图默认不裁切；装饰图允许的裁切需明确。
- 图像标注坐标相对实际图片计算，缩放或 letterbox 后仍对齐；不能把框定位到包含额外留白的外层。缺图/尺寸缺失有降级。
- Canvas/SVG 的底色、刻度和标签也适配主题；切主题时需重绘的图表要显式接线，不只改页面背景。
- 图片集弹层可提供前后按钮与方向键；单张不显示无效导航。导航范围、计数和说明必须清楚，不强制循环或限定某个帧数。
- 弹层用 dialog 语义，有名称与关闭入口；打开时锁背景、移入焦点并约束 Tab，关闭时回到有效触发位置。图片与内部按钮点击不能意外关闭；Esc 行为不抢输入里的合理编辑动作。

## 8. 模板、离线与性能

- 根据工具用途选择离线自包含或受限 localhost，不强制所有工具单 HTML。已有服务器授权与 CSP 不放宽；不增加任意路径读写、CDN、隐式外发。
- 更新唯一源模板和生成器，不手改历史生成物；维护者指定旧产物时才刷新。静态共用资源用相对路径，单文件产物生成时内联并测试离开源码目录的使用。
- 外部文字用 textContent 或可靠转义。内嵌 JSON 转义 `</`；占位符只用于真实替换点。Python 字符串模板特别注意反斜杠/引号层次；对**实际生成脚本**做语法校验，不只校验未生成的源文件。
- Markdown 文档展示复用成熟解析与清理库（本地固定版本的 Marked / DOMPurify），不再扩大各页的正则替换实现。解析器、安全策略、阅读弹窗与文档装载分层，业务导出/文件授权不掺进渲染器。新工具可复用共享模块；已有专用渲染流程仅在明确修改范围内迁移。
- 「使用说明」优先在页内阅读弹窗展示，保留打开源文件入口。README 等正文是唯一维护真源；离线副本由生成脚本装配并检查新鲜度，不手写双份说明，不依赖 `file://` 下的 fetch。新增/改动说明后同步生成资源。
- Markdown 内容不执行原始 HTML，危险协议链接拒绝，远端图片不自动加载；链接按源文档位置解析，未收录文档给明确源文件入口。不要因复用而引入 CDN、任意路径读取或放宽原有 CSP。
- `==高亮==` 使用解析器行内扩展输出 `<mark>`，样式随主题可读；代码、转义与未闭合标记不转换，不在生成 HTML 上全局替换。新增语法扩展须补语义与安全回归，不能绕过 HTML 清理。
- 用模块或严格模式闭包避免全局污染；既有测试/集成桥允许保留，勿使用与浏览器内置属性冲突的裸全局名。
- 派生数据按变化频率缓存，列表批量挂载，局部状态增量更新。长列表可用 `content-visibility`，配合理估计尺寸和打印覆盖；不对需持续测量尺寸的 Canvas 或吸顶祖先盲加 containment。
- 不把几次测量推广为根因：源码重建、样式/布局、图片解码、绘制、外部请求分别测；某层「很快」只排除该层，不能证明另一层一定慢。性能阈值与数据规模、设备、操作场景一起记录。

## 9. 修改与验证

1. 记录起始 HEAD 和工作区状态。**仅维护者明确要求才提交基线**；本规范不能自动授权 commit 或回退。
2. 列出受影响源文件、消费者和测试层；保留无关 WIP。不默认改动 Launcher、编辑器或历史原型。
   新增工具、入口变更或维护状态变化时，同步 `tools/catalog.js` 与相关 README；[工具功能介绍页](index.html) 从该清单展示用途、能力、入口和边界。暂停维护与暂不处理必须明确标注，不能冒充可用或已验收。
3. 用典型数据及边界数据验证：空、长词、多项、失败、禁用、已有进度。生产数据只留本地产物，不入库或外发；实验工具可用可复现合成数据，不强制真实媒体。
4. 按仓库 `run_check.py` 包装受影响测试，输出有界。浏览器单独验证主流程与状态保留，截图覆盖深/浅、桌面/窄屏、关键展开态；没有弹层的工具不要求弹层截图。
5. 在 320/375/414/768px 及桌面、相关断点附近测内容可达性、局部滚动、横向溢出、热区和间距。长列表强制重排计时见 AGENTS；后台测量不能冒充前台滚动帧率或触屏体验。
6. 收尾写明通过、失败、跳过、未测和实际证据路径。截图不等于交互通过，标记断言不等于浏览器通过。生成与源码同步，必要的用户说明和人工核查清单一并维护。

## 10. 交付前自查

### 每页适用

- [ ] 用途、主操作与边界清楚，没有为了统一而添加无用组件
- [ ] Launcher 视觉基线、深浅主题、名称与焦点样式一致，主题保存失败不阻断启动；所有文字计算字号 ≥11px
- [ ] 窄屏内容可达，宽内容局部滚动，常驻区不遮挡，没有靠裁切掩盖溢出
- [ ] 输入/点击/键盘不冲突，热区和间距有实测；重置/覆盖保留必要确认
- [ ] 业务状态不丢，错误与保存边界真实；测试、浏览器证据与未测项分别记录

### 按实际组件检查

- [ ] 筛选：有名称、重置、空结果入口，默认范围合理，工作状态保留
- [ ] 分组/密度：语义与范围明确，折叠不丢状态，精简不隐藏关键证据
