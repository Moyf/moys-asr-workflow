# CHANGELOG 编辑器

维护者本地工具页：按版本拆开 CHANGELOG 逐条编辑、逐条对比、粘贴配图，并把图片写进版本 assets、生成附图后的 CHANGELOG 与 `docs/releases/<版本>.md` 归档；支持多版本批量完成、分屏实时预览与测试版条目对照。

## 打开方式

直接双击 `index.html`（file:// 即可），或在仓库根目录起任意静态服务后访问。
生成归档依赖 Web Crypto 与文件写权限，请用 **Chrome / Edge** 打开；「仅加载 CL 文件」是只读降级模式（不能写盘，完成编辑改为下载文件）。

## 使用流程

1. **打开仓库目录**：选择仓库根目录（读写模式）。页面读取 `CHANGELOG.md` 与 `docs/releases/`，侧栏列出全部版本并标注归档状态（绿=一致，黄=需重生成，红=缺失）与未完成的修改（橙点）。侧栏宽度可拖动边缘调整（自动记忆）。
2. **逐条编辑**：选择版本后每条更新是一个卡片，直接改文本；「对比」显示与原文的逐词差异，「还原」恢复原文；条目与小节标题（`###` 行）都可新增、删除、上下移动。历史测试版小节默认锁定，点击「仍要编辑」后才会解锁（按会话记住）。
3. **粘贴配图**：点击某个条目（选中态）后直接 `Ctrl+V` 粘贴截图（分屏模式同样可用），或把图片文件拖到条目卡片上。图片条里已有图片与新图片混排：alt 与链接路径均可编辑，**拖拽即可排序**；新图片默认用条目标题做文件名（同条目多张自动加序号），文件名输入框只含主名、扩展名单独显示不可改；粘贴位图会转 WebP（最长边 1600px、质量 0.9），超过 300 KiB 有软提醒。文件名允许中文等字符，只需避开 `\ / : * ? " < > |` 和空格。删除条目会一并移除其新图片。
4. **预览 / 分屏 / 对照**：
   - 「预览」按渲染效果查看当前版本；「分屏」左侧编辑、右侧实时预览（防抖刷新）。
   - 「对照」列出**上一正式版之后的所有测试版小节**（对 1.9.0 会包含 1.8.0-beta.1），逐条勾选"已核对"，用于确认合并稿没有漏掉内容。
5. **完成编辑**（支持多版本批量）：有改动的版本会自动检出；多个版本同时有改动时弹出批量清单，按版本勾选「是否写入」「是否重生成归档」。写入顺序：
   - 备份被覆盖文件到 `.artifacts/changelog-editor/backup/<时间戳>/`（目录已被 Git 忽略）；
   - 磁盘冲突检测：CL 在打开后被外部改动时弹窗三选一——**强行覆盖**（磁盘版本先备份）/ **另存为单独文件**（写入 `.artifacts/changelog-editor/manual-save/`，不碰磁盘 CL 与归档，之后手动合并）/ 取消；
   - 各版本新图片写入 `docs/assets/<版本>/<文件名>`（同内容自动去重），并把链接插入到对应条目后的既有位置（保持条目内顺序）；
   - 一次性写回 `CHANGELOG.md`；
   - 重生成勾选版本的 `docs/releases/<版本>.md`。
6. **归档生成**（侧栏，按版本勾选、仅正式版）：对勾选版本按当前 CL 生成归档；生成前会先保存 CL 并备份被覆盖的归档。测试版与未发布区不参与，与 `--check-all` 的规则一致。

## 契约与保证

- 归档生成逻辑是 `scripts/prepare_release_notes.py` 中 `extract_release_section` / `build_release_document` 的逐字节等价实现；`selfcheck.js` 用当前仓库对拍（47 个小节往返无损、全部正式版归档与 Python 产物一致）。改动 `cl-lib.js` 后运行：

  ```powershell
  node tools/changelog-editor/selfcheck.js
  ```

- 版本归档仍以 Python 侧 `--check-all` 为准；页面生成只是省一步，CI 检查不因此豁免。
- 归档中的相对图片链接会被固定为 raw.githubusercontent.com 的 tag 地址，所以**引用的图片必须在 tag 可达**（本仓库把图片放在 `docs/assets/<版本>/` 并随版本文档一起提交，即满足该条件）。
- 自动保存：文本与图片二进制分别存 localStorage / IndexedDB（按 CL 哈希隔离），顶栏显示最近保存时间；配额不足会显式报错提醒尽快写盘。恢复的是"文本 + 新图片"，尚未写盘的图片仅在打开过该工具的浏览器里有效。

## 开发与自检

- 逻辑对拍（无需浏览器）：`node tools/changelog-editor/selfcheck.js` —— 解析往返无损 + 全部正式版归档与 `prepare_release_notes.py` 产物逐字节一致。
- UI 冒烟（需先起静态服务）：`python -m http.server 8791 --bind 127.0.0.1` 后运行 `node tools/changelog-editor/smoke-ui.js`，脚本载入真实 CL 走一遍编辑 / 对比 / 分屏 / 对照 / 图片条（含 HTML5 拖拽排序）/ 批量完成弹窗 / beta 锁 / 归档一致性，并检查页面无报错。

## 已知边界

- 浏览器只支持 Chromium 系（File System Access API + WebP 编码）。
- 版本小节本身的顺序不能在页面里重排（极少需要，且易误操作）；条目与小节标题级别支持增删与移动。
- 只读降级模式不产生备份。
- 磁盘冲突检测只在写回前比对 CHANGELOG.md；编辑期间外部改动不会被实时发现。
- 「对照」勾选状态按 CL 哈希保存，CL 变更后重新累计。
