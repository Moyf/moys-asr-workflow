# 符号级合并重放工作流

当编辑器拆分分支与仍维护单体 `web/editor.js` 的上游发生首次合并时，Git 的文件级合并会把已经迁入模块的声明重新带回入口。不要手工逐个删除这些副本：很容易把同名函数的函数体贴错。

在拆分分支、且 `git merge --no-commit <main-ref>` 已停在冲突现场后运行：

```powershell
node tools/merge-flow.mjs resolve --dry-run
node tools/merge-flow.mjs resolve
```

工具以 merge-base、`MERGE_HEAD` 和当前分支 HEAD 的模块树为三方输入。它只把模块冻结门面导出的符号视为模块所有者；这样上游新加入、但恰好和模块私有函数同名的入口函数不会被错误移除。对于上游改动的已迁移声明，工具将 main 版本重放到所属模块，并为跨模块自由引用加上门面命名空间；入口则从干净的 main 版本重建，删除已迁移声明并修正其调用。

`--dry-run` 的 REPLAY、REMOVE、KEEP 和 CONFLICT 是合并前的审计记录。出现 CONFLICT 时先停止并人工决定语义归属；不要把工具当作覆盖分支独立功能改动的手段。

完成后至少执行：

```powershell
node --check web/editor.js
node --check web/editor-*.js
node --test tests/test_editor_utils.mjs tests/test_waveform_js.mjs
uv run --no-sync python -m unittest tests.test_waveform
git diff --check
```

再检查关键导出仍在其模块（例如 `editor-export-srt.js` 中的 `buildGapRemovedSrt` 必须调用 `buildSrtPayload`），以及上游入口行为（例如 `renderAll` 的对象参数）仍在 `editor.js`。日常合并不要重建 `blank-editor.html`；它只在发布检查时统一生成。模块化背景与拆分约定见《编辑器模块化拆分指南》。
