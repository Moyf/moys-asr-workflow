## 拆分约束与依赖审计

- 清单装配顺序严格对应原文件顺序；同一领域的非连续区段保留独立文件，不为归类而重排。
- 不包新增 IIFE、不引入 strict mode、不改命名空间；保留原全局词法作用域和函数提升语义。
- 从文件尾向前落盘，每个完成区段插入剩余入口之后，保持整体原序；最终入口只承担入口角色，不以“裸声明归零”作为此次机械拆分指标。
- DOM / combobox 声明必须早于加载期初始化使用；ASS 状态、异步保存修订、预览刷新与卸载保存顺序保持。
- `updateSelectionCountText`、叠加轨选择状态、ASS 样式库、字体选择器等仍有跨区段裸引用。本轮记录消费者与声明所有者，迁移时不顺便改写；下一轮按这些边界补门面和类型。
- 历史模块已提取但入口仍留有同名或疑似无用辅助声明（如延迟波形重试）：先记录，保持等价，另轮经引用分析后清理。
- 自动化装配测试中的文件名、marker、加载顺序断言随清单更新；避免用匹配源码片段的旧文件名断言误报。

## 目录分层

建议这轮在接线拆分之后完成，无需等后续深层重构结束。保留两层目录深度；仍由清单独占加载顺序。

```text
web/
  editor-scripts.txt
  editor-template.html
  editor.css / waveform.css
  launcher/                         # 现有 Launcher，保持独立
  sfx/                              # 现有静态音效
  shared/                           # editor-utils、i18n、gap-remove-core 等共享能力
  editor/
    boot/                           # runtime、boot、入口、startup、onboarding
    state/                          # core-state、settings、history、轨道状态
    cues/                           # 编辑、选择、搜索、拆分、合并、文本工具
    styles/                         # 字体、ASS、外观、颜色与说话人
    media/                          # 播放、波形、几何预览
    io/                             # 工程、媒体输入、保存、导出、服务连接、拖放
    ui/                             # DOM、浮窗、帮助、菜单、工作区布局、提示
```

表中 34 个接线区段与现有模块一起归类。跨领域模块按主要所有者放置；目录不改变公开 API，不新增导入关系。工作区布局优先 UI，工作区工程传输优先 IO。

## 同一分支内的提交与验证

提交按检查点组织：①等价审计基线与契约支持；②连续接线拆分；③子路径校验与测试；④纯目录移动和引用更新；⑤源码地图与验证记录。它们统一进一个 PR。

每完成一个区段记录文件、决定、命令、结果及未验证边界；每完成 2–3 项写阶段汇总。若环境或测试阻塞，保持真实的“阻塞”状态。

验收：

- 结构层：所有顶层语句完整、连续覆盖，声明没有遗漏或重复；脚本清单可解析、顺序检查通过。
- 源码层：切段拼回原文件逐字节一致；按清单装配顶层 AST 完全一致；目录移动前后装配源码一致。
- 单元与契约层：Node 全套、Python 全套、类型检查、Ruff、`git diff --check`；子路径正反例同时覆盖 Python / Tauri 校验。
- 浏览器层：启动 localhost 编辑器，检查控制台、空白启动和加载工程、播放 / seek / 拖动、键盘、筛选、主副轨和叠加轨、ASS、保存 / 导出 / 导入、引导。失败必须与同环境基线逐 test ID 对照。
- 产物层：Tauri 构建检查、在线编辑器构建检查；便携渲染使用临时目录验证，不重生成仓库 `blank-editor.html`。

PR #154 审查中，相关 Chromium 26 项为 22 通过 / 4 失败；同环境 main 复现全部 4 个失败（英文 shell、引导合并、引导重播、英文引导）。这里只保留为基线线索，实施本轮时重新实测，不以旧失败数替代全量对照。
