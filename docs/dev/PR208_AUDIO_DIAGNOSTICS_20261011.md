# PR #208：Launcher 空结果提示（当前方案）

## 当前决策与实现

用户决定取消空结果后的静音检测，避免给长录屏转写增加等待。当前方案替代 `b86c19db` 的完整扫描 / 抽查实现，保持原 PR Draft。

- ASR 明确报告没有识别内容，或成功输出的工程字幕列表为空 / 文本全为空白，统一进入友好错误链，不进入后处理或误报完成。
- 中英文通用提示为未能转写出任何有效文本，并建议检查处理范围、语言与模型设置。
- 已有音轨数量大于 1 时，补充文件包含多条音轨、请检查选中的音轨是否有效，并提供「检查音轨」入口。这是复听提醒，不是选错轨的诊断。
- 单文件复用选文件时已有的音轨列表；更换文件立即清除旧信息。批量复用原有默认选轨探测，每个条目的数量独立，不能继承单文件或其他条目的数量。明确指定选轨但没有数量信息时保留通用提示。
- 空结果后不启动 FFprobe、FFmpeg、静音分析或第二次 ASR，不自动换轨。已有默认选轨探测保持原来的 10 秒超时，不引入额外探测。
- 只匹配明确的最终空文本错误；旧日志中的空结果 / 音轨警告不能覆盖最后的认证等错误。原始错误详情与选轨索引保留，取消仍优先。
- 损坏的音轨探测条目不能误报无音轨或改变其他音轨索引；这项既有修复保留。

## 边界与预研

开头静音但后面有人声、多条轨都静音、只有游戏声，都不会据本地电平得出原因结论。ASR 空结果不足以证明整轨无声或不存在人声。未知音轨数量保留通用提示。

波形顺序与已有响度数据的研究独立记录在 [波形预研](PR208_WAVEFORM_PREFLIGHT_RESEARCH_20261011.md)。本次没有实现缓存响度诊断，也没有把波形生成移到转写前。

# PR #208：Launcher 空转写与音轨诊断

## 基线与范围

- 独立 worktree：本聊天 `dfe6/maw-fork`；初始提交 `cfe2931b`，已通过 `236337d5` 合入上游 `09af19f`。
- 反馈：多音轨 OBS 录屏误选未录入声音的音轨，界面只提示转写失败。
- 原代码：OpenAI 对空字幕抛异常，本地模型无文本返回失败；Qwen / Soniox / Doubao / Bcut / Tencent 对无识别文字输出“错误: 未识别到任何内容”，但整理后全空仍可能写出空工程。Launcher 之前没有统一这些入口与音频证据诊断。
- 仅修改 Launcher 的执行与错误提示链，保留生成器 CLI 行为、选轨默认值和输出路径。不自动换音轨、不额外请求 ASR、不修改原工作区配置；保持 #208 Draft。

## 研究结论与边界

| 现象 | 本地证据与处理 | 状态 |
| --- | --- | --- |
| 视频没有音轨 | FFprobe 成功返回空音轨列表时使用明确无音轨提示；音频提取失败有选轨证据时也可进一步核实 | 已修复 |
| 空字幕或所有字幕文本为空 | 执行成功后检查工程文本；已知空文本失败也走诊断 | 已修复 |
| 所选音轨近乎静音 | FFmpeg astats 检查各声道总峰值，不进行单声道混合；≤ -60 dBFS 区分完整处理范围与抽查片段的证据 | 已修复 |
| 多轨选错 | 所选轨完整处理范围近乎静音、另一轨峰值 > -45 dBFS 时提示另一轨有信号，引导复听；不认定游戏声轨是正确的人声轨 | 已修复 |
| 多轨全部近乎静音 | 必须每条轨都完整检查且 ≤ -60 dBFS，才提示换轨可能无法解决；失败或漏检的轨道不能算静音 | 已修复 |
| 有信号但空结果、噪音太大或无人声 | 电平无法证明人声、信噪比或可识别性，只列为可能原因，不确定归因 | 仅说明 |
| 探测失败、超时、无采样 | 保留空结果与原错误详情，不能冒充无音轨或静音；损坏的轨道元数据也不误报无音轨或改变后续索引 | 已修复 |

依据：[FFmpeg astats 官方文档](https://ffmpeg.org/ffmpeg-filters.html#astats)，Peak_level / Number_of_samples 用于电平与采样证据，不能作为人声识别。

复审后取消只查开头 60 秒的策略。短文件尝试完整处理范围，尊重 length-limit；超过 10 分钟的处理范围直接抽查开头、中间、结尾各 3 秒。完整检查超时且时长可读时也可尝试抽查，只有三个窗口都成功且安静才给出独立的抽查提示；抽查不判断整轨无声、不扫描其他轨。完整所选轨安静时，在预算内检查其他轨，不再固定只查另外三轨；只在每轨均完成时报告全轨安静。

FFprobe 诊断超时 2 秒，含探测在内共用 6 秒执行预算，单次解码最多 3 秒、单解码线程。长片跳转抽查的工作量基本不随总时长增长；容器无索引、磁盘慢、工具失败等仍可能超时，此时保留不确定结论。取消或超时终止所属进程；常规清理最多再等 1 秒，异常回退清理最多再等 1 秒，不把 6 秒说成包括操作系统清理的绝对墙钟上限。日志记录索引（从 0 开始）、处理范围、完成标记、抽查窗口和未查完的轨道；中英文提示对应，批量沿用错误码。保留空输出供排障，不进入后处理或误报完成。
