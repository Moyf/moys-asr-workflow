# Plan：编辑器设置结构与入口整理

## 目标与基线

让用户能按任务找到设置、看懂选项的生效范围，并让区域面板、设置页、工具窗与导出参数各自承担清楚的职责。

已有结构清单见 [EDITOR_SETTINGS_REVIEW.md](EDITOR_SETTINGS_REVIEW.md)。本计划制定时的实现基线为 `feat/word-timing-mode` 的 `8ce6bef9`；接手时以实际代码和 diff 为准。

已完成的波形 ⚙️ 三组作为基线保留：

- **波形外观**：波形来源、频谱颜色、振幅、响度适配。
- **显示**：基础模式显示窗口、多行模式行长与行高、分组标记、禁用字幕显示、字词时间码。
- **播放**：播放时跳过已移除空隙。

字词块只显示文字，时间范围在悬浮提示中；字词模式打开另一工程后重置。接手时不得重新实现这些能力。

## 本轮边界

本轮实施设置的分类、分组、名称、跳转入口和范围说明。保留既有默认值、快捷键、存储键、工程字段、导出结果以及撤销 / 重做语义。

控件移动时优先保留原 DOM ID 和事件接线。若同一选项已有多个入口，整理到一个控件位置，再让其他入口跳转过去；不新增一套配置状态。

本轮不增加设置搜索、完整快捷键定制、设置导入导出、统一重置系统或新的字幕处理能力。「全局设置」顶层名称暂时保留，先解决范围说明与入口发现性。

只修改源码和文档，不生成或修改 `blank-editor.html`。遵守仓库 AGENTS.md，保持 UTF-8、LF，保护无关 WIP；发布、推送、创建 PR 或合并须有对应授权。

## 最终信息架构

全局设置从 11 页变为 12 页；新增「区域设置」索引页，三个现有页面改名，其余页面保留。

| 导航分类 | 页面及顺序 | 实施要求 |
| --- | --- | --- |
| 基础 | 界面、区域设置 | 区域设置只有入口、摘要及不可用原因，不复制原面板控件 |
| 编辑 | 编辑操作、时间基准、拆分与合并 | 「通用操作」改为「编辑操作」，移动到编辑分类 |
| 预览与播放 | 播放与预览、字幕样式、颜色与说话人 | 「视频预览」和「字幕颜色」分别改名；三个页面职责明确 |
| 工程与输出 | 保存、导出 | 导出按格式组织配置；保存说明 Server 工程绑定限制 |
| 扩展功能 | 表情包、彩蛋 | 表情包页保留素材管理，OTIO 输出策略由导出页管理 |

现有页面的内部 ID 与已保存的 tab key 继续使用，包括 `general`、`subtitle-preview`、`subtitle-color`，避免改名导致旧入口和历史偏好失效。新增区域设置页使用独立稳定 key。

## 阶段 1：范围核对与区域设置索引

### 1.1 核对生效范围

逐项核对实际读取、写入和工程加载行为，形成简短的设置归属表，再添加文案。不可仅根据页面位置推断范围。

- **个人偏好**：在当前浏览器 / 本机复用的操作与界面习惯。
- **当前工程**：由工程保存并随工程加载的时间基准、预览样式、空隙决定等；具体选项以实际代码为准。
- **临时显示**：字词模式等按既有规则在切换工程时清理的状态。
- **工作区布局**：说明工程布局、本机工作区预设与显式导入导出的关系；不简化成一种范围。

同组范围一致时用一条组说明，只有例外选项加单独提示。文案说明实际影响，不显示内部存储键。保存页说明自动保存与多版本备份的区别以及不可用条件。

### 1.2 新增「区域设置」索引页

提供以下入口：波形、当前字幕、字幕列表、双语字幕、工作区配置。每项包含一句功能摘要和一个明确的打开按钮。

- 打开区域面板前关闭全局窗口，复用既有打开函数、定位逻辑、互斥逻辑和 active / aria 状态。
- 面板打开后聚焦第一个可操作控件；关闭后焦点回到目标区域的 ⚙️ 或对应工具栏入口，不回到已经隐藏的索引按钮。
- 双语模式未开启时，保留索引说明，禁用打开按钮并说明需先开启双语字幕；不自动开启模式。
- 工作区入口打开既有配置菜单，保留 Server / 便携模式的差异。
- 已有「帮助 → 设置」和其他设置跳转继续工作。

阶段验收：从全局窗口可以发现所有区域入口；反复打开、关闭和 Esc 操作不会留下遮挡、失焦、错误展开状态或隐式工程改动。

## 阶段 2：编辑、播放与区域面板分组

### 2.1 「编辑操作」页

分成「选择与定位」「波形拖动」「按键微调」「空隙修正」。

- 选择与定位：点击字幕行为、跳转目标、同时选中分组成员。
- 波形拖动：允许拖动指针、贴合边界方式、自动吸附联动。
- 按键微调：快捷键时间基准、字幕微调幅度；说明其与播放跳转时长不同。
- 空隙修正：空隙区段操作方式，提供静音空隙工具窗跳转。

「播放过程中点击鼠标自动暂停」移到「播放与预览」。保持其与点击行为的原有协作和动态提示。

### 2.2 「播放与预览」页

分成「预览内容」「播放与定位」。

- 预览内容：主字幕、副字幕、表情包的预览开关，保留条件显示。
- 播放与定位：鼠标悬停预览、JKL 模式、播放跳转时长、播放中点击暂停。
- 提供到波形 ⚙️「播放」组的入口，说明空隙跳过在该处控制；不复制跳过开关。
- 波形 ⚙️「播放」组增加「更多播放设置」跳转，关闭区域面板后打开全局的对应页。

### 2.3 字幕列表 ⚙️

分成「筛选」「显示」「跟随与浏览」。

- 筛选：字数阈值、拆分后临时保留、隐藏禁用字幕。
- 显示：序号、时间码、表情包、字数。
- 跟随与浏览：点击字幕后自动滚动；关联现有工具栏的「跟随播放」入口或说明，不新增跟随状态。

### 2.4 双语字幕 ⚙️

分成「显示」「联动」「语言」「字幕管理」。

- 显示：列表显示方式、双语波形行高、轨道徽标。
- 联动：跨轨吸附、同时选中绑定对、绑定时自动同步时长。
- 语言：主、副字幕语言类型及字符型 / 单词型说明。
- 字幕管理：导入、交换主副字幕，保留已有确认与预览流程。
- 常规波形行高与双语行高互相说明各自生效的模式；不新增行高同步规则。

当前字幕 ⚙️ 继续使用「显示 / 操作」两组。保持原列表焦点、筛选、自动滚动和快捷键行为。

阶段验收：所有移动的选项可操作，中文 / 英文与条件隐藏一致；字词编辑、主副轨联动、播放导航没有回归。

## 阶段 3：颜色、说话人和导出配置

### 3.1 「颜色与说话人」页

将「字幕颜色」改名为「颜色与说话人」。保留颜色预览、自定义色板、说话人映射三类内容，明确预览名称和导出名称是不同选项；提供到导出页的对应跳转。

更新所有相关按钮、标题、帮助与中英翻译。只改名称和组织，不改变 CSS / ASS 模式的颜色语义或说话人数据。

### 3.2 导出页按格式组织

| 分组 | 内容 |
| --- | --- |
| SRT | 首条从零开始、按颜色统一保存、说话人文件名后缀、附加说话人名称 |
| ASS | 说明沿用字幕样式与颜色配置，提供对应设置 / 样式库入口，不复制样式控件 |
| OTIO | 同时导出 SRT、包含表情包、字幕作为标记、标记与区段；表情包素材引用 / 便携模式 |
| 动态图形与其他格式 | 简短说明格式专用参数在各自导出确认窗配置，提供明确入口；没有参数的格式无需空白分组 |

- 四个 OTIO 通用开关集中到导出页，继续使用现有偏好状态及默认值。
- 普通与去空隙导出菜单中原重复开关改为「OTIO 导出选项…」入口，均跳转到同一组。
- 表情包 OTIO 模式控件从素材页移动到导出页；素材页保留「配置 OTIO 导出」跳转。
- 修改选项后，普通和去空隙导出均读取同一状态；原导出按钮和结果语义保持一致。
- 轨道、尺寸、帧率等单次参数继续由现有格式确认窗承担。打开配置入口不能直接启动导出或下载。
- 无法使用的 Server 专属格式仍按既有条件提示或禁用，不隐式改变工程绑定。

阶段验收：两个 OTIO 菜单指向同一配置，重新打开与保存重载符合原偏好行为；SRT / ASS / OTIO 结果与现有测试一致。

## 实现接入点

- `web/editor-template.html`：导航、控件位置、面板分组和说明。
- `web/editor.css`：分组、索引行、范围说明与响应式布局。
- `web/editor/ui/editor-settings-panels.js`：既有设置页和区域面板路由。
- `web/editor/ui/editor-wiring-settings-help.js`：入口事件与帮助跳转。
- `web/editor/ui/editor-display-settings.js`：模式相关可见性。
- `web/editor/ui/editor-export-menus.js`、`web/editor/io/editor-wiring-export-actions.js`：导出配置入口与接线。
- `web/shared/editor-i18n.js`：所有新增、改名和修改的中文文本及英文翻译。
- `web/editor/state/editor-settings.js`、波形设置和工程模块：核实范围，避免无需求的存储重构。

新增独立业务模块时按 `web/editor-scripts.txt` 装配，避免扩大 boot 入口。具体修改前核实实际文件内容，以上接入点不要求每个文件都修改。

运行仓库要求的 Node 语法 / 装配、编辑器工具与波形测试、Python 契约测试、类型检查和 diff 检查。Python 一律使用 `uv run --no-sync`，不自动同步环境。

```powershell
node --test tests/test_editor_script_syntax.mjs tests/test_editor_script_order.mjs
node --test tests/test_editor_utils.mjs tests/test_waveform_js.mjs
npm run typecheck
uv run --no-sync python -m unittest discover -s tests -p "test_*.py"
git diff --check
```

新增有意义的浏览器覆盖：区域索引及返回焦点、模式不可用入口、移动控件仍生效、三个改名页面旧 key 可恢复、共享 OTIO 配置、动态隐藏、中英文本与窄窗口布局。避免只测试 DOM 排列而漏掉实际操作。

相关 Playwright 回归按改动选择并记录实际运行范围：`word-timing`、`waveform-history`、`layout-feedback`、`cue-list-layout`、`multi-subtitle`、`editor-i18n-save`、`media-controls-layout`、`otio-export`、`ass-export`、`fcp7-export`。先跑受影响用例，再在收尾跑上述相关 spec；失败必须查明原因。

## 执行与交付

1. 读取 AGENTS.md、当前结构梳理、实际源码与 git diff，核对接手分支已包含基线。
2. 建立 `docs/EDITOR_SETTINGS_IMPLEMENTATION.md` 记录本计划各阶段状态、决定、验证与未验证边界；每完成一阶段立即回写。
3. 按阶段 1 → 2 → 3 串行推进。共享模板和接线有强依赖，不同时铺开大量修改。
4. 最终提交前检查 UTF-8 / LF、无关 WIP、生成 HTML、媒体和个人路径；提交用 conventional commit，包含 2–3 句正文且无代理署名。
5. 交付最终页面分布、截图、验证结果、兼容性说明与未完成项。不要把源码梳理当作已完成的浏览器验收。
