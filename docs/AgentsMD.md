# 文档阅读与维护

默认只按任务读文档，**不要批量遍历 docs 或读取 `_archied/`**。

- 使用入口：[文档索引](README.md)；安装从 [工作流](WORKFLOW.md) 开始。
- 开发入口：[开发概览](DEVELOPMENT.md)、[工程契约](../JSON_SCHEMA.md)、[长命令规则](E2E_SERVER_HANG.md)。
- 后续行动：[未完成事项](OPEN_ITEMS.md)。区分当前待办、缺验证证据和已被新代码替代的旧状态。
- 未实施方案放 `plans/`，不作为已实现能力；原文中的旧架构约束需与当前开发说明核对。
- 历史过程按 [分类目录](_archied/README.md) 存放。归档不代表完成；未闭环项提取到 OPEN_ITEMS，原始证据保留。

当前使用说明只保留有效操作，架构写 DEVELOPMENT，字段写 JSON_SCHEMA，同一规则只维护一处。索引和兼容入口仅给链接，不复制正文。

新任务的过程记录放 `docs/tasks/<任务名>.md`（需要时创建目录），只读当前任务对应文件；用短表更新最新状态与证据，不重复追加整份阶段总结。收尾时将未完成事项提取到 OPEN_ITEMS，过程记录移入 `_archied/` 对应分类，并修复引用。官网副本由同步脚本生成。

历史检索先用 `rg --files docs/_archied` 找文件，再用 `rg -n "关键词或 PR 号" docs/_archied/<分类>` 读命中片段。提交演进用 `git log --follow -- <路径>`；历史测试数字不能替代当前验证。

归档前还须检查代码、测试、脚本和网站生成副本的路径依赖。历史说明与有效测试样本是不同维度：仍被测试读取的资料必须标明依赖并保留，迁移时同步引用、运行对应测试；不能仅因内容年代久远就认定可删除。
