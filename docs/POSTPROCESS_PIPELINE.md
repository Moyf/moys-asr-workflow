# 转写后自动处理

Launcher 的「转写后自动处理」用于把工具箱中的字幕处理串成一次任务。它默认关闭；启用后，转写成功才会启动处理链，原始转写产物不会被覆盖。

## 配置方式

在 Launcher 的「转写后自动处理」卡片中打开总开关，再勾选需要的步骤。步骤顺序固定为：

1. 文稿匹配
2. 固定处理
3. LLM 校对
4. 重新断句
5. OCR 字幕去重
6. 翻译

未配置的步骤不会直接被勾选。固定处理包含按顺序执行的批量替换，以及可选的“转为简体／转为繁体”；它位于翻译前，确保后续校对、断句和翻译看到的是已经统一过的文字。Launcher 会打开工具箱对应页，滚动到第一个无效字段；LLM 配置会定位到 API Key、API URL 或模型。LLM 必须用当前供应商、地址和模型完成一次实际连接测试后才能启用。修改供应商、API Key、API URL 或模型会使验证状态失效；修改提示词、思考强度或翻译目标不会使连接验证失效。

「翻译」只有一个步骤，通过「翻译目标」选择中文或英文，二者互斥。自动处理的配置保存在用户级配置文件中；API Key 仍只保存在 `.env`，配置文件、工程和 Launcher 主日志都不会保存明文 Key。

## 产物与恢复

每次运行都会先保留原始 `.mosp` 和 `.srt`，中间结果统一放入：

```text
<媒体目录>/MAW-Postprocess/<媒体名>-<时间戳>/
```

每一步的产物作为下一步输入，最终结果以 `.postprocess` 后缀写回正常输出目录，并使用防覆盖命名。每个最终文件通过临时文件原子写入。

- 「保留中间产物」默认关闭；成功后会删除本次运行目录。
- 勾选后，成功运行会保留完整运行目录和 `manifest.json`。
- 失败、取消或异常退出时始终保留运行目录；Launcher 会提供「打开自动处理中间产物」入口。
- 失败时可以点击「从失败步骤重试后处理」，使用原来的运行快照从失败步骤继续，不需要重新转写。

自动处理失败或取消不会撤销原始转写；失败步骤之前的成功产物会保留在运行目录中，便于排查和恢复。

## 日志与安全边界

Launcher 主日志会记录总步骤数、当前步骤、每步完成的产物名称，以及 OCR / LLM 长任务的节流进度。不会记录 API Key、完整提示词或模型原始响应；需要查看模型流式细节时，仍使用工具箱中的手动处理功能。

自动处理由 Python 后端统一调度，不依赖前端模拟点击多个工具按钮。开始转写时会生成不可变的运行快照，因此运行期间修改自动处理设置不会影响当前任务。
