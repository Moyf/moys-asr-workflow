### 选测精度修复

PR `e641c371` 的矩阵两片均失败，分别有 457、299 条通过。目标 `2.0dev@4fd058e0` 自身的辅助浏览器任务也失败；两边选测集合不同，不能仅凭红灯相同认定失败用例相同。本地把 PR 所选范围先缩至 13 个 spec 复验，170 条中 160 条通过、10 条失败，失败落在设置、波形反馈、词时序等宽泛消费者。标记专项不在失败列表。

根因是消费图按源码文件中的宽泛 facade 引用和测试读取整份源码选入 59 个 spec，即使七个 G12 web diff 只包含标记 ESM 包装与调用替换。现在 `marker_migration_only` 对这七个文件把 ESM 包装、标记 import 与调用替换逆变换，再与目标基线的**整份文件逐字比较**；任何额外行为编辑、无法读取的基线或不合规导出均回退原有广覆盖。证明成立时仍选标记运行时六组 spec、标记源码契约，以及直接修改的 AI 夹具。当前 PR 计划为七个 spec、37 条 Chromium 用例，全部通过；这不是全量浏览器验证。构建新鲜度、类型检查及消费图测试通过，真实媒体拖动与试听仍由人工清单核对。未提交旧的只检查改动行是否含标记名称的方案，因独立自审发现其会漏掉同一行的其他行为删除。

远端 `f7a5a67d` 的实际辅助计划也列出上述七个 spec；矩阵 `1/2`、`2/2` 均通过。`Change acceptance`、各有限检查、Ruff、Windows MAW-lite 预览与 CLA 均为通过。PR 仍待维护者人工核验与合并。
