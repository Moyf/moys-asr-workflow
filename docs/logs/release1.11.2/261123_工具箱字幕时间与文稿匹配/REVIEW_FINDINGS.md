# 2.0 工具箱字幕时间与文稿匹配复核

目标基线为 `2.0dev@38ccf51f`。从 [#318](https://github.com/Moyf/moys-asr-workflow/pull/318) 移植校对合并和重新断句的词项处理，从 [#423](https://github.com/Moyf/moys-asr-workflow/pull/423) 提取句级文稿匹配的三处修正。2.0 继续通过主轨读写接口处理工程，旧工程导入、轨道身份、绑定和独立组沿用现有约束。

## 输入与结果

| 操作 | 目标基线的结果 | 修正后的结果 |
| --- | --- | --- |
| 校对把两句按原文原序合并，词项含零时长标点及置信度 | 合并结果丢失 `items` | 对整句复核映射、时间和顺序后保留原词项。重新断句时句首零时长标点能与相邻词同段，输出字幕有正时长 |
| 校对合并英文 `Hello,` 与 `world.`，两句词项分别带前导空格 | 旧版丢弃合并词项；仅检查两条原句又会误收与拼接正文不符的词项 | 对最终的 `Hello,world.` 检查，保留正文，丢弃无法定位的词项 |
| 输入两句 `AB / CD`，分别用两行或三行不相关文稿做句级匹配 | 换行路径可绕过已有的匹配度门槛，等行路径还会报告 100% | 在生成 MOSP、SRT 前拒绝；换成 `AB / CX` 时仍能修正并报告实际的 75% |
| 原字幕为 `AB [0,1000]`、`CD [5000,6000]`，文稿分为 `AB / C / D` | `C` 从 1000 毫秒开始，吞掉四秒静音 | 三段分别是 0–1000、5000–5500、5500–6000 毫秒 |
| 仅修正文字，前后句可对齐，中句录音是“猫在沙发睡觉”，文稿该处是“天气预报警报” | 单靠两侧位置推算，用不相关文字覆盖中句 | 保留整个原句及元数据，计入未匹配提示；同一次处理仍可把相邻句中的“结菓”改为“结果” |

## 独立复核

- `maw/postprocess_resegment.py` 的 `merged_source_items` 已处理英文词首空格。三个模型断点协议都拒绝生成零时长字幕。用例在 `tests/test_postprocess_resegment.py`，通过工具箱公开入口读取、处理及重开结果。
- `maw/postprocess_match.py` 在两种换行路径之前执行原有 55% 门槛。仅修正文字时，二分定位第一个结束位置超过当前句首的匹配块，确认它与本句区间相交。独立对照确认，相邻句的字符匹配不会为中句提供依据。输出路径及拒写验证见 `tests/test_postprocess_match.py`。
- v2 绑定和颜色组用例覆盖等条数时保留引用、改变条数会破坏关系时拒绝写出。此次未更换词级文稿匹配算法，也未加入 Launcher 审阅窗口。对于一条本身跨越多个原字幕的新句子，仍允许它跨越中间的停顿。

## 验证范围

本地用临时工程、文稿和受控模型回复复现并回归。公开入口覆盖输出 MOSP/SRT、输入原件保护、零时长标点、英文词项、拒写和时间边界。另跑了迁移另存、拖动保存、命令面板取消导出、暂停 ASS 副轨预览、切轨及样式库的现有 Chromium 用例。真实供应商输出质量与用户录音的人工听校仍待实测。
