### 实跑结果

- Windows Chromium 按完整测试标题收集 20 条，执行 20 条，全部首轮通过。旧工程拖入一项另用真实 OPFS 文件句柄验证了 Ctrl+S 后的文件名及内容，磁盘原件字节相同。
- 颜色组用例在修改前复现首尾共用 0–3000 ms，修改后分别得到 0–1000、1000–2000、2000–3000 ms。普通跨轨移动、删除、撤销及重开回归也通过。
- Ubuntu libass 中右对齐三轨的右边距分别为 20、13、15 像素，护栏画面外的墨迹为零。多行夹具分别保留 11、3、3 行。
- 切片与不切片在 750 ms 均为 209×63，峰值亮度 192；在 1750 ms 均为 263×79，峰值 128。故意重启时钟后两个时点均为 146×44、峰值 64，同一比较在两处都能识别错误。
- 编辑器与 Launcher 构建产物新鲜度、TypeScript 和文档检查均通过。[初次完整执行记录](https://github.com/Moyf/moys-asr-workflow/actions/runs/44939093494)保留了修复前的失败。

### 颜色过滤按钮的独立工程

[官方分片一](https://github.com/Moyf/moys-asr-workflow/actions/runs/44999671548/job/137138275329)在检查无色工程的过滤按钮时读到了前一用例的黄色字幕。单独隔离按钮用例后，本地按文件顺序执行，在另一条过滤菜单用例中观察到 3 个选项，预期仅有默认色和红色。现为该 spec 的每条用例创建独立的无色工程和 localhost 服务，用例结束后释放服务并清理临时目录。
