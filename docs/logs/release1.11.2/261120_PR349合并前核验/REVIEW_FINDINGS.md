# PR 349 合并前复核

本轮以 `6a39519c` 为 PR 起点，将目标分支 `2.0dev@58b408e4` 合入候选分支。原合并基线为 `76bb330a`。冲突只涉及 `AGENTS.md` 和 `editor-checks.yml`，两个文件均采用目标分支版本。

## 字体与样式库

- #377 从 `05a81f72` 到合并提交 `69ce2cc6` 保留了按需覆盖、Arial 优先和局部字体回退的策略。v2 保留工程打开时的字体名称检查，以及重查时对名称和字形覆盖缓存的刷新。实际帧等待字形覆盖期间切换工程或关闭窗口会取消旧请求。FCP 7 图片字幕也等待覆盖，停止导出时保留其他入口共用的字体请求。
- main 合流时需整合重复的字体覆盖、别名及输出接线，保留 v2 的按需重查。main 的 emoji 限制图标在合流时按 v2 轨道数据适配。普通缺字回退使用固定系统候选，复杂脚本与 emoji 仍可能由各渲染器自行回退。
- 最新 `2.0dev` 已允许 Python 保留 65 项，但前端加载时仍切到 64 项。#349 与 main 的 #381 均修正前端加载边界。#349 还保留读取失败时的已加载样式库和联动轨道快照。整库迁移和多个窗口之间的保存冲突保护属于 #381。

## 验证

- 独立复核发现主轨字号较大且叠加句继承轨道样式时，两层会在直接烧录中重叠。旧代码生成的 640×360 画面里，叠加字幕下缘为 y=321，主字幕上缘为 y=194。修复后，主轨与叠加轨使用轨道或单句样式时由 libass 同层布局，FFmpeg 像素测试同时通过继承和单句覆盖两种情况。复核未发现剩余阻塞。
- 最终 Python 工程 ASS、说话人和烧录定向共 97 项通过。Node 字体、画布、样式、说话人和装配测试 488 项通过。编辑器构建与新鲜度、类型和 Ruff 检查通过。
- 旧实现的两项实际帧逆向测试均发出了过期请求。修后，关闭再打开预览窗、等待期间切换工程和正常出帧三项均通过。三项画面测试改用实际帧窗口的渲染按钮，Canvas、Server libass 与导出结果复跑通过。FCP 7 等待时停止和切换工程的两项新用例在旧 head 上均失败，修后通过。
- Chromium 初跑 62 项，52 项通过。失败包含没有等待字形覆盖的直接 ASS 调用、只改样式库却断言既有工程快照的夹具，以及 FCP 7 图片测试的字体等待和 Windows 路径大小写比较。对应的 10 项复跑通过。两项 FCP 7 等待测试也在复跑中通过。
- 轨道样式集成用例迁入 `tests/e2e` 后，目标分支的选择器能生成有效计划。计划包含工程字体、样式快照、样式集成、说话人颜色、ASS 与烧录用例。
