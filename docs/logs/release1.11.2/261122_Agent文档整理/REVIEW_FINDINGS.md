| --- | --- |

## 任务入口走查

基线为 `2.0dev@393dbd5c`，跟进前 PR 头为 `ab160902`。分别从根文件走查准备软件版本、旧工程另存和烧录定位、共享工作树自审。三个情景均可在目标文档或章节找到操作和对应约束。

| 发现 | 处置 |
| --- | --- |
| 直接按新版本替换测试字符串会破坏固定的 beta 样例。打包负例另从工作树复制回退值。 | 在[版本准备](../../../releases/preparation/README.md)点明需要核对的负例，保留固定样例。正式版指南明确系列首版总结与补丁增量。 |
| 浏览器导入和 Server 打开旧工程的迁移标记来源不同。旧字段映射章节未包含另存约束。 | 区分两条路径，将[代码入口](../../../engineering/DEVELOPMENT.md#代码入口)指向包含另存和原件保护的 v2 契约。Editor 的烧录作业与 Launcher 工具箱的桥接各自指向对应测试。 |
| 审查提交范围可能漏本地候选。路径参数无法隔离同一文件中其他会话的改动。 | [自审章节](../../../engineering/DEVELOPMENT.md#提交前自审)要求核对 PR 头与目标引用，补全本次未跟踪文件及暂存/未暂存快照。共享文件先协调或隔离。 |
| 修订自审取证步骤时漏了大改动的分工要求。 | 恢复按产品代码、测试和规范分工的约定。独立复核无 blocker 或 major。 |

版本准备页位于发布归档目录的子目录，避免进入顶层正式版扫描。官网索引保留该页的 2.0dev 链接，PR 合入后指向上游页面。当前软件版本的 16 项入口回归和 20 份正式版归档校验通过。

## 开发维护与用户自动化入口

在 `2.0dev@e8f81c24` 上，批量技能由用户 CLI 指南引入。试读发现技能中的硬件尝试顺序已漂移，现按自动探测、显式选择和失败处理说明。复核也发现技能混用了 SRT 与工程的样式来源，已按 #349 合入后的公开 CLI 指南修正。用户 MCP 指南先标明规划状态，索引保留单独入口，供对应功能 PR 维护。
