## PR #458 Windows 打包复核

`521a615b` 的 Windows 打包预览在真实 exe 启动后报告 `Packaged editor has no application bundle`。用生产渲染器取出空白 Editor 页，旧检查复现失败，且页面里存在一个构建器写入的 SHA-256 产物头。

`scripts/packaging/smoke_editor.py:17` 改为识别带代码的构建产物头。独立复核验证实际渲染结果、空标记和仅有旧全局名称的负例，确认启动、项目身份、资源请求与退出检查继续执行。资产与打包契约共 65 项通过，Ruff 通过。

## Windows 全量 Python 失败复核

以 `6c81ec4a` 为基线，用 FFmpeg 7.0.2 和 10 个 worker 重跑。复现两项去空隙烧录断言、缩略图 PTS 断言、音频取消和任务超时。修复后第一次全量又捕获一次缩略图 HTTP 拒绝响应的连接中止。

- 烧录保留原始包时长，并对旧版 FFmpeg 重映射后缺失的时长按解码间距估算。真实 B 帧与单帧窄区间复核通过。缩略图 PTS 夹具改用 muxer 偏移，旧版 FFmpeg 也能生成声明时长完整的非零起始 Matroska。
- 缩略图 POST 在读取请求体前被拒绝时显式关闭连接。Host、Origin 和长度拒绝的 3 个子用例在修复前失败，修复后通过。
- 独立复核发现通用 Windows 回收若先终止 Job Object，会遗漏注册前已启动的子进程。观察到旧顺序能清理该子进程。保留通用回收顺序，仅直接执行 FFmpeg / FFprobe 的媒体任务优先终止已注册的 Job Object。回收顺序和媒体任务定向共 44 项通过。

最终候选按原命令重跑全量 3,649 项，3,590 项通过、零失败、零错误，59 项跳过。实际用例集合和跳过项与修复前的本机全量一致。

## PR #458 浏览器时钟复核

`a7ead251` 的浏览器辅助分片在波形边界取消后的自动保存用例报 `Cannot fast-forward to the past`。旧用例把测试进程的当前时间传给 `pauseAt`，Chromium 收到时页面时钟可能已超过目标。用真实 Chromium 和短命令延迟复现同一错误。

波形拖动和全文编辑的相关用例在导航前安装时钟，在交互前暂停于共同起点之后的固定时刻。独立复核确认自动保存仍在拖动开始前标记脏数据，并保留拖动期间不保存与释放后真实落盘的断言。全文编辑仍逐段推进计时器，核对焦点和选择结果。

本地 Chromium 用两个 worker 将两个 spec 各完整运行三遍，93 项全部通过。
