## 验证证据与边界

- 工具箱从公开入口读入合成工程，核对 MOSP、SRT、输入原件和保存取消。真实 Windows WebView2 子窗接收 Launcher 快照，并通过测试选址另存，读回 v2 主轨正确。原生保存对话框的人手选址及非 Windows 桌面仍待人工核验。
- Windows 的对齐 worker 在空 PATH 下调用指定 FFmpeg 和 FFprobe，识别第二条默认音轨并输出 500 毫秒 PCM。74 项组合中 47 项通过、27 项跳过。真实云模型返回、真实缺库显卡和用户录音的人工听校另验。
- 半透明底框、逐字换色由真实 libass 渲染；Chromium 覆盖样式库导入往返、三轨开关、手动定位、结果链和对照窗。浏览器保存用底层真实编码和可读 MP4 验证。原生烧录与媒体任务组合 60 项中 57 项通过、3 项跳过。原生覆盖目标在发布前复核身份；外部进程在最后检查与系统替换之间的并发修改仍受平台文件接口限制。
- 早期缩略图 E2E 的 FFmpeg 子进程查询受本机沙箱限制，单项在可查询的环境中复验通过。通用编辑器组合首次因默认 Python 子进程启动超时，显式指定已锁定的解释器后 407 项通过。媒体任务进度测试两次在 0.3 秒观察窗口内未取得样本，改为真实子进程等待测试端确认后退出。
- 提交 `68cbe31c` 的准入检查通过。辅助巡检检出了工具数量、标题选择器和跨平台根目录夹具三类问题；`a8d0dfab` 调整对应验收。本机 3 项 Chromium 与 9 项 Python 通过。各次 CI 只对应其运行的提交，当前状态见 [#431 检查](https://github.com/Moyf/moys-asr-workflow/pull/431/checks)。
- 提交 `7dbc07c9` 的准入和 Windows 预览通过。Linux 辅助 Python 跑了 2,793 项，跳过 21 项，其中 18 项使辅助巡检失败。两项来自本轮对齐 worker 测试。Windows 脚本扩展名用例已接入 Windows 专项，Homebrew 候选路径改用临时夹具，在真实子进程验证有、无包内 FFprobe 的两种结果。Windows 定向复验 18 项全部执行通过。其余 16 项对应目标线既有用例：11 项需要 soundfile，5 项依赖 Windows 路径或 ACL。它们的跳过仍按原规则报告。[该次辅助巡检](https://github.com/Moyf/moys-asr-workflow/actions/runs/45124991379/job/137527352209)

## 维护者复核与评论核销

[对首批代码的审查](https://github.com/Moyf/moys-asr-workflow/pull/431#issuecomment-7089057246)与[对盘点文档的审查](https://github.com/Moyf/moys-asr-workflow/pull/431#issuecomment-7089683934)分别对应 `13ae4a4e` 和 `ff837be2`。后续审查验证了[回填重叠的修复](https://github.com/Moyf/moys-asr-workflow/pull/431#issuecomment-7093049334)，并在 `5e8b4703` 上指出[结果链串线与长片导出两项阻塞](https://github.com/Moyf/moys-asr-workflow/pull/431#issuecomment-7094020817)。[`4337ccca` 的复审](https://github.com/Moyf/moys-asr-workflow/pull/431#issuecomment-7095143662)确认测试配置已修正，两项产品问题当时仍可复现。下列产品验证使用后续修复。

- **文稿回填重叠**　旧启用句被新句完全覆盖时，匹配成功写出，并在报告中说明省略了旧句。与新句重叠的禁用句按维护者决定原样移至叠加轨。重新运行文稿保护、分组及对照还原测试，35 项通过。
- **辅助 Python 红灯**　`5e8b4703` 实跑 2,875 项，断言失败和异常均为 0。21 项跳过中，11 项能量谷用例缺少 soundfile，另有 5 项真实 Windows 路径或 ACL 用例缺少平台登记。修正后的测试依赖组包含锁定的 soundfile，Linux 仅按具体测试 ID 和平台原因认可这 5 项。Windows 使用真实音频及系统 API，17 项全部执行通过；未知用例、缺依赖或缺少原因仍会使严格验收失败。[`5e8b4703` 的原始报告](https://github.com/Moyf/moys-asr-workflow/actions/runs/45126860654/artifacts/14796920675)
- **两个对比入口的工程来源**　原版连续处理独立工程 A、B 后，会把 A 的原始输入与 B 的最新结果配对。修正后的 Chromium 用例走相同的输入、处理和对比按钮，分别验证独立输入、同链续作、历史分支，以及任务处理中再次选源。任务完成后仍按原有行为选中新产物。完整对照窗读取当前预览。
- **FCP 7 透明图片字幕**　用评论中的原样例重放编辑器 ASS 生成器与规划器：1,125 条四秒字幕，每条两词，共 75 分钟、60 fps。旧版将 270,000 帧计入动态采样并拒绝导出。修正后 PNG 和 WebP 均只需 2,250 个采样。真实 FFmpeg/libass 对短片逐帧比对，覆盖整词翻色、淡化、分数帧率和同句多个事件。长片已验证规划，剪辑软件导入留给人工核验。
- **AI 口播整理后再做文稿匹配**　原版会让重复词的空格归属变化破坏已有删词记录。音频仍删除该词而 SRT 再次显示它。以实际口播整理产物对照，修正后工程保留可恢复的两个 Hello，SRT 只显示一次，音频删区仍为 0–200 毫秒。完整对照另存也保护手动恢复与跨句停顿；找不到可靠词项时会在写出前退出。
- **独立文稿命令行**　目标线已有按位置继承 ID 的行为。源句与结果句数相同、分界不同，会把译文或分组转移给另一句。公开命令行入口已逐句核对字符来源，三种错漏词策略均覆盖绑定、颜色组及贴纸组。同一反例在修正前有 9 种组合错误写出，修正后保留原件并提示。
- **遗漏的烧录提醒**　2.0 已有字体覆盖与 Canvas 文本样式处理，但缺少 #377 的实际帧提醒。Chromium 验证了隐藏副轨、ASS 模式开关、撤销重做、鼠标悬停与键盘焦点。图标与相机按钮相距 8 像素，提示框与图标垂直相距 9.5 像素。
- **实际帧回归**　原绿幕用例在当前候选和引入提醒前的 `b7693dbe` 上均未完成。首次失败发生在服务就绪探测或宿主字体覆盖查询，尚未发出实际帧请求。`46099a68` 补回 #377 的字体覆盖夹具；真实帧接口、FFmpeg 和图像断言保留。单工作线程、零重试复验 2/2 通过，验证了音频工程 1.500 秒位置及空白工程的 1920 × 1080 绿底图像。
