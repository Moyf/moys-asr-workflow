# 官网单一真源独立审查

独立审查者未参与实现，按当前 diff 与未跟踪新增源码只读检查，并运行参数拒绝、图片路径与代码示例的内存探针；未运行会清理文件的命令。以下列出审查时发现的问题及处置，具体层级边界见实施与验证记录。

| 发现 | 处置与验证 |
| --- | --- |
| Astro 默认清空输出，且自定义参数可绕过隔离根目录与输出保护 | 改为先构建到隔离目录，目标存在时拒绝；检查和构建不透传参数，开发只允许端口。既有目录保全和参数拒绝均有定向测试；真实 Astro 构建至新目录通过。 |
| 网页图片语法漏检、无扩展名图片落到远端、编码路径不匹配 | 校验本地图片，拒绝尚不支持的引用式、根路径、srcset 与 data-src 形式，支持编码路径；定向测试先失败后通过。协议相对的外部图片继续保留。 |
| 图片可读取环境文件或跟随符号链接 | 文档及图片逐级检查路径，拒绝环境文件与符号链接；使用不存在的环境文件路径和合成链接复验，不读取真实环境文件。 |
| 全量复制可能带入环境文件与无关私有文件，测试夹具也有同类风险 | 官网根输入改为白名单，复制过程过滤环境文件并拒绝符号链接；测试只安全读取必要文档和引用图片，子进程输出固定到自己的夹具目录。 |
| 手写路由和生成路由可冲突；旧图片与手写图片难以辨别 | 预检路由冲突；维护历史生成图片与手写图片清单，未登记图片报错并保留。定向测试与隔离构建覆盖已登记的手写资源。 |
| 开发监听失败可能遗留服务；配图清单改变可能覆盖手写图片 | 监听先于服务启动，失败关闭已创建的监听；热更新先只读验证图片清单，变化即停止并要求重启。真实 HTTP 探针验证普通文档及手写页面更新并回收进程；监听系统错误注入尚未实测。 |
| 文档代码示例被当成图片；Node 支持版本说明过时 | 排除 fenced / inline 代码示例并补测试；按 package engines 更新版本说明。 |

审查者最后一轮确认未发现未处置的 blocker / major；最终 Astro 构建和开发服务由实现者在隔离副本验证。Windows / Linux 原生执行、浏览器 HMR 和远端 CI 未覆盖，不能据本地 HTTP 或构建结果推断通过。
