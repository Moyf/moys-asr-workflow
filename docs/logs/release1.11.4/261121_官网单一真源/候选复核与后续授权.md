# 官网单一真源：候选复核与后续授权

基线为 `Moyf/website-single-source` / `44577872`。开始时已有 `website/dist` 可重复构建相关的未提交修改；本次在其基础上工作，保留 `.pnpm-store/` 等既有内容。

## 发现与处理

1. **Pages 推送路径**：`sync-maw-docs.mjs` 允许安全地读取仓库内任意路径的本地图片，并不只允许 `docs/assets/` 和 `assets/`。当前 23 个本地配图均在 `docs/assets/`，根目录 `assets/` 是目前未使用但允许的输入；原 Pages 过滤器也会漏掉其他允许的图片路径。现对 `main` 的任意 push 执行 Pages 工作流，覆盖范围完整，代价是无关 push 也会构建和部署。阻塞检查选择器对 `assets/` 目前按未知输入选全量，已包含 website；新增测试验证根目录图片、当前图片清单和部署触发约束。
2. **缩进及容器代码**：原同步器只保护顶层围栏与行内代码，将缩进代码里的图片示例当作真实图片；独立复核还发现列表、引用块中的围栏及制表符边界。现在复用仓库已有的 Marked 词法器识别代码块，将容器内去缩进位置映射回原文，再沿用已有图片和导航改写。实际引用式图片仍明确报不支持，代码里的引用式图片示例保留原样。测试覆盖空格、制表符、列表、引用块、段落续行、实际图片、导航与生成文档。
3. **连续构建**：website 阻塞检查按现有命令框架连续运行两次 `pnpm --dir website run build`，不安装测试框架；测试检查命令清单确有两次。两次真实构建另在隔离 checkout 中执行，第二次确认删除 `website/dist/` 中人为放入的旧输出哨兵，且重新生成 FAQ；CI 目前只验证连续两次命令成功，哨兵清理是本地验证，不宣称 CI 自动检查了哨兵。
4. **staging 累积：待协调者决定授权**：`dev`、`check`、`build` 每次通过 `mkdtemp(path.join(os.tmpdir(), 'maw-website-stage-'))` 新建 `<系统临时目录>/maw-website-stage-<随机后缀>/site/`，其中包括生成文档、图片、手写资源和指向官网依赖的链接。当前 `finally` 只关闭计时器和 watcher，从不清理父目录；准备阶段失败也会遗留。实测一个 check 的父目录约 7.3 MiB，实际大小随输入而变。本次未删除任何 Node staging 目录。

建议协调者向维护者明确二选一：

- 授权 Node **只清理当前进程通过 `mkdtemp` 新建的精确父目录**，在准备、检查、构建结束或开发服务退出后执行；不跟随目录内指向外部依赖的链接，不按通配符扫描旧目录，不处理其他进程或先前残留。应覆盖异常路径，清理失败要报告，进程被强杀导致的残留不承诺自动回收。
- 保持当前保留策略，接受临时目录增长；如需清理旧残留，另行明确具体目录和授权。

此授权与已授权清理 `website/dist/` 或 Python 测试仅清理自身本次临时夹具是不同范围，不能自行推定。

## 独立复审
