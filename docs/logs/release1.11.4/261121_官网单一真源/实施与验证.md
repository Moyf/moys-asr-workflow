# 官网文档单一真源：实施与验证

基线为 `Moyf/website-single-source` / `fb02552f`。前一 worker 的生成后检查已移除远端取源，但 Astro 仍会读取跟踪副本、旧生成路由与整目录配图；本次将 Astro 输入改为新建隔离目录，使用当前工作树生成页面和图片。手写页面、普通公共资源及登记的手写配图保留；历史生成 slug 和配图由清单识别，无法判定来源的配图报错而不静默发布。缺文档、缺图、环境文件、符号链接或生成路由冲突会失败。

构建在隔离目录内生成，成功后只向全新的输出目录复制；输出目录已存在时拒绝执行，避免 Astro 清空已有文件。开发服务器仅监听 `127.0.0.1`，同步源文档与手写页面修改；文档映射或配图清单变化要求重启。旧 Git 跟踪副本仍保留，CI 与部署不依赖其新鲜度。

## 验证

- 本机 Node `26.12.1`、pnpm `11.28.4`；在新建隔离目录以 `pnpm install --frozen-lockfile` 安装，锁文件 SHA-256 与工作树一致，实际 `source-map-js` 为 `1.2.2`。曾用 pnpm 10 的探索性尝试不作为验收证据。
- `node --test tests/test_docs_sync_check.mjs tests/test_readme_content_sync.mjs`：22 项通过；覆盖缺源/缺图、图片语法、环境文件、符号链接、旧镜像、手写资源、路由冲突与输出保护。失败先例包括缺图语法及发布空目录处理，修复后重验通过。测试夹具保留。
- 真实隔离流程：先运行 `python scripts/build_release_site.py --preview`，再用锁定依赖执行 `pnpm --dir website run check` 与 `pnpm --dir website run build`。Astro check 0 错误，最终构建 47 页；刻意植入的损坏镜像与旧页面未进入输出，源文档、手写页面、登记的手写配图和其他公共资源进入输出，原副本保持原样。构建前关闭 pnpm 的自动安装检查以确保只使用隔离安装的依赖。
- 开发服务真实 HTTP 验证：分别修改源 FAQ 和手写页面，服务均返回新内容；服务仅绑定回环地址，结束后回收。HTTP 验证不等于已连接浏览器的 HMR 实测。
- `python scripts/check_docs.py`：无新增断链或结构错误；`git diff --check` 通过。独立审查发现的问题和修订过程见 `REVIEW_FINDINGS.md`。
