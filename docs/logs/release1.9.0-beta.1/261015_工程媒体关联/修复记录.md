# 工程媒体关联修复

范围：[PR #238](https://github.com/Moyf/moys-asr-workflow/pull/238)，开发基线 `main` / `1d961b90`。本记录保留设计、审查结论与验证边界；完整操作过程、截图和原始输出只保留在本地 `.artifacts/`。

## 问题与处理

| 问题 | 状态 | 决定与实现 |
| --- | --- | --- |
| 子目录工程引用媒体文件名导致缺失 | 已修复 | 媒体引用以工程目录为基准，同目录写文件名，子目录写 `../media.mov`，跨盘回退绝对路径。真实媒体探测继续使用源路径。 |
| 旧 `_maw` 工程不能找到父目录媒体 | 已修复 | 原路径和现有同目录匹配失败后，仅在 `_maw` / `*_maw` 父目录尝试原引用的完整文件名；不递归或猜测扩展名。 |
| Launcher 手动关联只对本次生效 | 已修复 | 默认勾选「记住关联」，加载成功后只更新 `media` 并保留 `.bak`；取消则仅本次使用。重复绑定不覆盖原备份，写入失败明确提示。 |
| 派生、搬移和另存为破坏相对引用 | 已修复 | 后处理写出、原始快照、跨目录搬移、最终发布及生成编辑页都按目标位置重算；浏览器隐藏目标目录时使用已知绝对源路径，换工程不套用旧绑定。 |
| OCR runtime 打包漏依赖 | 已修复 | `postprocess_io` 新增 `project_io` 依赖后，补入 `MAW.spec` 的 `ocr-runtime/maw` 清单；保留完整导入图契约检查。 |
| 生成页媒体 URL 含特殊字符 | 已修复 | 仅相对 URL 使用 `quote(..., safe='/')`，不编码工程原生路径，不重复编码跨盘 file URI。覆盖 `#`、字面 `%20`、中文空格与特殊字符目录。 |
| 断服救急下载沿用旧相对引用 | 已修复 | 回退下载单独构建 `buildJson({ forFileExport: true })`；正常服务器提交仍保留相对路径。覆盖取消、静默失败和替代媒体。 |
| 资产测试匹配旧 `buildJson()` 签名 | 已修复 | 更新签名断言，保留紧邻的时间基准同步检查，不重生成便携副本规避测试。 |
| 指定 HEVC 视频黑屏 | 仅说明 | Chrome 读到元数据后报 `PIPELINE_ERROR_DECODE`；FFmpeg 可抽出正常画面但有 SPS 告警，临时 H.264/AAC 720p 对照可播。尚未区分硬件与码流兼容性，未修改原视频或引入自动转码。 |

代码入口：`maw/media.py` / `maw/project_io.py` 管理路径，`server-editor/serve.py` 与 Launcher 管理重新关联，`maw/postprocess_io.py` / `maw/postprocess_pipeline.py` / `edit.py` 覆盖派生链路。现行用法以 [Launcher 指南](../../../user/LAUNCHER_GUIDE.md) 和 [工程契约](../../../engineering/JSON_SCHEMA.md) 为准。
