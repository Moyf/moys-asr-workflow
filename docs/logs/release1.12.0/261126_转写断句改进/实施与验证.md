# 转写断句改进：实施与验证

这轮问题出现在本地 Qwen 反馈样本中，但设置分发和字幕断句由多条转写路径共用。下表按用户可感知的行为列出变更，也作为后续 PR 说明的核对底稿。样本、原始识别输出和工程不入库。

| 项目 | 以前 | 现在 |
| --- | --- | --- |
| 统一符号配置 | Launcher 只把自定义断句符号传给云端 Qwen；公开 CLI 会丢掉显式空串。 | 云端和本地入口接入同一清单；未指定用默认值，显式空串禁用标点断句。换行、停顿与长度规则不依赖标点；单词型逗号仍只用于超长补拆。句尾显示仍由保留设置控制。 |
| 本地 Qwen 零时长归并 | 句号后的零时长字会并到前一个时间项，把下一句的开头带回上一条。 | 遇到真实的标点切点，优先归入右侧可用时间项；不为零时长字编造独立时长。没有右侧可用时间项时仍保留文字。 |
| 成对引号 | 内部逗号容易把短引语拆散。 | 优先保住放得下的成对引语；引语超长、碰到停顿或没有配对时，允许按合法边界切。 |
| 短句与已有切点 | 后续字幕太短时一律优先向前并，可能把下一句起头放到上一条。 | 普通短句不撤销已生效的标点切点；超长补拆仍尽量避免短尾。 |
| 断句字数 | 标点和空白也占字符额度。 | 字符型的上限、短句阈值和引号判断只计正文；原文与实际字词时间码不因此改变。 |
| 超长补切 | 时间项中间的标点可能被错当成项尾切点；长引语退回补切时可能忽视真正的逗号边界。 | 优先选贴着已配置标点的合法时间项边界。必须拆引语时，内部真实标点可作候选；没有合适标点再考虑词边界。保留数字表达与原时间项。 |
| 极短逗号片段 | 1 个字也可能单独闪一下。 | 字符型字幕若仅有 1–2 字、真实时间项跨度不超过 300 ms、后文在 200 ms 内接上，可跨已配置的中英文逗号向后合；不跨说话人、换行或停顿分组，不超长度上限。句号、叹号等仍保留；不使用插值时间触发该规则。没有词表。 |

## 验证与边界

- 较早的 A/B 用同一份 4:04 音频各跑一次本地 Qwen3-ASR-0.6B，九个原始识别块及时间码一致。两版是独立生成的工程。
- V3、V4 使用相同的识别数据回放，仅对照规则和参数。V3 用 500 ms、18/5 字；V4 只改为 900 ms、25/3 字。两份工程是当时快照，不代表最终规则。后续本轮只做内存回放，没有改写四份对照工程。
- 最新规则的样本回放：18 字上限在 00:44.160 选择真实逗号边界；25 字上限保留完整引语。两组参数都把 01:54.720 的 80 ms 单字片段并向后文，正文无丢失。
- 相关自动化覆盖配置传递、零时长字归并、成对引语、标点与空白计数、强边界、说话人隔离、句级插值和自定义补切符号。新增的超长引语与短逗号片段用例已确认在修复前失败。
- 本轮相关自动化 582 项通过；文档链接和发布说明校验通过。
- 不改模型识别、30 秒音频分块、全局最低显示时长或真实字词对齐。只有句级时间时，不把估算切点当成真实字词时间。真实云端供应商与最新规则的实机推理未重跑。

## V5 对照与后续建议

- V5 沿用 V4 的 900 ms、25/3 字参数和同一份本地识别结果，只替换断句规则。四份原工程未改写。多工程工具保留早期对照页，并在另一页载入 V2–V5。
- V4 → V5：139 → 131 条；显示时长不超过 300 ms 的段从 10 → 6 条。正文不丢字，输出字词时间范围均来自原识别时间项。单样本数字不代表整体质量。
- 优先候选：原始 AAC 的 `ffprobe` 时长约 184.12 秒，完整解码为 243.968 秒。本次为避免漏尾使用了显式预解码。直接对 AAC 分块时应以解码时长为准，而不是普遍修改字幕规则。
- 低风险候选：提示极短、异常拥挤或恰在音频分块边缘的字幕，默认不改时间或文本。样本 00:48 附近的 1.28 秒时间码空档，用简单低能量检测未检出静音；该检测不能证明有无讲话，不宜直接拿空档给字幕延时。

## 多工程转写对比

- 转写对比的浏览器导入和 Launcher 预载各自限制为 10 份；时间码对比仍是双文件工具。十份字幕可分别显示或隐藏，隐藏项仍保留卡片和加载名额；重新显示无需导入。
- 表格、时间线、搜索和差异只使用显示中的文件。隐藏基准时暂时停用差异筛选，恢复后继续对照。多文件时间区间按排序后的起点单次扫描分组，避免重复扫描后续区间。
- Chromium 验证了第十一份拒绝、键盘切换后保持焦点、基准恢复、全隐藏和再显示。实测 320 / 375 / 414 / 768 / 1280 px 下无页面级横向溢出，表格内部可横滚；开关轨道 34×20 px、文字不小于 11 px、与相邻信息至少相隔 8 px。深浅截图见本机 `.artifacts/compare-visibility/`。另用 Orca 加载了实际五份工程。
- 转写对比的两项 Chromium 用例、工具页六项静态检查与预载七项 Python 测试通过。独立的时间码对比分组用例仍在同一断言失败，在 HEAD 测试上复现；未改动时间码对比页。

## Agent 一条命令打开对比

`MAW.exe --compare before.mosp after.srt` 复用 Launcher 的预载协议和既有转写对比 HTML。只读取显式参数给出的本地文件，按参数顺序载入，重复路径只取第一次，不从 URL 参数读取文件，也不写入输入工程。源码入口同样支持 `--compare`；窗口关闭即返回。

Windows 源码实测从 `maw_gui.py` 分发 CLI，真正启动原生 WebView，并确认同一窗口内按顺序渲染了合成 `.mosp` 与 `.srt`；测试结束关闭了窗口。相关 Python 测试曾通过 592 项；未重打发布安装包。
