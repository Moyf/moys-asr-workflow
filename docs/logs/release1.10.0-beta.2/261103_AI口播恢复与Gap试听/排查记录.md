## 条目 1：为什么两种弹窗不同

1. [AI 整理后端](../../../../maw/postprocess_ai_cleanup.py) 对自动删除生成紫色标记，调用 `_ai_annotation(..., pending=False)`，没有 `review` 字段；媒体移除范围写入 `provenance.sources.ai_cleanup`。整句移除还会禁用主字幕及绑定副字幕。
2. [标记面板](../../../../web/editor/markers/editor-markers-panel.js) 的 `isAiCleanupReviewMarker` 要求 `[AI]` 备注、有效区段和待复核 / 已确认状态，或者已存在归属于该标记的 `ai_cleanup_review` 记录。自动删除标记不满足条件，因此按钮隐藏，复核状态显示「无」。
3. [复核静音操作](../../../../web/editor/ui/editor-gap-remove-ui.js) 的 `toggleAiCleanupReviewMute` 只增删 `ai_cleanup_review`。它没有撤销 `ai_cleanup` 自动删除的入口；仅把按钮显示出来仍不足以恢复声音。
4. 自动删除的 Gap 与标记目前没有稳定的归属 ID 关联。新增恢复能力需要明确关联，不能只按颜色或备注文字判断；旧工程需要依据可靠的范围 / 字词证据匹配，无法唯一匹配时应回退到范围恢复操作。

### 建议的用户交互

复核决定与媒体保留状态分别呈现，名称、颜色、删除标记操作沿用现有弹窗：

| 当前媒体状态 | 状态提示 | 主要操作 |
| --- | --- | --- |
| AI 已完整移除 | 已移除 | 恢复声音 |
| 人工恢复 | 已恢复 | 再次移除 |
| 标记范围只部分被移除 | 部分移除 | 恢复此区段声音 |

- 普通标记保留原有复核循环；AI 删除标记不再用「无」代表媒体处理状态。
- 「删除」保留删除标记的含义，不作为恢复声音的替代入口。
- 主操作明确为「恢复声音」，作用于当前标记范围并写入人工保留决定，进入撤销 / 重做与工程保存。
- 整句字幕也被 AI 禁用时，另提供「恢复声音及字幕」。只改 Gap 不会自动重新启用整句字幕；局部字词投影则会根据最终有效 Gap 恢复对应文字。实现时需要保留原字幕状态及绑定关系，避免覆盖后续人工编辑。
- 多来源重叠时，界面应报告最终是否还有移除范围；不能仅撤销一层就显示「已恢复」。

## 条目 2：先听到音头再跳过

- [核心判定](../../../../web/shared/gap-remove-core.js) 的 `getGapPlaybackSkip` 只匹配已经满足 `start <= currentTime < end` 的范围，没有提前安排下一个边界。
- [播放器事件](../../../../web/editor/media/editor-media-playback.js) 通过 `timeupdate` 和 `requestAnimationFrame` 调用跳过逻辑；`play` 只启动下一次动画帧，没有先完成 Gap 内起播位置的校正。
- [播放循环](../../../../web/editor/media/editor-playback-loop.js) 的 `applyGapPlaybackSkip` 只设置 `player.currentTime = gap.end / 1000`。它没有在入区间与异步 seek 期间抑制声音，因此视觉覆盖正确也不能保证试听没有残留音头。
- 逻辑实验：Gap 为 `[1000, 2000)`，上一次检查在 `995ms` 时不会跳过；下一次检查在 `1012ms` 时才发起跳转，播放器声音仍为开启状态。这是受控逻辑示例，不能当作用户原片的实测泄漏时长。
- 同一 Gap 的 seek 守卫会阻止重复跳转。若落点量化回 Gap 末端内部，守卫仍返回且声音未关闭，存在残尾继续播放的边界风险；这是另一条逻辑复现，不代表已在用户原片观察到。

建议播放修复覆盖三条路径：在下一个 Gap 边界前安排播放控制、seek 期间抑制输出并在安全落点恢复、从 Gap 内起播时先定位再出声。声音门控须独立于监听音量与工程增益，遵守用户暂停 / 静音状态，并处理连续 Gap 与落点量化。

另外，区段「定位试听」会有意绕过 Gap，播放该区段原声；点击 Gap 也会临时预览该 Gap。这与正常播放漏出一小段音头后跳转需要分开验收。
