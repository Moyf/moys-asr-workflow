# 转写卡在「正在校验和修复时间码」

## 现象

用 stt-async-v6 的 Windows 打包版转写一条 43 秒 AV1（2560×1600）DVR 录制，进度行停在
`[解析] 正在校验和修复时间码...`，之后长时间无输出、进程不退出（实测 100 秒以上仍未结束）。
同一文件换 stt-async-v5 也一样，说明与模型无关。

## 定位

- 该行日志在 `maw/asr/soniox.py`，紧跟其后是 `repair_segment_durations`（毫秒整数修复，
  毫秒级完成），再往后才是波形缓存：`[waveform] 已生成波形缓存` 之类。卡住的日志位置因此
  是误导，真实卡点是波形提取。
- 直接调用 `maw/waveform.py::extract_waveform` 复现，`faulthandler` 栈固定在
  `maw/waveform.py` 的 `process.stdout.read(4096)`。
- 差异只和 ffmpeg 有关：系统 ffmpeg（libdav1d 解码）无明显日志、秒过；打包内置的 8.1.2
  （libaom-av1）对这条损坏录制即使在 `-loglevel error` 下也吐约 10.7 KB
  `Failed to decode frame` / `Corrupt frame detected`。

## 根因

`extract_waveform` 同时把 `stdout` 和 `stderr` 接到 `subprocess.PIPE`，但只在 stdout 读完后
才读 stderr。Windows 匿名管道默认只有 4 KiB 缓冲：ffmpeg 写满 stderr 后阻塞在写日志上，
Python 阻塞在等 stdout（音频数据），双方互等。矩阵探针：

| 变体 | 结果 |
| --- | --- |
| stderr 不管 | 20.01s 后强杀，stderr 里只留下 4076 B |
| stderr 通过线程排空 | rc=0，0.06s |

兼容性佐证：`maw/quapeaks.py`、`maw/thumbnails.py` 早就把子进程 stderr 写临时文件，
只有 `waveform.py` 还留着 PIPE 对。

## 修复

`maw/waveform.py`：stderr 改为 `tempfile.TemporaryFile()`，进程结束后 seek 回来读文本，
失败路径与退出码路径共用同一个 `read_stderr()`（读后关闭）。stdout 仍是管道，逐块读取不变。

## 验证

- 单条媒体连续 3 次提取：修复后每次约 0.12 s，修复前无限挂起。
- 回归用例 `tests/test_waveform.py::WaveformExtractionTests::test_extraction_sends_stderr_to_a_file_not_a_pipe`
  断言 stdout 仍是管道、stderr 不是管道（修复前失败，修复后通过）。
- `tests.test_waveform tests.test_media_cache tests.test_reapeaks` 77 项、
  `tests.test_soniox tests.test_gui_workflow tests.test_waveform tests.test_media tests.test_thumbnails`
  236 项通过；`ruff check`、`pnpm run typecheck` 干净。
- 打包版端到端：重新构建后同一媒体 `--transcribe-soniox ... --with-waveform` 10.98 s 完成
  （修复前 420 s 超时），波形缓存 4312 peaks 覆盖整段 43 s，SRT 与工程正常落盘。

## 边界

- 只处理 stderr 死锁；ffmpeg 仍然解不出该录制的画面帧（缩略图 mjpeg 报 `Invalid argument`），
  与本次问题无关、维持原状。
- `maw/media_jobs.py`、`maw/media_export_audio.py`、`maw/postprocess_ffmpeg.py` 仍是 PIPE 对，
  但各有排空方式或输出量小，本次未改；需要时可同样收口。
