## 根因证据与 diff

合并后的 `editor-wiring-overlay-transfer.js:initOverlayTransferWiring` 通过 static import 引入 `cues/overlay-track.js`，按清单位置执行规范化并注册命名空间。`editor-wiring-export-context.js`、`editor-json-repair.js`、`editor-sticker-overlay.js` 也已是 init ESM。

旧 `tests/helpers/track-golden.mjs` 却把 export-context 按注释截成半段，再 vm.runInNewContext；截取后仍含 import，且 init 函数外壳不完整。其他 ESM 文件也被当 classic 脚本直接执行。首个错误为 `SyntaxError: Cannot use import statement outside a module`，并未到达 golden 或 getter 引用比较。sticker 用例有独立同类语法错。

改动仅限测试基础设施与回归覆盖：

- helper 使用仓库 `compileSources/readSources/readModules`，按当前 manifest 的原顺序装配完整 multi core、timeline、overlay init、export-context 与 JSON repair；真实 static import 跟随生产编译器解析，不剥 import、不按注释切源码、不复制生产实现。
- VM 的 window 与全局对象共用同一门面，移除手动复制 MaweMultiSubtitleCore/MaweTimeline 的旧接线，避免 ESM 自由变量与 window 脱节。
- getter 测试改用 main 的 MAWE.resolve('overlay-track') 命名空间；strictEqual/全字段/输出比较保持。新增回归证明现有 normalize 会替换 overlay 容器，但持有的 TrackStore 能在随后 resolve 到新容器原 cue；只替换 overlay 容器时也不缓存旧引用。
- sticker 初始化同样经过编译器，复用真实工程 core/getter；补齐 main 的 preview 状态门面，原两张图、四个组区间及两个开关的断言不变。
