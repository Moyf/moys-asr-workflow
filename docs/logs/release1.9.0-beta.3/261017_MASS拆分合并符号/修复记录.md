# MASS 拆分/合并符号处理修复

基线：`feat/ass-style-line-spacing` / `af141848` 起步；开发期间并行提交 `96685652`（样式库默认值与内置条目管理）落库，本任务两个源文件与其无交集。

维护者实测反馈（2026-10-17，含截图）：两条同类问题 + 一条整句/非整句的实现提醒。

| 条目 | 状态 | 处理与边界 |
| --- | --- | --- |
| 单词型合并不折叠符号对 | 已修复 | `!!This is a!!` + `!!short test video!!`（单词型，空格连接符）合并得到 `!!This is a!! !!short test video!!`；预期 `!!This is a short test video!!`。原因：`joinSegmentTextsMassFold` 的 junction 折叠以 `separator === ''` 为门槛，只有字符型（直接拼接）走折叠。现移除门槛，把分隔符作为 joiner 传入 `foldMassPairJunction` 复验重 union，折叠后把分隔符插回 junction，items 层把分隔符归位到后段首个存活 item 开头，守恒契约继续成立。 |
| 渐进拆分左半句不补全 | 已修复 | 渐进拆分 `**重新开始**` 得到 `**重` + `**重新开始**`；预期 `**重**` + `**重新开始**`。原因：`buildSplitPair` / `splitAtCursor` / 联动弹窗预览三处渐进路径都跳过 `splitStyledTextParts` + `completeSplitMassPairs`。现渐进与普通拆分同走刀点吸附与补齐，仅采用左段结果；右段保留整句原文（自带开符号），`rightPrepend` 置空，右段 items 维持原切片。附带行为：切点贴着符号时渐进也吸附（左半句不再产孤儿符号；符号旁无正文的切点会被拒绝，与普通拆分一致）。 |
| 整句 / 非整句标记区分 | 已修复 | `!!`（原地震动）与 `>>…<<`（淡出淡入）是句级壳，其余六对是行内标记。合并折叠中原 `!!` 走行内 pair 解析，与句级 parse-once 语义不符：新增 `shakeShellPair` 句级分支（与 fade 并列，按 `parseSentenceShakeMarkers` 复验），并把 `!!` 移出折叠的行内 marker 列表——行内形式的 `!!` 不跨 junction 折叠（折出来也是句中死标记）。拆分侧 `!!` 是对称符号，由 styled crossing 与 `completeSplitMassPairs` 行内兜底补齐，无需改动。 |

涉及文件：`web/shared/utils/text-processing.js`（foldMassPairJunction 加 joiner 参数与 shake 壳分支、joinSegmentTextsMassFold 去门槛 + 分隔符落 items）、`web/editor/cues/editor-split-core.js`（buildSplitPair / splitAtCursor / 联动弹窗预览三处渐进门槛）。
