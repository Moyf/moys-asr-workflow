# PR246 同页工程切换失效

## 目标与基线

基于 PR246 `4da10a946848e9c037e48785e8908001287c5bf4`，在独立副本分支 `code/pr246-switch-intent-20261018` 修复同页旧请求迟到改变服务器绑定的问题。本轮不整合 main、不修改其他任务分支。维护者随后授权独立复审通过后提交并推送到 PR246 原分支。

网页打开 A 后，服务器可能仍在加载 A；用户又打开没有媒体路径的本地 B，B 不发 attach，旧 A 因服务器绑定未变仍可成功。原 PR 能保住页面 B 并禁止写错文件，但没有让服务器知道旧 A 已过期。

## 最小协议与模块

仅修改两个产品模块；Launcher 继续负责启动服务和打开 URL，不参与网页内切换。

| 模块 | 改动 |
| --- | --- |
| `server-editor/serve.py` | 每份页面配置生成独立 `projectSwitchPageId`；新增 `POST /api/project/switch-intent`；维护每页最新代次；attach/recent 加载前及发布绑定时检查代次，同时保留现有绑定 CAS |
| `web/editor/io/editor-server-save.js` | 复用 `observeProjectLoad`，每次开始加载即发送通知，包括本地工程；通知绕过旧 attach 队列；attach/recent 等待对应通知确认，并携带页 ID 与代次 |

通知携带 `requestToken`、`switchPageId`、`switchGeneration`。通知只更新意图，不改变绑定或保存能力；同代次可重复确认，较低代次返回 409，不得回退。代次按页面隔离，存于服务器进程内存，不写入 MOSP 或用户设置；每个发生切换的页面增加一条记录，随进程结束释放，不随意回收旧条目以免迟到请求复活。HTTP attach/recent 缺少有效意图时返回 409，旧页面需刷新；内部 Python 调用保留原合同。

加载前检查拒绝尚未开始的旧任务；发布前检查与 `_bind_project_locked`、最近工程更新共用 `settings_lock`，拒绝旧任务的绑定发布及其取消媒体任务、缩略图重绑等副作用。已有绑定 CAS 仍处理另一页面先改变绑定的情况。

通知失败时不发起/重试 attach，禁用服务器保存并提示先导出当前工程后刷新。过期通知的失败不再干扰新页面内容。后续显式打开仍按既有规则恢复传输游标。

保证从服务器登记新意图后开始成立，以通知确认作为可观测边界；已发布的绑定不回滚。本地工程仍不自动解绑服务器；其他页面不因本页代次而被取消。已开始的读取、解码或可重建缓存计算不在终止承诺内。

## 回归设计

- Python 使用真实临时 WAV/MOSP 与真实 HTTP，在 A 的 `load_project` 设置事件屏障；只登记较新的本地意图，再释放 A。attach/recent 均须 409，发布方法、设置落盘、延迟加载启动均不调用，绑定、最近记录及 A/B 文件不变。
- HTTP 覆盖请求令牌、缺少/非法意图、通知乱序与重复、独立页面代次、跨页面绑定 CAS，以及新代次正常接管。
- Node 覆盖通知绕过阻塞队列、attach 等待通知确认并携带同代次、通知失败不重试，以及旧失败不干扰新工程。
- 复审补强：通知已经被服务器登记但响应丢失，本次 attach 不发送、保存保持禁用；下一次显式打开通过更高代次恢复。Node 模拟登记后丢响应，Chromium 以真实 `route.fetch()` 成功后中断响应验证。
- Chromium 在真正发出旧 HTTP 变更前暂停它；通过真实网页打开无媒体 B 并等待通知确认，释放后检查 409、B 内容、禁用保存、服务器绑定与磁盘文件，再显式打开工程确认恢复。服务器加载期间的时序由 Python 屏障补齐，没有把响应延迟当成服务端加载暂停。
- 另修正生命周期夹具根路径为 `Path(self.temp.name).resolve()`，避免 macOS 路径别名使断言和屏障 mock 不匹配；本轮无 macOS 实机证据。
