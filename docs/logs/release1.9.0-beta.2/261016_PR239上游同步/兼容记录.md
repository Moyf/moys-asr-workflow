## PR242 与 PR239 同时保留的行为

视频预览继续支持关键帧标记、铺满画面带、隐藏三态，铺满模式可关闭实时补间并只读缓存；Launcher 保留高精度画面预览开关、旧预设迁移及播放优先调度。

工程仍按 PR239 的持久化内容检查点判定未保存状态，保存 v2 分组、字幕属性与 FPS 来源。视频图片、解码结果及本机画面显示偏好不成为新的工程真源，也不因缓存刷新触发未保存提醒。工程更换或解除媒体绑定时，缩略图绑定与旧请求失效处理保持有效。

2.0（含预发布版）独立 HTML / 在线入口退役门禁继续生效，本地 Server 的视频预览、工程打开、保存、备份与导出保留；1.x 继续按过渡规则支持旧入口。

## PR243 编辑视图：保留功能，后续适配

依据 [PR243 的兼容结论](https://github.com/Moyf/moys-asr-workflow/pull/243#issuecomment-6195098386)，记住纯文本编辑视图与 PR239 保存机制应同时保留。本轮未合入 PR243 的实现，也不把下述组合场景记作已验证。

后续接入要求：

- 延续 `timed_text_edit_view: rows | single` 的语义；缺失按 rows，默认 rows 可以省略写出。同步工程字段分类、载入、Python / 浏览器接受规则及文档。
- 将该偏好接入纯 `projectSnapshot()` 和实际保存输出，统一由 PR239 的内容指纹和最近成功保存的快照判断变动。不要恢复旧 `projectSaveFingerprint()`，也不要增加 `timedTextEditViewDirty` 作为第二套判脏真源。
- 视图选择改变后沿既有入口刷新保存控件、关闭提醒与自动保存调度；仅调用刷新函数而没有更新持久化快照，不能算完成适配。
- 保存只确认发起时捕获的快照。保存期间切换视图应仍提示未保存；切回已保存内容应恢复干净。旧工程保存响应不能确认新工程的视图偏好。
- single 因字幕含内部换行等原因临时降级为 rows 时，保留工程选择，不把实际显示降级覆盖成用户偏好。切换工程不得串用另一工程的选择。

组合回归至少包含：首次打开与默认值；v1 / v2 的双端接受规则及非法类型 / 枚举；主动切换与切回；自动保存；保存期间再切换；写入失败 / 取消；Server 保存、文件句柄和另存为；保存重开；工程切换与旧响应；运行时降级后保存。仅写备份不推进工程保存检查点；备份恢复应保留已成功持久化的偏好。实现若沿用可撤销工程命令，还须核对撤销 / 重做与内容检查点一致。
