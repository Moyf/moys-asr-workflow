## 实现 / 审查结论
<!-- id: implementation -->
<!-- badge: fixed 只读 -->

条目 1（修复）：assignSticker 写入 head.sticker 后立即调用 syncTimelineGroupRanges，head 区间覆盖整组而不是首句；applyCanonicalProject 与服务器直接注入 DATA 的启动路径均在加载时归一，治愈旧版本落盘的工程。根因与症状闭环：拖动提交路径（onCommitEdit）本来就调用同一同步函数，所以拖一下就恢复。

条目 2（特性）：实际画面窗口在帧 PNG 上叠加表情包图层，纯前端实现，serve.py 与成片烧录顺序未动。层定位框取 PNG 的 object-fit: contain 实际绘制矩形；几何取 preview.sticker 归一化几何（previewGeometryToCss，与舞台表情包层同源）；显隐跟随「预览表情包」开关（stickerBurnEnabled，与烧录行为同源）。叠放次序与舞台暂停视图一致：表情包层压在实际帧上方；表情包与字幕位置不相交，真重叠的场景暂不处理。

后续小改进：全局设置打开「启用表情包」的那一刻自动勾选「预览表情包」；只挂在用户的开启动作上，启动恢复已保存的「预览关闭」不被覆盖。
