# ASS 像素核验准备复用

本分支接在独立产品修复 `4898229f` 之后，只调整测试成本。A1 的大字号斜体真实回归、原 Canvas / libass 三像素阈值和全部原断言保持不变；205 个原 `expect` 调用的 AST 比较完全一致。

## 等价范围

- 像素统计跳过全黑外边界及角色 mask 的空白边缘，保留坐标原点、内部空行、阈值、峰值、颜色统计和字形摘要。
- 同一测试内，同一完整 ASS 源字节和完整时刻数组只准备一次 native / guard 两个真实画布序列。libass 仍看到精确毫秒；仅在渲染滤镜之后重设输出编码时钟。
- 每个原标签仍保存 ASS、原始 PNG 与 FFmpeg 日志。缓存按测试实例隔离，返回指标深拷贝，改变一个源字节或任一采样时刻都会重新准备。

从真实瞬时移动旅程导出的同一份 ASS，在 490、500、501、1490、1500、1501、1750ms 比较 A1 的逐点 oracle 和本分支序列 oracle：14 张 native / guard 图像原始像素逐字节一致，guard ASS 字节和所有像素指标一致；真实 FFmpeg 启动由 14 次降至 2 次。字体选择日志属于整段真实序列，不宣称逐时间点日志完全相同。

独立小图验证黑边、断行、角色阈值、颜色容差和摘要；缓存负例验证源字节、时刻数组、跨测试及返回值修改的隔离。真实浏览器只跑大字号斜体、静态对照与七时点瞬时移动三条必要旅程，均通过。

## 未抽取与边界

源治理分支另外包含第三 viewport 画布、Decimal 坐标移位和像素判定校正，本次没有抽取；也未带入多行轨道隔离、切片参考修正、设置入口、字体 TTC 或其他 UI 改动。本分支继续使用 A1 的 native / guard 两画布与原 `nativeSHA == guardCropSHA` 判定。

序列方案以有限帧文件和指标缓存换取较少进程启动，不宣称峰值内存减少。本地 Node 24.19.0 低于 engine，结果不能替代合规环境 CI；本分支仅本地提交，不推送或创建 PR。
