## 需求与方案

用户希望通过 📣 按钮调整整段音量，显示原始与调后响度、对比 LUFS 参考，并将调整用于视频预览和烧录。首版仅使用固定增益；“均衡化”实现为整体响度归一化，不加入压缩、限幅或频段均衡器。

先调查 quapeaks、媒体替换、工程保存及三条烧录链路，再由 Astra high 子代理单独给出 UI 和接入方案；主代理与 Sol 子代理分别实现后端与前端。

- quapeaks 的 `moy.asr.loudness.v1` 是线性 RMS，逐桶选最响声道，供波形缩放；缺少 LUFS 的 K 加权与门限等信息，不能直接换个单位充当标准测量。
- 📣 面板集中放置工程增益、原始整段 LUFS、调后预计值、参考选择、归一化、重置与监听音量。沿用原监听音量，只影响试听。
- 工程参数为 `audio_processing: {gain_db, target_lufs, peak_ceiling_dbtp}`；增益范围 −60 到 +24 dB，峰值参考固定 −1 dBTP。测量不写入工程，不混入 `DATA.loudness`。
- 预览使用 `MediaElementAudioSourceNode → GainNode → destination`，增益为 `10^(dB/20)`，与播放器监听音量相乘。用户手势恢复 AudioContext，每个播放器仅捕获一次，替换播放器时断开旧路由。
- 后端按需分析当前 `/media` 服务的实际预览文件及默认音轨；可能是源媒体的浏览器转换缓存。返回明确的预览音轨索引。
- `POST /api/audio/loudness` 复用绑定及文件指纹缓存；202 表示分析中，200 返回 measured/silence/no_audio/error。重复轮询不重复解码，force 只重启已结束的分析；切绑定和关闭服务会取消进程。接口只接受绑定身份，不接受客户端路径。
- FFmpeg `loudnorm` 仅作分析，读取 `input_i` 与 `input_tp`；处理后的输出丢弃。实际烧录只用 `volume=…dB`，去空隙在每条最终 concat 音轨后应用一次，其余路径使用普通音频滤镜。
- 归一化增益为 `clamp(min(target-I, -1-TP), -60, 24)`，按 0.1 dB 向下取整。峰值余量不足时显示未达目标。手动超限只提示，不偷偷改变用户增益。

## 响度口径与边界

EBU R128 的节目响度参考为 −23 LUFS；制作真峰值参考为 −1 dBTP。−16/−14 LUFS 仅称常见参考。调后 `I+gain` 和 `TP+gain` 标为预计值，门限、剪辑和 AAC 编码可能造成偏差。峰值参考用于自动计算增益，不保证编码后成片或未测音轨达标。

普通/去空隙烧录对全部保留音轨使用同一增益；绿幕沿用原所选音轨。浏览器本地 blob 支持增益试听；未绑定服务器媒体时无法测量 LUFS。file 或未经允许的跨域媒体不会先接管 Web Audio，避免静默失声。

参考：[FFmpeg 滤镜](https://ffmpeg.org/ffmpeg-filters.html#loudnorm)、[EBU R128](https://tech.ebu.ch/publications/r128)、[EBU Tech 3343](https://tech.ebu.ch/docs/tech/tech3343.pdf)、[Web Audio 规范](https://www.w3.org/TR/webaudio-1.0/)。
