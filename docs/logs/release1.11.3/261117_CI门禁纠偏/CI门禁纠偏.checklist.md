# CI 门禁纠偏核对

> 日常合并检查与完整辅助巡检分离；本清单不代表已合并main，不自动勾选人工验收。

## 实现与审查结论
<!-- id: implementation -->
<!-- badge: todo 进行中 -->

目标是撤回PR/main自动完整矩阵及旧门禁的重复执行，保留所选可靠检查的阻塞语义与完整巡检的真实失败；实际完成与审查证据以同目录账本和覆盖撤回核对为准。

## 修复与交付记录
<!-- id: changes -->
<!-- badge: todo 待交付 -->

维护者授权独立分支提交、推送并创建PR，未授权合并、修改远端保护或批量更新其他PR。候选发布后不以创建PR声称全仓main已切换策略。

## 自动化验证
<!-- id: automation -->
<!-- badge: todo 待回填 -->

计划、所选回执及辅助失败隔离通过定向契约和故障注入验证；文档、普通代码、main与定时路径分别核对，实际命令和结果由同目录账本回填。尚未执行的完整巡检、实际预览包和main事件不得由单测冒充通过。

## 维护者核验
<!-- id: manual -->
<!-- badge: todo 待核验 -->

- [ ] **确认候选PR不再自动叠加完整矩阵**
  （操作）查看交付PR最新head的Actions任务和Change acceptance依赖，再对照覆盖撤回核对表。
  （预期）日常结论只依赖所选阻塞检查，没有自动12单元完整矩阵；预览若运行是本次打包工作流改动相关，而非所有代码PR都默认运行。
  <!-- id: candidate-jobs -->

- [ ] **确认辅助失败没有被涂绿或当成全仓通过**
  （操作）查看故障注入结果、巡检/预览摘要和PR评论的跳过、取消、失败示例。
  （预期）辅助失败保留红灯与证据，未运行明确说明；所选阻塞失败或缺报告仍让Change acceptance失败，不声称所有测试通过。
  <!-- id: outcomes -->

- [ ] **合并后核对文档在PR与main都采用轻量路径**
  （操作）维护者批准合并后，在下一次普通工程文档变更的PR与main运行中查看选择计划和实际任务。
  （预期）执行文档及实际消费者检查，不启动无关完整Python、Node、FFmpeg、全部E2E或Windows包；旧run不算新策略验收。
  <!-- id: docs-after-merge -->

- [ ] **确认完整巡检和正式发布能力仍保留**
  （操作）检查每周与手动巡检配置、正式release的触发和依赖；下次获批完整运行时检查各平台报告。
  （预期）巡检仍完整发现双平台集合、漏报告不能绿，正式发布Windows阻断和辅助平台警告政策不变；未实际执行部分保持未验。
  <!-- id: retained-coverage -->
