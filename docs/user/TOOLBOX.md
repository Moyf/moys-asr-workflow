# Launcher 工具箱

工具箱分为「字幕处理」与「媒体工具」。前者处理字幕文字或时间码，后者处理媒体。希望转写后自动执行多个步骤时，使用 [自动处理链](POSTPROCESS_PIPELINE.md)。

## 选择输入与输出

字幕后处理的「处理文件」可用 `.mosp`、旧 `.json` 或 SRT，默认跟随 Launcher 的当前工程/字幕。成功处理生成带操作后缀的新文件，并将新路径填回处理输入；源文件不覆盖。可选择「工程 + SRT」「仅工程」「仅 SRT」。

媒体工具有独立「媒体文件」输入，默认跟随 Launcher，允许手动覆盖；清空后恢复跟随。「文稿匹配」完成后会将新字幕设为当前工程，并加入字幕处理链，便于继续校对；其他媒体操作不会改写该输入链。

## 文稿修正

选择 UTF-8 的 `.txt`、`.md` 或 `.markdown` 文稿，用其文字修正已有字幕。该模式在本地执行，不需要 LLM，也不上传文稿。

已有准确文稿与对应录音、无需先生成转录文本时，点击本页顶部指引，直接前往「媒体工具 → 文稿匹配」。文稿修正处理已有字幕；口播对齐还提供重录候选、试听和人工选 take，区别见 [能力对比](ALIGNMENT_FEATURES.md)。

- 按顺序对齐，比较时忽略大小写、空白和标点；匹配度不足时不写产物。
- 断句与句尾标点共用「⚙️ 设置 → 断句与标点」清单，默认剥除 `，。；,.;`、保留 `？！`；删掉符号即取消它的断句作用，换行始终生效。
- 默认清理成对的 Markdown 标记，只保留可见文字；预览与匹配共用同一结果，可关闭清理。
- 所有启用字幕都有完整 `items` 时，根据字符时间码重新断句；SRT 或时间码不完整的工程保留原有分段时间槽。
- 文字变化后清除不能对应新文字的旧 `items`；禁用字幕保留原样。
- 录音里存在、文稿里没有的完整 ASR 字幕段会保留，不会并进下一句文稿。

结果文件仍使用 `.文稿匹配`（英文 `.match`）后缀。这是把文稿作为文字真源的修正方式，需要保留录音中的改说时可使用下面的 AI 整理。

## 口播整理：以录音为准

进入「AI 处理」，选择「口播整理」。参考文稿可选；没有文稿时直接根据原始转写和上下文判断。补充要求填写在自定义提示词中。「文稿修正」仍是本地的确定性文字对齐工具，不调用 LLM。

模型按完整表达比较重录版本，而非孤立的短字幕：保留独有的方法、数字、条件、否定和承接，清理明确的过程话、作废 take、真重复、假起头和句内磕巴。不能仅凭文字判断音质，也不会按目标删减比例压缩。

模型输出类 Markdown 编辑稿，本地固定脚本转换为 MOSP：

```text
[c001] 原文直接保留
[c002] ~~整段删除的原文~~ %删除：后面有完整重录版本%
[c003] ~~重复起头~~保留的原文
[c004] 原文 %待确认：需要回听原声%
```

每个目标行必须出现一次，整段删除也要明确划删，漏输出不能作为删除。脚本拒绝改写、重排行和无效 ID；切开多字 item 的划删不执行，该行完整保留并标待核查，其他可靠的整理可继续完成。模型不生成时间码。时间范围只取工程中完整 item 的整数毫秒来源。缺少完整字词时间的段保留并标待核查，SRT 通常需先生成字词时间码。

英文 ASR 词项自带的首尾空格不影响对齐，划删完整单词也不要求把其前后分隔空格一起划入；字母、词内空格和标点仍须与原文一致。若同一个词项包含多个单词（例如 `we we`），不能只删其中一个单词：它们没有独立时间码，应保留并标待回听。模型误输出本轮明确标为只读的上下文行时，程序忽略这些行，不采纳其修改；未知 ID、重复目标或真正漏行仍会拒绝。

整理遵循原文语言，不校正英文语法或拼写。模型建议删除的独立犹豫声（如 `Uh`、`Um`、`Hmm`）可通过本地保护校验；`no`、`yeah`、`so`、`like` 等可能表达否定、确认或承接的词不会仅凭词形视为废话。

原文已有 `~~`、百分号或反斜杠格式会在编辑底稿中转义，仍按原文字面保留；只有模型新增的划删才用于整理。数字、比例、否定与限定条件不能因重复折叠而被静默删去，无法安全核验时保留并标待确认。

| 编辑稿 | MOSP 结果 |
| --- | --- |
| 未标记的文字 | 保留原始转写，无需生成逐段「保留原因」。 |
| 整段划删 | 禁用该字幕及其绑定副字幕，删除范围写入可恢复空隙层。 |
| 句内划删 | 只写入 `gap_remove.provenance.sources.ai_cleanup`，保留原始 `segments/items`。 |
| 待确认 | 保留原文，写入 `markers.items[*].review.status=pending` 的待核查区段。 |

「追加 AI 复查」默认关闭；开启后在首次整理之后追加漏清扫描，再通读剩余文稿审计信息覆盖与承接。此设置会记住，工具箱与自动后处理共用。关闭时只执行首次整理，本地词项与信息保护校验仍然执行。开启时首轮没有删除也会扫描；最终审计只能恢复危险删除或标注疑点，不能扩删。每批每个工序的无效响应至多重试一次，任一最终协议失败或写出前取消，不生成部分整理结果。

整理成功时不另存阶段记录；失败或取消时保存独立的 `.ai-cleanup-record.md`（重名自动编号）。记录包含本次已发生阶段的目标 ID、输入底稿、模型回复、重试校验错误和本地决定，错误提示给出记录位置；不新增保存开关。漏清扫描中的已删除段只供参考，不采纳其再次输出的修改；因此该轮目标行数可能少于原始 SRT 条数，行数错误会显示预期数、实际数和缺少或多出的 ID。记录含字幕与可选文稿，分享前请检查内容；记录不保存服务连接配置或 API Key，常见凭据文本会打码。

整理与重新断句允许模型回复带完整的前导思考块、代码围栏或空行；原文中的字面内容不会被当作包装删去。真正的漏行、改写、未知 ID 仍拒绝；整理建议切开词项时保留原行待回听，不执行没有可靠时间来源的剪词。重新断句仅在失败或取消时保存 `.resegment-record.md`，可查看具体断点、原字幕位置、左右文字和原因；流式输出显示实际批次及重试。

出现处理结果后，结果链最前面显示「原始输入」，按原文件类型显示 MOSP / SRT；点击可重新用最初输入处理，继续处理后仍保留该入口。结果链中的 MOSP / JSON / SRT 可以设为下次处理目标；对比 HTML 与整理记录只能查看或打开所在文件夹。

输出新 `.AI整理.mosp` / `.AI整理.srt`（英文 `.ai-cleanup`）。导出 SRT、ASS 和动态字幕时按当前生效的 AI 空隙派生文字，源工程文字保持可恢复；恢复局部空隙后派生文字随之恢复。编辑器原始字幕列表仍用于查看与恢复来源。整段删除同时禁用了字幕，恢复时还需启用该字幕。绑定副字幕的句内文字不会自动翻译或改写。

提示词要求检查句内重复起头，按完整重录表达优先保留后面完整、连贯的一遍，不能只按单行去重。脚本允许清理可逐字核验的相邻重复限定词；数字与否定仍受保护。相邻两组的每句能完整对应、且模型已删除旧版开头并保留新版开头时，本地统一保留新版整组，避免混接旧版收尾；不同内容或待确认项不套用此规则。

在「标记与区段」检查待核查项，并试听删除接口。删除 `[AI]` 注释不会恢复字幕或空隙决定。LLM 收到临时 ID、字幕、完整词项和可选参考文稿文字，不收到音频、路径或时间码；请求次数增加，费用以供应商账单为准。

### 生成处理前后对比结果

「AI 处理」中勾选此项后，同时生成离线 HTML；口播整理、校对、翻译、断句和自定义任务均可使用。结果列表中的「对比 HTML」可打开页面，展示连续文稿、原文与结果、划删及待核查原因，支持筛选和搜索。页面是生成时的快照，之后编辑工程不会更新页面。合并/拆分字幕的逐段对应按时间范围展示，连续文稿用于通读最终结果。

翻译核对页支持单语、补译回填与双语合一产物。可直接修改译文、筛选搜索并下载「核对后 MOSP」，再进入 MAWE 继续编辑；原文不可编辑，原时间与结果工程中的其他轨道、绑定、标记和元数据保持。修改过的译文清除失配的词级时间，不生成虚假的时间码。空译文、重复或未知 ID、损坏快照会阻止导出。恢复按钮回到生成时译文；页面刷新不会保存手动修改，请先下载。双语合一的换行由源文与译文结构重建，不猜测哪一行是译文。

校对、翻译与自定义任务可附带稀疏备注：普通说明为 `[AI] 注：…`，疑点为 `[AI] 待核查：…` 并设为待核查区段。备注由源字幕定位，不影响字幕、空隙或剪辑；模型没有备注时不强制生成逐句解释。重跑更新本任务未被人工修改的备注，保留用户改过或已确认的项，其他任务和用户标记不变。断句不可安全满足字数限制或局部网络失败，也在对应源区段留下待核查提醒。无法可靠定位的全局信息仍在运行结果中。

未勾选不生成 HTML。自动计划的口播整理、校对、断句与翻译共用并保存此开关；旧计划任一 AI 步骤启用了对比页，载入时都会恢复勾选，即使不保留中间文件，对比页仍保留在输出目录，完成日志会列出最终路径；此时「打开后处理文件夹」打开最终输出目录。旧版「文稿匹配 + AI 整理」计划会迁移成独立的口播整理步骤，供应商旧记忆也迁移，已有的新选择优先；单文件限制保留。

也可由两个工程快照生成页面：

```powershell
python scripts/build_ai_comparison.py before.mosp after.mosp --output comparison.html
```

## 固定替换

每行填写 `原文 => 新文`，按顺序执行；可在替换后转简体或转繁体。该功能在本地运行，不改变分段时间；文字变化的段清除旧逐词时间码。

## AI 校对、翻译与断句

先在 Launcher 的 LLM 后处理配置保存供应商、地址、模型与 Key，并测试连接。工具支持校对、重新断句、翻译成中文/英文和自定义文字任务。

预设任务说明只读，自定义提示词始终可编辑；切换任务不清空自定义文字。普通文字任务返回经过校验的文字或 ID 分组；重新断句只标断点，原文与时间由本地程序重建。完整规则见 [LLM 协议](../engineering/LLM_POSTPROCESS_PROTOCOL.md)。

### 重新断句与最大字数

模型只返回断点 ID 属于正常输出；程序按这些位置重建字幕。协议不合格会重试一次，实时输出按实际字幕批次标注，例如「第 1 批 · 重试 1」，重试不代表开始处理下一批。

断点校验失败时，提示包含断点 ID、原字幕序号、左右原文片段和具体原因（数字与单位、比例或连续英文字母等）。界面最多列出五处，其余保存在本地 `.resegment-record.md` 阶段记录中。每次请求前后均更新记录，包含输入、模型回复、各次校验及本地重建结果；成功或失败均提供记录路径，不覆盖原工程。记录含字幕与补充要求，分享前请检查。自动后处理成功后会在原字幕目录保留记录，即使关闭了「保留中间产物」。

选择「重新断句」，可填写「每条字幕最大字数」，例如 18；留空按自然语义断句。计数按中文、英文、标点逐字符计算，空白不计，限制每条字幕的总字数而非排版后的每行字数。

模型先通读前后文，按完整意群合并过碎短句、拆分过长表达；脚本校验断点并对超长结果补拆，原文、标点和词级时间保持来源。完整词项、数字单位或缺时间码的整段本身超过上限时保留并提示，可先生成词级时间再重新断句。部分段缺时间码不会让其他段整体降级。已有禁用、说话人变化与长停顿作为处理边界。

口播整理后再断句会保留已有局部删减及其恢复能力：字幕的原文和全部词项仍在工程中，导出继续隐藏当前生效的删减内容；人工恢复对应空隙后，文字也会恢复。已有可靠删减无法保持词项绑定时会中止写出，保留输入工程。

当前副字幕绑定要求一对一。已有绑定的主字幕会保持原 ID、文字、时间和词项，并成为断句边界；其他未绑定字幕正常处理，绑定段超过字数限制会提示。建议先重新断句，再翻译或创建副字幕绑定；已有工程需调整这类段时，先解除对应绑定。

设置字数上限时，脚本会对连接词悬尾、孤立引导语等相邻断点局部重平衡，优先保留模型的自然边界，数字与帧、像素等单位不拆开。这些语义规则是软偏好，严格上限仍可能拆开主谓或动宾；如果结果过碎，可放宽上限或留空，并生成对比页检查。完整短回答不会仅因字数少而被强行合并。

上限会保存到自动处理计划。勾选「生成处理前后对比结果」可查看字幕边界变化与连续原文，结果仍需人工确认阅读节奏；网络失败保留的原段可能超过上限，会明确提示。

| 翻译输出 | 结果 |
| --- | --- |
| 普通翻译 | MOSP 保留原文主轨与译文副轨；SRT 输出译文。 |
| 双语合一 | MOSP 保留原文主轨与译文副轨；SRT 将原文与译文放入同一个字幕段，按设置上下排列。 |
| 回填 | 将需翻译的句子替换为译文，其他句子保留。 |

「跳过已是目标语言的字幕」默认开启，工具箱与自动处理共用并记住设置；遇到误判可关闭，将所有非空字幕发送给模型。此开关不改变回填的 50% 保护。

翻译成中文时，只有识别结果或用户语言提示明确为中文、且全文没有假名或韩文的工程，才按单句汉字占比跳过已有中文（无其他文字脚本，汉字占汉字与拉丁字母总量至少 70%）。日文/韩文工程、仅从文字推断语言或缺少语言来源的工程、SRT 中含文字的字幕均发送给模型，避免把日文纯汉字句误认为中文；因此语言不明的中文 SRT 也会发送。翻译成英文时不把所有拉丁字母文本当成英语跳过，以免漏翻其他语言。

普通翻译与双语合一均只翻译主轨原文，保留主轨文字、字词时间码和样式；完整校验后覆盖固定副轨，没有副轨才创建，不追加新的译文轨。新译文不生成虚假的字词时间码，与原文相同的译句不重复添加到副轨。失败或取消保留原有副轨，已有副轨的 MOSP 允许从主轨重新翻译。回填中未翻译的句子保留原数据；超过半数替换时跳过回填并保留双轨工程与独立译文 SRT。旧单轨工程和 SRT 继续按文件名标记防止明显重复翻译。

重新断句在完整字词时间码输入上可使用 item-aware 协议，保留字词时间码；普通文字变化会清除失配的 `items`。无效响应的补救、部分结果和失败行为按协议区分，不保证每种任务都能输出部分结果。

长任务中，校对与自定义任务的单批网络中断、超时或 HTTP 408 / 429 / 5xx 可保留该批原字幕并继续。翻译必须所有批次成功且一对一校验完整才写出结果，失败或取消不替换原副轨；详情见 [LLM 协议](../engineering/LLM_POSTPROCESS_PROTOCOL.md)。

## 生成时间码

各功能的输入、文字真源、时间处理和重录能力见 [文稿与时间码工具对比](ALIGNMENT_FEATURES.md)。

为 SRT 或缺少字词时间码的工程选择原始媒体，再使用 Qwen3-ForcedAligner 或 FireRedASR2-CTC：

- 「补充缺失」只处理缺少完整 `items` 的段。
- 「重新生成」替换原来的字词时间码。
- 工程有有效媒体引用时可直接使用；SRT 必须指定媒体。

结果写入新文件；失败段保留原时间并报告。环境、缓存和对齐器准备见 [本地 ASR](LOCAL_ASR.md)。

## 脏录音：先审查念读，再生成文稿字幕

在 Launcher 工具箱的「口播对齐」选择输入方式：已有原始 ASR 工程，或「从录音开始：先 ASR 再审查」。后者使用主界面所选 ASR 提供者、模型、音轨和输出位置，保存原始 ASR MOSP 与 SRT；此步骤不执行文稿替换、AI 自动后处理或测试时长截断。准备期间可停止，失败后可重试。

选择准确的 UTF-8 文稿，每个非空行对应最终一条字幕。打开口播审查页，启用「文稿字幕生成」，确认输入是未用文稿替换文字的原始 ASR 结果。沿用下方波形、候选和试听选择；最终文稿工程不能再次当作独立 ASR 证据。

「应用保守推荐」只推荐独立 ASR 文字逐字对应的唯一完整候选。多次念读需试听选择；可主动开启「局部重录组内优先最后完整念读」。数字、否定、术语等差异需试听后确认具体候选，换候选后原确认失效。半句或漏读不会因手动启用而补成完整文稿；匹配分数不能证明声音念对或表现最好。

源字幕过粗、同一段包含多行文稿时，可先「补充 ASR 字词码」；补码保持识别文字与原句界，成功后用新工程重新打开审查。任一源段失败、取消或输入变化，不发布部分补码工程。补码与最终生成使用本地 Qwen ForcedAligner，环境和模型准备见 [本地 ASR](LOCAL_ASR.md)。源码运行可复用已具备模型依赖的当前 Python；桌面发布包使用已安装的本地模型运行时。

确认就绪后生成新 MOSP、SRT 和 report.json，放在 ASR 工程目录下独立的 `.script-reviewed-随机后缀` 结果目录；原 ASR 和录音保持原样。保留的额外内容仍进入结果。内部重录与手动静音切除按实际保留片段处理，字词时间回到原录音时间轴；单行保留声音最多300秒，跨拼接点的词项无法可靠映射时会要求调整选择。文稿行跨说话人、与其他保留Extra发生字幕重叠时，先拆分文稿或改选连续完整念读。

同一浏览器和同一来源下，刷新会恢复候选操作、确认和手动静音切除；运行中刷新可继续查看与停止，失败或取消后可重试。更改源工程、文稿或对应媒体会使旧审查失效，需重新打开。停止口播服务将取消其模型任务；恢复跨浏览器、清除本机存储或重新启动ASR准备任务不在本机恢复保证内。

最后用 MAWE 打开结果试听、Seek、保存再重开，并检查额外内容和删除接口。此功能是推荐与确认工作流，真实 ASR 和对齐模型仍可能出错，不能省略听审。

## OCR 去重

视频画面已烧录字幕时，可检测重复字幕并将命中段禁用，避免再次叠加。先安装独立 OCR 运行环境，再选择 CPU RapidOCR tiny 或 small、画面范围及相似度阈值。

默认完整画面，长视频可限制到字幕区域。OCR 不改文字和时间；可额外生成逐段 CSV 报告。纯音频或无媒体引用的 SRT 需要另选视频。完整说明见 [OCR 字幕去重](OCR_SUBTITLE_DEDUP.md)。

## 媒体工具

### 文稿匹配

入口位于「口播对齐」前。选择上方媒体文件与准确文稿，不需要已有 MOSP / SRT，也无需先 ASR；每个非空行生成一条字幕，同时输出新 MOSP 与 SRT。短录音整段对齐，长录音使用静音或人工锚点，仅使用 Qwen3-ForcedAligner。

可先检查输入与分块，无需下载模型；检查不改变当前工程或写出字幕。可以指定音轨序号与输出目录，结果列出策略、行数与块数。录音有多次重录、重复和明显口误时，使用「口播对齐」审查选 take，再生成字幕；直接文稿对齐不能判断念读正确与否。详见 [文稿驱动对齐](SCRIPT_DRIVEN_ALIGNMENT.md)。

### 生成波形

可只生成媒体工程和缓存，也可生成后直接打开编辑器。频谱另行选择；它比普通波形耗时。生成波形只为定位和显示，不执行 ASR。

### 烧录字幕

选择视频与 `.srt`、`.ass`、`.ssa`、`.mosp` 或 `.json`，生成新的 H.264 MP4；输入视频不覆盖，重名结果加后缀，任务可停止。

SRT 使用样式库中的 SRT 渲染样式；ASS / SSA 保留文件内嵌样式；`.mosp` / `.json` 工程会临时导出为工程自身基础样式的 ASS 再烧录：字体、字号、颜色、颜色字幕和叠加轨跟随工程预览设置，PlayRes 取视频实际分辨率（绿幕取所选画布尺寸），与编辑器预览同一约定。强调语法、字级动画、逐句定位、多重字幕与说话人前缀属于编辑器 ASS 模式的完整导出能力，工具箱烧录不含这些效果；需要完整效果时先在编辑器导出 ASS，再选择导出的 `.ass` 文件。编码器可自动、CPU 或显式硬件编码器；CRF、预设和音频码率可保存默认值。默认 CRF 21、预设 medium、音频 192k。


「生成绿幕视频」默认无需视频源：使用纯绿色画布输出 MP4，结束于最后字幕之后半秒，30 fps。勾选后可选择视频尺寸：1080P（1920×1080）/ 2K（2560×1440）/ 4K（3840×2160），默认 4K。需要音轨时再勾选「附带音轨」，并选择包含音轨的视频或音频文件；输出长度仍由字幕决定，较短的音轨不会截短绿幕画布，较长的音轨会在绿幕结束时截断。SRT 样式按所选尺寸换算，与编辑器预览一致；ASS / SSA 沿用自身画布坐标，随输出尺寸等比缩放。没有有效字幕结束时间时不生成结果。

macOS 烧录需要支持 libass 的 FFmpeg；安装了 Homebrew `ffmpeg-full` 时程序优先尝试它，显式 `FFMPEG_PATH` 仍优先。

### 提取音频

FFprobe 列出音轨序号、语言、标题、编码和声道信息。选择音轨后输出新的 AAC `.m4a`，不修改原媒体。

### FFconcat 媒体重组

在编辑器中使用「去空隙导出 → 重组后视频」，按当前工程绑定的源媒体和保留区间生成新媒体。视频重组采用流复制，首尾扩展到共同安全关键帧并合并交叠区间，短空隙可能保留；进度面板显示扩展增加的总保留时长。完成后用「保存匹配字幕（SRT）」保存本次实际视频时间线对应的字幕，需试听核对。音频工程显示「重组后音频」，使用当前选定音轨解码后按样本精确裁切和拼接，导出 WAV，保持源采样率、声道及采样精度；音频切点不受视频关键帧或压缩音频包边界限制。原工程和现有精确去空隙 SRT 不会自动改写。

视频工程也可使用「去空隙导出 → 重组后烧录视频」：按保留区间重新编码并烧录当前 ASS 字幕，输出 MP4。解码后按保留区间裁剪，视频精确到帧、音频精确到采样，音画与去空隙字幕共用收缩时间轴。编码参数与「烧录字幕」相同并全部取默认值；需要自定义编码器或画质时，改用工具箱对重组结果单独烧录。完整源视频（不去空隙）的烧录入口是编辑器工具栏的「烧录视频」按钮（「去空隙导出」左侧，仅在 ASS 字幕模式且已绑定视频工程时显示）。

如果要交给外部 FFmpeg 工具，可从「去空隙导出」单独导出 FFconcat 文件，并与配套的去空隙字幕一起使用。
