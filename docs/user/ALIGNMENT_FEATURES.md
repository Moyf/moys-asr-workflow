# 文稿、时间码与口播工具：当前差异和演进建议

本文按当前实现比较功能。后半部分是产品建议，不代表这些入口已经合并。

## 当前能力对比

| 能力 | 输入 / 前提 | 文字以谁为准 | 对时间与结构做什么 | 重读 / 改说处理 | 模型与产物 |
| --- | --- | --- | --- | --- | --- |
| ASR 转写 | 媒体；不要求文稿 | 识别到的录音内容，仍需校对 | 从无到有生成字幕、句级或字词级时间码 | 尽量记录说了什么，不替用户选 take | 选定 ASR；SRT + MOSP |
| 文稿驱动对齐（本 PR） | 准确文稿 + 对应录音；不要求已有工程 | 文稿原文；每个非空行一条字幕，保留标点 | 对录音做声学定位，新建 items 与句界；≤300 秒单发，长录音需静音 / 人工锚点 | 不能判断实际是否念对；可能忽略口误、额外内容与重读，不自动选优 | 本地 Qwen ForcedAligner；新 MOSP + SRT；无需 ASR / LLM |
| 补充 / 重生时间码 | 已有 SRT / MOSP + 媒体；句级范围已存在 | 已有字幕文字 | 在现有字幕范围内补充 / 替换 items；保留原结构，失败段保留原时间并报告；既有 Qwen 75 秒分块策略不变 | 不校正文字，不选择重录，不建立录音内容证据 | Qwen / FireRed；Launcher 写新工程，SRT 无法保存字词字段 |
| 普通文稿匹配 | 已有字幕 / 工程 + 文稿；匹配度足够 | 文稿；源录音中独有的完整字幕段仍保留 | 本地文本序列匹配；完整 items 可支持重断句，否则保留时间槽；失配的旧 items 清除 | 不是重录选优工具；按顺序匹配，不能确认录音真正说了什么 | 无模型；新匹配工程 / SRT；沿用断句与标点设置、可清理 Markdown |
| 口播对齐 Server | ASR 工程 + 文稿；媒体用于试听 | 源 ASR 字幕；文稿用于找候选 take | 找完整 / 不完整 / 重复 / extra 候选，用户试听选择，保留源时间或按 items 拆分；写禁用与 gap-remove | 明确提供 take 选择、手动启用 / 禁用；Extra 默认保留；匹配只是建议 | 本地文本算法，无新增识别 / LLM；新 `.aligned.mosp` |
| AI 整理 | ASR 字幕 / 工程 + 文稿 + 配置好的 LLM | 录音侧 ASR 文本；文稿仅作证据 | 建议保留 / 可逆移除 / 待复核，保留时间码，写区段标记；有候选删除时通读复查 | 处理改说、重录和独有信息，但依赖 ASR 证据；需检查复核项 | LLM 收到文字，不收到音频；新 AI 整理工程 / SRT |

本 PR 的提速来源是省掉识别与其他文本处理步骤，不能凭流程少一步就承诺固定倍数。Qwen 的文本预处理与时间码输出遵循 [上游实现](https://github.com/QwenLM/Qwen3-ASR/blob/main/qwen_asr/inference/qwen3_forced_aligner.py)；返回的文字来自输入文稿，不能把“文字全覆盖”当成声学内容校验。

## 怎么选择

- 一次顺序念完、文稿准确：文稿驱动对齐 → MAWE 听审 → 导出。
- 没有准确文稿、临场改说很多：ASR → 校对 / AI 整理 → MAWE。
- 字幕文字和句界已准确，缺 items：补充时间码；已有 items 需要重新定位时才选“重生”。
- 录音基本一致，只需把 ASR 错字改回原稿：普通文稿匹配；文稿不是实际最终说法时不要强行替换。
- 有多次重录，需要人工选 take：ASR → 口播对齐试听选优 → MAWE；AI 整理可提供另一路可逆建议，不把两套删除结果无检查地连续叠加。

不要用本 PR 的生成工程反过来证明录音念对，再交给口播对齐“发现口误”：其文字本来就是文稿。需要这类证据时，应另做 ASR，且由用户明确选择，不能在免 ASR 路线失败时静默切换为识别。

## 本次已经完善

- Unicode 组合字符按 NFC 输入模型，通过字符映射保留原文；不将编码差异误报为录音不一致。
- 单发与人工锚点策略不依赖静音阈值；空 / 全零音轨单独拒绝，低音量不等于空波形。
- CLI `--alignment-check` 和 Launcher「检查输入与分块」不加载模型、不写字幕，提前检查非空行、音轨、时长和锚点，并返回计划；生成时重新检查，不能依赖陈旧的预览。
- Launcher 可指定音轨序号和输出目录；生成结果显示策略、行数、块数、时长与音轨。静音参数用途明确限定为长录音自动分块。
- 文稿生成工程写入可选的 `preserve_punctuation`，MAWE 启动与保存重开保持原文标点。没有该字段的历史工程行为不变；用户主动编辑或文本处理仍有效。

## 建议的最终形态

用户入口收敛为三个任务，能力在内部复用。

| 任务入口 | 用户先决定什么 | 内部路线 | 结果如何审查 |
| --- | --- | --- | --- |
| 生成字幕 | 有准确文稿吗？录音是否顺序念稿？ | 没有文稿走 ASR；准确念稿走文稿声学对齐；不确定 / 多次重录明确推荐 ASR | 新工程；显示采用路线与时间码来源，定位异常块 |
| 修正已有字幕 | 改文字，还是修时间？文字以文稿还是录音为准？ | 改文字：普通匹配 / 校对；修时间：补码 / 重生；两步可以显式组合 | 新文件与文字 / 时间变化预览；说明失效 items 和失败保留范围 |
| 整理口播 | 哪些 take 保留？哪些额外信息不能删？ | 文本匹配找候选，LLM 可选地给建议；用户试听确认 | MAWE 内同一条原始时间轴上的候选 / Extra / 待复核侧栏，可撤销的禁用与空隙 |

口播对齐与 AI 整理最终应共享一套“建议 → 试听 / 比较 → 确认”的工作区；算法是不同建议来源，用户只管理一套决定。普通匹配保留快速确定性工具的定位；不能改名成“智能整理”后悄悄加入 LLM。补码与新建字幕可以共享模型和音频准备，但不能共享错误的输入假设、分块策略或失败政策。

技术上逐步复用输入检查、音轨读取、模型运行、分块进度、取消、失败块重试和结果报告。保留 `segments` 作为字幕真源、items 作为时间精度、waveform 作为可重建缓存；来源记录用于解释和复核，不创建另一份互相漂移的字幕真源。

下一阶段优先级：先完成真实 Qwen 短 / 长素材与脏录音验收，再做锚点的波形可视化编辑、逐块进度 / 取消 / 重试，最后将口播对齐工作区纳入 MAWE。无需为了入口统一立即重写已有算法或扩大成 ASR 平台。
