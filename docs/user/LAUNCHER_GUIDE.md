# Launcher 指南

Launcher 负责选择媒体、转写、批量任务和工具箱。第一次安装见 [工作流](WORKFLOW.md)，服务商字段见 [PROVIDERS](PROVIDERS.md)。

## 识别设置

先选择识别方式、供应商与模型，再设置语言、断句、热词或上下文。高级选项随模型能力显示，不支持的选项不能作为所有供应商的通用能力。

- 默认云端模型为 Qwen-Audio 3.0；3.1、Qwen3-ASR 和 Fun-ASR 可在模型菜单切换。
- Qwen-Audio 3.1 可选保留方言表达；其他模型不支持该开关。
- 已知语种时可提供语言提示；混合语言可留空让模型判断。
- 说话人标签是本段音频中的匿名编号。开启颜色后会写入一次性颜色快照，之后仍可编辑。
- 快速测试时长支持 `20s`、`2m` 等值；完整转写前需取消限制。
- 字幕断句使用字符型或单词型规则；CLI 对应参数见 [CLI](CLI.md)。

字符型「单句上限」使用本地 jieba 分词，优先保留标点和完整词边界，并在相邻字幕间轻微调整断点，减少「没有｜用」「继续｜编辑」及孤立短尾。例如上限为 5 时，「今天天气真好啊」可拆成「今天天气｜真好啊」。常见小数、比例、版本号、数字与单位以及连续英文词受到保护，不把 `1.25倍`、`16:9`、`1.9.0` 或 `1999元` 拆开；标点预切也跳过这些表达内部的分隔符。

断点必须落在原有字词时间码（item）之间。没有合适的词边界时，仍只在完整 item 之间回退；单个 item 或因数字 / 英文词保护相连的一组 item 本身超过上限时，会完整保留并在日志中提示超限，不编造内部时间码。长停顿与换行仍优先断开。短尾与连接语规则是软偏好，不能保证每个意群都完整，尤其是上限较小或 item 较粗时，仍需试听。这是转写后的本地切分，不需要调用 AI；已有字幕的 AI「重新断句」仍从工具箱使用。

云端 Key、地域、模型和地址可以保存到本机 `.env`；识别预设不保存密钥。界面语言首次跟随系统，之后可在通用设置中切换。

「⚙️ 设置 → 断句与标点」统一控制转写与文稿匹配。默认断句符号为 `，。？！；,.;`，末尾保留 `？！`，其余断句符号从句尾剥除；删除某个符号即取消它的断句作用，文稿换行始终生效。旧设置首次加载时迁移，已有显式选择继续保留。

超长字幕的“弱标点”只是优先选择断点，也读取左侧同一份清单，不再内置另一组顿号、冒号或破折号。默认保留「这个、那个」这样的列举；如需在顿号后断句，将 `、` 加入左侧，右侧未保留它时句尾顿号也会移除。新默认值补充英文分号 `;`，与中文 `；` 对齐；顿号、冒号 `：:` 和破折号 `—–` 仍由用户按需添加，不自动加入已有的显式配置。英文仍沿用按词数与句末标点识别完整句子的策略。

## 选择声音轨道

含多条音轨的视频会在媒体路径下方显示「声音轨道」。默认选择 FFprobe 标记的默认轨，没有默认标记时选第一条；转写、波形和频谱使用同一条轨道，选择会保存到工程。

![多音轨选择示意：手动选择人声音轨后，转写、波形和频谱使用同一条音轨](../assets/guides/audio-track.svg)

*示意图，非界面截图：音轨名称仅作示例，程序不会按「人声」名称自动选轨。请根据录制方式确认所需轨道。*

默认轨缓存没有后缀，其他轨使用 `.track-N`。所选轨缓存缺失时优先重建，重建失败才临时回退到默认轨缓存。纯音频和单音轨视频不显示此控件；探测失败时沿用第一条轨道。批量任务对每个文件独立探测默认轨，不复用单文件页面的选择。

## ASR 识别预设

高级选项旁的「预设管理」可以搜索、查看和加载预设。单击列表项只看资料，点击「加载预设」才应用；加载不会切换供应商、模型或开始识别。

| 操作 | 结果 |
| --- | --- |
| 另存为新预设 | 保存当前识别表单。 |
| 仅保存名称/描述 | 只改选中预设的资料。 |
| 更新预设 | 经确认，用当前表单覆盖选中预设。 |
| 复制预设 | 生成副本，可继续改名。 |
| 删除预设 | 经确认移入系统回收站。 |

当前表单偏离已载入预设时，会出现「更新预设」入口。预设包含高级识别参数、快速测试与断句设置，不包含密钥、媒体、输出位置或后处理链。Qwen 上下文、OpenAI Prompt 和 Soniox 背景文本共用同一份提示词。热词文件仅保存路径，文件缺失会提示。

每个预设是一个 `.json` 文件，名称取自文件名，描述可为空。默认目录为 MAW 用户数据目录下的 `asr-presets/`；可在通用设置选择已有可写目录，并选择是否迁移旧文件。损坏或不支持的预设会标记不可用。

## 批量转写

切换到「批量」，添加或拖入多个媒体，再点击「开始全部」。重复路径会忽略，任务按顺序执行，同一时间只转写一个文件。

- 整批共用当前模型、语言、热词和自动处理设置，不支持逐文件覆盖。
- 单个文件预检、转写或后处理失败后，其余文件继续。
- 「停止全部」取消当前及未开始任务；已完成结果保留。
- 每个文件生成自己的 SRT / MOSP；命名冲突自动加后缀。完成条目可以打开工程或文件夹。
- 每批在首个有效媒体的输出子目录记录 `maw-batch-manifest.json`。它是结果清单，不是断点续跑入口。
- 当前批量模式跳过文稿匹配及其 AI 整理模式，避免把同一份文稿用于多个录音；不修改已保存的单文件设置。

其他自动处理步骤按 [自动处理指南](POSTPROCESS_PIPELINE.md) 执行。

## 输出目录与命名

通用设置中的「文件输出」控制 Launcher 产物：

| 设置 | 默认 | 行为 |
| --- | --- | --- |
| 将所有输出文件放入子文件夹 | 开启 | SRT / MOSP 写入媒体旁 `_maw`；关闭后在媒体旁。 |
| 每个视频单独创建子文件夹 | 关闭 | 开启后使用 `<媒体名>_maw`。 |
| 在输出文件名中附加模型名称 | 关闭 | 开启后附加供应商或模型段。 |

波形 `.mopeaks` / `.quapeaks` 与视频缩略图 `.mothumbs` 跟随输出子文件夹设置；读取时也查找媒体旁和旧输出位置。REAPER 原生 `.ReaPeaks` 始终在媒体旁。旧 `*.waveform.json` 不再读取，其他已支持的缓存位置不会因切换设置自动迁移。

自动处理中间产物、调试文件、浏览器转换缓存和批量清单使用辅助目录。常见布局为：

```text
媒体目录/
├── clip.mp4
└── _maw/                  # 或 clip_maw/
    ├── clip.srt
    ├── clip.mosp
    ├── clip.mp4.mopeaks   # 按需生成
    ├── clip.mp4.mothumbs  # 视频基础画面缓存
    ├── 后处理/            # 英文界面：postprocess/
    └── 调试/              # 英文界面：debug/
```

图形设置不等同于公开 CLI 的默认命名；脚本要稳定定位文件时，显式指定输出路径，见 [CLI](CLI.md)。

工程的媒体路径以 `.mosp` 所在目录为基准：上述 `clip.mosp` 记录 `../clip.mp4`。保持内部目录结构一起移动媒体和 `_maw` 后，仍可直接打开；跨盘无法使用相对路径时回退绝对路径。旧工程只写了文件名时，服务器还会在 `_maw` / `<媒体名>_maw` 的父目录尝试原引用的完整文件名，不递归搜索其他目录。

「编辑器」卡片的工程文件输入框下方会列出本机最近打开的工程（最多 10 条，与编辑器右上角「最近工程」共用同一份记录），点击即可填入路径并自动检查关联媒体；文件已移动或删除的条目会标「已失效」，仍可点击尝试。列表在打开启动器、编辑器加载完成和返回启动器时刷新。

### 修复工程媒体关联

在 Launcher「编辑器」选择工程，找不到媒体时手动选择原媒体。默认勾选「记住关联，更新工程文件」：工程加载成功后只更新原工程的媒体路径，并保留原文件为 `.mosp.bak`（旧 JSON 工程为 `.json.bak`），无需进入编辑器补按保存。写回失败会在编辑器显示错误；只启动监听不代表工程已加载或关联已记住。取消勾选则只在本次打开时使用，不自动改写磁盘工程；之后在编辑器主动保存仍会写入关联。

若该端口已有其他 Launcher 或独立启动的编辑器实例，所选工程和手动指定的媒体都不会被忽略：Launcher 会提示先关闭旧实例或更换端口，再打开所选工程。未选择工程时仍可打开端口上已有的编辑器。仅打开工程而未手动指定媒体，不会自动写回磁盘；旧路径兜底结果在下次保存时修正。

服务器已知保存位置时重新计算相对路径。浏览器「另存为」或下载不提供目标目录，服务器已知的源媒体会改用绝对路径，避免沿用错误的相对目录；若媒体本身也是通过浏览器选取的文件，则无法获知其完整本地路径，之后仍可能需要手动选择媒体。

## 波形、日志与通知

波形由编辑器按需读取或生成；提前生成波形会额外扫描媒体，频谱是可选的耗时步骤。缓存失败不会让已经生成的字幕失效。

视频在正常转写的媒体缓存阶段生成两级画面缓存：**关键帧地标档**总是生成——只解码各关键帧，秒级即可覆盖全片，每关键帧一格（密度即关键帧密度，长视频远高于旧固定档）；「其他」区的「生成高精度画面预览图」开关（**默认关闭**）在此之上额外解码每个显示网格点的精确画面，勾选后转写耗时随素材分辨率与帧率增加，未勾选时编辑器画面带默认以关键帧标记显示、铺满模式下可按需补帧。缓存命中时直接复用；生成期间在既有日志中报告进度；同源播放或可见画面优先时报告暂停和继续。取消后保留已经完成的可重建结果，再次运行时继续补缺。来源始终是原始视频，选择音轨不重建同一视频的画面，临时音频清理后缓存仍可使用。

基础文件是 `<完整媒体名>.mothumbs`，图片不写入 `.mosp`。编辑器需要更密的可见区画面时，另存补帧缓存，不反复改写整个基础文件；直接打开旧工程且没有基础文件时，也只补当前可见区。媒体目录不可写时退到应用缓存，仍不可持久化时使用本次会话缓存；失败会提示，但不阻止字幕和工程保存。

缓存损坏、版本变化或源文件替换会自动失效。如需重建，可将相应 `.mothumbs` 移入回收站，再运行 Launcher 媒体缓存阶段；兼容的补帧仍可复用。画面带显示入口见[编辑器指南](EDITOR_GUIDE.md#视频缩略图导航)。

日志显示起止时间、耗时和实时率（RTF = 转写耗时 ÷ 媒体时长，越小越快）。阿里云费用估算使用程序内参考值，不能代替账单；服务商现价见 [PROVIDERS](PROVIDERS.md)。

完成通知默认关闭。开启后，单文件完成/失败和整批结束会触发系统通知；手动停止批量任务不算完成。

处理已有字幕或媒体请打开 [工具箱](TOOLBOX.md)；希望转写后自动串接处理，请配置 [自动处理链](POSTPROCESS_PIPELINE.md)。
