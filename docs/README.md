## 文档约定

文档与所在分支的实现及支持范围配套。按本次变更维护相关内容；现有说明准确时，保留原状即可。

### 内容放在哪里

以下路径相对 `docs/`，临时区位于仓库根目录。

| 位置 | 内容与维护方式 |
| --- | --- |
| `user/` | 用户操作、功能说明与常见问题。随行为变化更新，维护者在相关变更或发布时回看受影响部分。 |
| `engineering/` | 当前架构、契约和开发方法。优先更新已有说明。 |
| `plans/` | 共享目标、方案取舍、进展与验收。已有议题或计划足够时，直接沿用。 |
| `releases/` | 从 CHANGELOG 生成的版本更新正文与发布管线说明。人工只改 CL，再生成对应版本文件。 |
| `logs/release<version>/<YYMMDD>_<主题>/` | 该版本之后的开发日志。按根规则使用六位日期与可读主题归组；时间和改动沿 Git 历史追溯。已有历史目录保留，不批量迁移。 |
| 仓库根 `.artifacts/<task-id>/` | 本地原始输出与临时预览，由 Git 忽略。 |

同一读者、主题和支持范围维护一份明确的现行说明。适用范围写在正文，人工回看状态以维护者确认结果为准。源码、配置、测试夹具与必要持久证据按项目用途入库。共用资源保留在 `assets/`；`archived/` 用于维护者选定的历史资料。

### 入口与参考

`README.md` 负责阅读分流；`INDEX.md` 用稳定主题锚点映射现行正文；`logs/INDEX.md` 登记保留日志；`logs/CURRENT.md` 记录当前相关参考、适用范围和未决事项。正文负责具体内容，计划负责进展。

新增独立指南、工程说明或计划必须登记到 `INDEX.md`，缺失登记仍使检查失败。开发日志放入 `logs/INDEX.md` 提示的当前 `release<version>/` 目录；日志索引漏登记只提示，不阻塞。文件名优先可读主题（如 `字幕导出问题排查.md`）。日志按版本整理不要求移动其他文档、图片、数据或脚本；日志移动后修正受影响的链接。本机工作范围、个人待办和原始输出留在本地临时区，不进入共享日志。通用的现行说明引用走主题入口；精确章节、历史证据、图片和程序输入使用直接目标。正文移动时更新映射并保持主题 ID 稳定。

官网已公开的页面 URL 与主题 ID 同样保持稳定。归档原文记录当时状态，当前正文改名不回写归档内容。

CURRENT 按具体版本或代码范围描述参考价值。有新证据时更新相关条目，结论进入现行说明后收束对应待办。已知正文位置时可直接阅读，历史资料按追溯需要查阅。

### 更新与退役

现行说明随实现更新；暂待补齐的内容写明差异和承接事项。仍受支持的旧版指南继续提供入口。完成计划与日志按直接查阅价值选择保留。

退役时处理当前需求、独有知识与消费者，再按贡献流程删除当前副本。重要历史保留原文或共享提交中的固定入口；未提交内容先明确保存方式。已对外使用的稳定入口保留简短退役说明。

### 提交与验证

同步本次变更涉及的索引、入链、出链、资源和生成器输入。在仓库根目录运行标准库检查与其回归：

```sh
python scripts/check_docs.py
python scripts/run_tests.py tests/test_docs_check.py
```

Agent 与 CI 使用 `python scripts/run_check.py --timeout 180 --` 包装上述命令，按根规则保存有界摘要与原始日志。

检查默认只读，覆盖 Git 已跟踪及未忽略的新文件，验证当前入口、关键文档登记、内部链接/锚点/图片、官网源文档、已知消费者与临时区隔离；日志未登记输出 `WARNING`，包括 `--strict` 下也不单独造成失败。`scripts/docs-link-exceptions.json` 只登记迁移基线中旧 README 的历史断链；新断链会失败。使用 `--strict` 可复核全部仍存在的历史断链，严格模式下它们也导致失败。结构检查用于验证路径与依赖，正文正确性结合实际改动审阅。Markdown 代码示例和动态拼接路径不能由链接扫描证明，相关消费者仍需运行对应测试。

比较迁移前快照时，可运行 `python scripts/check_docs.py --base-ref <本地提交> --mapping <旧路径到新路径的JSON>`；只读输出 JSON 使用 `--json`，原始输出保存到 `.artifacts/<task-id>/`。

官网源文档、映射或图片变化时，还需运行：

```sh
pnpm --dir website run sync:docs
pnpm --dir website run check
pnpm --dir website run build
```

生成副本与源文件一同提交。脚本、配置或测试输入变化时运行对应最小回归；应用行为与打包变化遵循[开发概览](INDEX.md#engineering-development)的检查。变更结果及需维护者回看的内容写入正常交付说明。
