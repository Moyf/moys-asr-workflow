# 说话人核心与后续依赖

状态：PR #15 核心提交 `86aab171` 的远端 CI 已全部通过，保持 Draft、人工待验。#40 已接入完整体验，当前实现的定向验证与独立复查已完成；远端 CI 与人工验收另行确认。依据 [Issue 317](https://github.com/Moyf/moys-asr-workflow/issues/317) 的需求，以及先交稳定核心、再并行上层功能的范围决定。目标仍为 `2.0dev` 的 project v2；当前基于 fork #8，不另造格式版本。

## #15 必须先交付

- Python／JS 主入口使用同一身份表、段级引用、用途与五／九色设置；旧工程有明确升级规则。
- 旧字词身份先切段，再登记项目身份；绑定按既有独立／联动拆分语义处理并报告变化。
- 新旧工程的保存、另存、重开和服务器接管保留身份；跨工程导入不能按相同 ID 猜测同一人。
- 统一解析、分配、清除、身份合并接口；撤销包含身份表与设置；跨人字幕合并与 AI 后处理不得静默清除身份。
- 未适配入口保留数据并明确限制能力，不把旧颜色姓名当成身份姓名。

数据契约以 [JSON_SCHEMA](../engineering/JSON_SCHEMA.md#v2-说话人身份核心) 为准。核心不新增管理面板，也不交付自动九色；登记十个人可以仍使用五种显示色，但十个身份始终独立。

## 验收边界

采用合成工程和模拟 ASR 结果，不调用收费识别。定向覆盖 Python／JS 往返、长 ID 碰撞、三种旧输入另存、跨工程同 ID 不同人、清除后不恢复、一次撤销、跨人合并拒绝与事务回滚。保留真实浏览器和磁盘保存验证；不跑全量测试，不把自动测试当作人工验收。

待人工核验：真实旧工程迁移结果、拆段与解除绑定提示、主副叠加轨工作流及现有色块入口的用途区分。后续上层功能应使用这些共同接口，不重复实现身份模型。

#40 的身份管理、空槽与数字键、ASR 自动扩色、三轨筛选、预览和姓名导出已接入。[人工清单](../logs/release1.10.0-beta.2/261030_说话人体验/说话人体验.checklist.md) 保持待确认。相邻 `cue-color-filter` 用例中的三条旧断言（稳定组移出后的剩余成员、主题索引颜色、默认拆分修剪符号）与 #15 基线现有行为不符，本轮未回退生产语义，也不把这些失败计为通过。
