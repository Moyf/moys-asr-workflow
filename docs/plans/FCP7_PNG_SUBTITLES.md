# FCP 7 XML 图片字幕导出方案

状态：2026-11-08 维护者纠正格式要求：PNG 保留并作为默认图片格式，WebP 为显式可选项；保留原有动静分段、多轨和时序逻辑。FFmpeg 完成双底恢复、图片编码、Alpha 检测及逐帧 RGBA 哈希，图片字幕运行时移除 Pillow。当前返工记录见 [格式反馈账本](../logs/release1.10.0-beta.2/261108_FCP7WebP/TEST_FEEDBACK_FORMATS.md)。此前 VEGAS 14 核心导入证据针对 PNG，不代表当前 WebP 已通过目标软件验收。新验证见 [WebP 记录](../logs/release1.10.0-beta.2/261108_FCP7WebP/IMPLEMENTATION.md)。
源码核对基线：`esm/g08-cues-b`，`29bc204b`。本文的“已确定”指产品决定，不代表实现完成。

## 已确定的范围与行为

- 面向本地编辑器服务；维护者明确纯便携已 deprecated，本任务不考虑便携 HTML。
- 保留现有 Premiere 原生文字导出，图片模式将 ASS 渲染为透明 PNG（默认）或无损 WebP；通用 FCP 7 XML 入口明确可用于 PR / VEGAS，具体模式仍受目标软件能力限制。
- 静止部分使用单张图片持续显示；动态部分按导出帧率生成所选格式的图片序列。不能将整句有短动画的字幕全部展开为逐帧片段。
- 去间隙或切段后的新片段允许重新淡入；不要求保留切点之前的淡入进度。具体切段规则及其他动画的局部时钟在验证小样中明确，不由此推断所有动画都必须重启。
- 重叠内容输出多轨 XML，保留主轨、副轨、叠加轨的语义及遮挡层级。默认一个 XML；多个 XML 仅作为目标软件兼容性退路，不因 JS 生成多轨就主动拆文件。
- 沿用现有 ASS / 视频烧录的排版与画布约定，先核对并复用现有实现，不提前设计新的裁剪与位置系统。
- 批量渲染连续片段，避免每张图片启动一次 FFmpeg；流式处理，连续相同画面合并持续时间，全透明帧不产生可见片段。静态区间提前识别以减少渲染，无法确定的区间逐帧验证。
- 导出绑定启动时的项目快照，包含字幕、样式、布局、帧率、时间线和媒体绑定；支持进度、取消和失败处理，不发布缺图的成功结果。
- 提供“仅字幕”和“包含源媒体”两种输出范围；源媒体使用引用，图片模式不包含贴图。
- 交付 XML、所选格式的图片及素材清单；记录字幕 ID、轨道、帧区间、尺寸和渲染参数。重新导出不能破坏旧 XML 仍引用的素材。

## 已核对的现有实现

以下为设计阶段的源码核对基线；实施后的实测结果见末尾链接的验证账本：

| 入口 | 当前行为与复用点 |
| --- | --- |
| [ASS 导出](../../web/editor/io/editor-export-srt.js) | `currentAssVideoResolution` 优先取媒体元数据，其次取视频元素尺寸；`assExportOptions` 传入 PlayRes、字体样式和测量能力。`buildAss` / `buildGapRemovedAss` 通过 `buildAssPayload` 生成含主、副、叠加字幕的共同排版结果，并能通过 `onAssPlan` 获取布局计划。 |
| [视频烧录接线](../../web/editor/io/editor-wiring-burn-video.js) | `buildBurnVideoSubtitles` 使用上述 ASS 入口和同一布局计划收集贴图；明确 `alignFirstStart: false`，避免字幕文件“首条延长到零”偏好改变媒体时间线。`runBurnVideoJob` 先提交在编辑内容、生成请求，再等待保存选择器，并检查媒体绑定是否变化。 |
| [本地服务](../../server-editor/serve.py) | `burn_ass_video` 归一化字体名，将 ASS 写入任务目录并以文件名传给滤镜、以该目录为 cwd；贴图在 ASS 之前合成，字幕在上。已有 FFmpeg/libass 检测、任务取消和绑定校验。新增渲染实现应独立模块化，复用这些约定。 |
| 同上：`render_ass_frame_png` | 当前预览在 RGB24 上渲染 ASS，输出不透明 PNG，不能直接作为透明字幕导出的实现。透明 RGBA 和 alpha 合成需新增验证。 |
| [绿幕画布工具](../../maw/postprocess_ffmpeg.py) | `_green_screen_input` 接收画布尺寸并由字幕末尾确定有限时长；编辑器烧录绿幕调用使用 1080p 档位。其尺寸分支不能不加区分地复制为所有 PNG 导出的默认值。 |
| [FCP 7 序列化](../../web/shared/utils/fcp7.js) | 当前前端生成 XMEML v5，文字使用 GraphicAndType。已有媒体、贴图和字幕轨输出，可增加图片素材清单的序列化路径。 |

PNG 的画布、PlayRes 和 XML 序列尺寸应从同一快照解析，复用现有布局。尚不做透明边界裁剪。现有代码的共同计划是否能直接拆分为位置稳定的逐轨 ASS，需要验证；不能只将原始字幕拆开后重新排版。

## 模块边界

1. 前端准备不可变导出计划：输出范围、时间线、帧率、画布、布局、字幕轨及切段后动画规则。
2. 前端按完整上下文确定位置和层级后生成渲染请求；后端验证请求并批量调用 FFmpeg/libass，产生透明 PNG 和素材清单。
3. `fcp7.js` 保持纯序列化职责，接收按轨分组的图片片段，写出 `clipitem`、`file`、URL、静态图片属性和帧区间；不负责渲染或判断动画。
4. 图片成功落到最终位置后才发布 XML 和素材清单。目录选择、最终路径如何从宿主传到服务端，沿用现有受控文件能力设计；不新增任意路径读写接口。

素材清单至少包括 `cueId`、轨道与层级、`path`、`startFrame`、`endFrame`、宽高；帧区间统一为左闭右开。帧率使用准确分数。ASS 的时间精度与最终采样帧需显式对齐，不能多次独立舍入。

## 验证方案（执行结果见实施账本）

### 第一阶段：小样证明透明渲染与时间线

- 使用可公开的合成字幕和测试背景，产物留在 `.artifacts/`；先不接产品 UI。
- 制作约 10–15 秒、25 fps 小样，包含静态文字、短淡入淡出、静止保持段、两至三层重叠、空白段，以及去间隙后的重新淡入。
- 复用现有 ASS 生成和排版路径。输出透明 PNG，并按清单重新合成测试画面，与同一份 ASS、同一时间点直接渲染的参考画面对照。
- 分别在黑、白、彩色背景检查半透明边缘、阴影、描边；检查无字幕区域 alpha 为零、淡入中有中间 alpha、颜色没有明显黑边污染。
- 重点采样起点前一帧、首帧、动画结束前后、重叠开始和结束、末帧及后一帧。静止段必须只有一张图片跨帧保持；透明区间应为空白，不得错误沿用上一帧。
- 去间隙参考必须使用同样的“重新淡入”规则，不能拿保留原动画进度的参考误判。相邻片段按最终帧边界检查，不出现无意的一帧闪烁或重叠。
- 自动像素对照应固定字体、FFmpeg/libass 版本和尺寸；先测直接渲染与 PNG 重合成的正常舍入差异，再确定误差容限。不能仅凭文件存在、截图观感或同一份错误清单的自我对照判定通过。

### 第二阶段：目标剪辑软件导入

- 第一轮目标软件确定为 VEGAS Pro；具体版本取官方可安装版本并记录。仅安装本体，不安装附加套件；如需账号操作，由维护者完成。实际导入通过是最终验收条件。
- 先验证静态 PNG、短动画加长静止段、重叠多轨和源媒体引用组成的最小 XML；与参考时间线逐帧对照。
- 检查播放、Seek、轨道遮挡、alpha 解释、整体选择和移动一句字幕，以及保存工程后重新打开。
- 检查中文及空格路径、移动素材目录后的重新链接，分别验证“仅字幕”和“包含源媒体”。XML 自动校验不能替代此层验证。
- 第一轮默认每个变化帧为一个图片片段；静止部分合并。仅在实测操作性或性能不足时考虑嵌套序列、图片序列引用或多个 XML，不提前扩大实现范围。

### 第三阶段：集成、边界与性能

- 小样通过后再扩展 30000/1001 fps、1080p/4K/竖屏、极短字幕、较长项目、不同字体和效果组合。
- 记录动态帧数、唯一 PNG 数、XML 片段数、文件体积、渲染耗时、峰值内存和目标软件导入耗时；性能阈值依据实测讨论，不预先编造保证。
- 验证取消、磁盘写入失败、缺少 libass、缺字体、工程切换、导出期间修改字幕、重复导出和残留进程清理。
- 自动测试分为计划与帧映射、实际 libass 像素结果、XML 契约、前后端任务生命周期；目标应用导入及人工操作单独记录。
- 实施阶段遵守仓库检查入口、前端构建和独立自审要求；人工验收清单在实现及小样确定后编写。

## 当前进度与下一步

- 已在独立分支 `feat/fcp7-png-subtitles` 实现前后端 PNG 导出、静态保持、多轨、原子发布与取消。使用黑白双底 RGB 渲染恢复 straight alpha；直接 RGBA 渲染在本机 FFmpeg 构建下未通过像素对照。
- 已通过 25 与 30000/1001 fps 的重叠/动画边界像素对照、接口异常测试、前端单测，以及实际 Chromium 导出和旧文字导出回归。验证命令与证据持续记录在[实施账本](../logs/release1.10.0-beta.2/261106_FCP7图片字幕/IMPLEMENTATION.md)。
- 素材目录由服务端选在绑定工程旁，以随机后缀避免覆盖；完成后原子发布 XML、图片和 manifest。清单记录句子标识、轨道、区间、尺寸、帧率与渲染方法。
- 独立审查发现的瞬时动画窗口与采样上限问题已修复，补充旧红新绿证据并复审关闭；人工核验清单已生成。4K、竖屏及两小时静止段已有小样验证，复杂长工程的峰值资源占用和目标软件导入性能仍未测试。
- 维护者于 2026-11-07 提供 VEGAS 14.0 Build 211。原文件 URL 在该版本中无法定位素材，已追加 `subtitles-vegas.xml` 本地路径兼容副本，保留标准交接文件。25 fps / 30000/1001 fps 两种范围、中文及百分号路径、去空隙、保存重开均通过实际原生导入器验证；342 张黑白蓝背景原生快照最大通道差 1。
- 整句 10 个图片片段整体后移一秒、31 个 PNG 事件替换素材路径并保存重开，经 VEGAS 原生 API 验证；界面播放及逐帧定位已观察。文件选择窗口处理丢失素材、其他 VEGAS 版本、UNC 共享与大型时间线性能仍未验证，详见实施账本与核验清单。

XML 静态图片的 `duration` 按分钟写入，`start/end/in/out` 仍按帧；依据 [Apple XMEML 元素目录](https://developer-mdn.apple.com/library/archive/documentation/AppleApplications/Reference/FinalCutPro_XML/Elements/Elements.html)。VEGAS 对该约定的具体解释仍以实际导入为准。
