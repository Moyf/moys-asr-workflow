# Launcher 现代化改版设计方案

状态：方案已确认，开始分阶段实施（进度见[实施记录](../logs/unversioned/2026-10-14/LAUNCHER_REDESIGN_IMPLEMENTATION.md)）。本文记录设计原则、已确认的决定和实施约束；方案调整时更新本文。

原型已入库作为参考：[launcher-redesign/](launcher-redesign/README.md)，入口是 `prototype.html`，截图脚本是 `shoot.ps1`，挑选后的参考截图在 `shots/`。原型只用来确认方向，数据全是假的，也不代表最终的实现代码。

## 1. 为什么改

改版前，Launcher 是一条 630px 宽的单列：五张编号卡片（媒体 → 识别 → 自动处理 → 日志 → 编辑器）从上往下排，工具箱从右下角的悬浮按钮打开，设置是弹窗。主要问题有五个：

1. **一次性配置和每次任务混在一起**：API Key、获取链接、价格每次都占着主流程，但大部分用户只配一次。
2. **又长又窄**：884px 的窗口只用了中间一列，日志和编辑器卡片要滚很远才能看到。
3. **视觉没有层级**：卡片、输入框、提示行都带底色或边框，每块看起来一样重，主按钮也不突出。
4. **入口分散**：右上角是设置，右下角是悬浮工具箱，卡片里还有「单文件 / 批量」切换，没有统一导航；悬浮按钮还会盖住内容。
5. **状态看不出来**：准备、运行、完成三个阶段的界面几乎一样，用户要读日志才知道进行到哪一步。

## 2. 设计原则

1. **按使用频率分层**：
   - 每次都要用的（媒体、开始按钮）放在第一层；
   - 偶尔改的（模型、热词）可以折叠，但折叠时要用摘要标签显示当前值；
   - 只配一次的（密钥、地域、运行环境）放进设置。

   折叠不能变成「找不到」，看摘要就要知道当前配置。
2. **完整而不是精简**：改版不删掉任何现有选项。字段和条件显示规则以 `web/launcher/index.html` 为准，只改位置和形式；提示文字可以精简（见第 8 节第 5 条）。
3. **界面跟着状态变**：
   - 没选文件时，拖放区是主角；
   - 选好后变成文件卡片；
   - 运行时，底栏变成进度条和阶段链；
   - 完成后，顶部出现结果卡片，主按钮换成「在编辑器中校对」。
4. **就地配置**：哪里需要配置，就在哪里给入口，不让用户跳到别的页面再找回来（见第 5 节）。
5. **一页一个主按钮**：每页最多一个实心主按钮；条件不满足时按钮禁用，旁边写明还缺什么。
6. **同一份面板，多个入口**：工具箱页面和自动后处理的配置抽屉用同一套表单，不维护两份。
7. **一个工具只做一件事**：工具箱里的工具和自动后处理的步骤一一对应，用户不需要先选工具、再在下拉里选任务。
8. **克制的装饰**：
   - 去掉多余的边框和底色，靠留白、字重和少量品牌色区分层级；
   - 不用渐变；
   - emoji 换成统一的线性 SVG 图标，在各平台显示一致。
9. **可读性优先于紧凑**：宁可页面长一点，也不靠缩小字号、调暗文字来塞内容；文案尽量写短，避免折行。
10. **沿用现有约束**：明暗双主题、UI 间距规则（相邻元素至少 8px，按实测验收）、i18n、服务只监听 localhost，全部照旧。

## 3. 已确认的决定

| 项目 | 决定 |
| --- | --- |
| 整体布局 | 采用左侧窄导航 + 单列内容。 |
| 编号步骤 1/2/3 | 保留，样式减轻；完成的步骤显示对勾。 |
| 品牌色 | 取自吉祥物。亮色是红白，主色 `#c84545`（与编辑器的红色一致）；暗色是黑橙，主色 `#f09a50`（介于角饰橙 `#ff8f3f` 与 `#e0a05a` 之间，偏亮、不刺眼），主按钮上的文字用深色，保证对比度。（2026-10-14 第四轮调整） |
| 亮色底色 | 白就是白：背景、卡片、悬停、选中都用中性的灰白，不铺带红色调的粉色底；红色只用在文字、图标、边框、开关和主按钮上。 |
| 暗色明度 | 不要太黑：用炭灰（背景约 `#1c1c20`，卡片约 `#26262b`），不用接近纯黑的底色。 |
| 渐变 | 不用。结果卡片、缩略图、进度条、图标底都改成纯色。 |
| 文字可读性 | 不出现很小的字：12px 只用于徽标、角标这类短标签；提示、说明、标签、子标题至少 13px。次要文字对比度至少 4.5:1（暗色下尤其要注意），太暗的颜色只给占位符和装饰。 |
| 拖放区插画 | 先用图标占位，不复用软件图标；维护者以后提供专用素材再替换。 |
| 吉祥物 / 软件图标 | 软件图标用在导航 logo；吉祥物用在「关于」页。 |
| 识别设置 | 用摘要标签加可展开的完整表单；展开后包含全部现有字段，按服务商切换对应字段。 |
| 「最近工程」 | 做。 |
| 结果统计 | 后端拿不到的数据不显示（原型已去掉花费估算）。 |
| 宽窗口两栏 | 暂时不做。 |
| 术语 | 「转写后自动处理」统一改称「自动后处理」。 |
| 帮助入口 | 导航底部「设置」上方加「帮助」按钮，弹出菜单。 |

## 4. 导航与页面

左侧导航从上到下是：**转写 / 批量 / 工具箱 / 工程**；底部依次是 **帮助** 和 **设置**。

- **转写**：
  - 三个编号卡片：选择媒体、识别设置、自动后处理，再加底部操作栏。
  - 日志改成按需展开的卡片，入口在运行时的底栏里。
  - 结果卡片只显示后端能给出的数据（字幕条数、用时、产物路径、中间结果链）。
- **批量**：
  - 独立页面，替代原来媒体卡片里的「单文件 / 批量」切换。
  - 显示文件队列、每个文件的进度和状态，以及「只生成字幕」开关。
  - 识别设置和自动后处理沿用转写页，页面上用摘要标签说明，并给跳转链接。
  - 在转写页一次拖入多个文件，会自动转到批量页；批量运行时，导航上显示队列数徽标。
- **工具箱**：
  - 从悬浮抽屉升级成一级页面。
  - 左侧二级导航分三组：字幕处理、AI 处理、媒体工具。
  - 右侧依次是共享输入、当前工具面板，底部是运行按钮。
  - 共享输入按工具组切换：字幕处理和 AI 处理用「处理文件」（附处理链）；烧录字幕、提取音频、生成波形用「媒体文件」（对应 `toolboxUtilityMediaPath`，默认跟随转写页媒体）；口播对齐和生成时间码自带输入，不显示共享输入。
  - 输出模式（工程 + SRT 等）只在字幕处理和 AI 处理时显示；媒体工具始终生成新文件，不显示。
- **工程**（原来的「编辑器」卡片）：
  - MAWE 编辑器由本机 server 提供。这一页管的是「把哪个工程交给 server」和「server 现在的状态」，不嵌入编辑器本身，所以叫「工程」，不叫「编辑器」。
  - 从上到下：
    1. 服务状态条，压成一行；
    2. **最近工程**（新增）：可搜索，标出「正在编辑」，提供打开所在文件夹；文件丢失时可以重新定位或从列表移除；
    3. 打开其他工程：拖放、可选媒体、空白 / 便携编辑器入口和端口。
  - 最近工程只记在本机。在「设置 → 通用」里可以关闭记录、清除记录，最多保存 30 个。
  - 转写完成后的「在编辑器中校对」和底栏的「打开编辑器」，仍然直接启动 server 并打开浏览器，不用先进这一页。
- **帮助菜单**（导航底部）：
  - 菜单项：新功能（带版本角标）、使用指南、教程视频、报告问题、GitHub。第一版只做 UI，菜单项暂不可点。
  - 页头只保留「支持 MAW」和主题切换，原来的 GitHub、教程链接移进这个菜单。
- **设置**：
  - 从弹窗改成页面。
  - 分区沿用现有四类：通用、断句与标点、AI 模型、运行环境；另加「关于与支持」。
  - 运行环境里的每个依赖改成一行状态：图标、状态标签、操作按钮。

## 5. 自动后处理、工具箱与配置抽屉

原来的悬浮工具箱有个好处：在自动处理里勾选某一步后，可以直接弹出工具箱填配置，不用离开主页面。改版保留这个用法，并做了下面的改进。

### 5.1 工具与步骤一一对应

- 原来「AI 处理」是一个工具，里面用「任务」下拉选校对、断句、翻译等，层级太深，也和自动处理里分开的步骤对不上。
- 改版后，AI 处理拆成独立工具：**口播整理、AI 校对、重新断句、翻译、自定义提示词**。
- 每个工具只放自己的字段（例如重新断句的「每条最大字数」、翻译的「目标语言」「合并双语」）。几项公共内容放在面板底部：追加要求、折叠起来的「查看内置提示词」、生成对比 HTML、AI 模型设置入口。
- 供应商和模型统一在「设置 → AI 模型」配置，各工具卡片头只用一个状态标签显示当前连接。
- 「自定义提示词」只在工具箱里单独运行，不进自动后处理。

### 5.2 「可用于自动后处理」开关

- 工具箱里每个能自动执行的工具，卡片底部有一行紧凑开关：「可用于自动后处理」（小号开关 + 文字，上方一条分隔线）。不放在卡片头，避免和标题、模型状态标签挤在一行。打开后，这一步才会出现在转写页的自动后处理列表里。
- 默认只开常用的几步：固定替换、AI 校对、重新断句、翻译。其他步骤（文稿匹配、口播整理、OCR 去重、烧录字幕）由用户按需打开，避免首页一下列出八步。
- 关掉某一步的开关时，这一步的启用状态也会一起关掉，保证不显示的步骤不会被执行。
- 工具箱左侧导航里，可用于自动后处理的工具会显示一个小圆点：实心表示已开启，空心表示未开启；底部有图例。
- 转写页的自动后处理列表底部提示「另有 N 个步骤未显示」，并给入口跳到工具箱。

### 5.3 自动后处理列表

- 只列出已开启的步骤，按执行顺序重新编号。
- 每行有：开关、当前配置摘要、「配置」按钮，以及「LLM」或「慎用」标签。
- 缺少必要输入的步骤，按钮会变成黄色的「去配置」。

### 5.4 配置抽屉

- 点「配置」后从右侧滑出，宽 640px，盖住导航以外的内容，后面加半透明遮罩。
- 不用横向滚动的标签条，改成**左侧竖排步骤栏**：只列已开启的步骤，全部可见，显示序号和启用圆点；底部有「上一步 / 下一步」，可以连续配置。
- 右侧直接复用工具箱的同一个面板，但隐藏共享输入和「可用于自动后处理」开关。抽屉标题下写明「对本次转写结果按顺序执行」，面板里不再重复提示（原来的 `toolboxConfigOnlyHint` 合并到标题说明）。
- 面板头部有「启用」开关，和列表里那一行双向同步。
- 底部有「在工具箱中单独运行」和「完成」；按 Esc 或点遮罩也能关闭。
- 原来右下角的悬浮按钮取消，由导航里的「工具箱」和列表里的「配置」两个入口替代。

## 6. 识别设置按服务商切换

摘要标签和展开区都跟着服务商变化，共用的部分（识别方式、模型、快速测试、语言、频谱、调试）位置不变。各服务商的差异如下：

| 服务商 | 专有字段 |
| --- | --- |
| 阿里云百炼 | API Key 与地域提示、保留方言、提示词（400 字）、热词（直接输入 / 从文件读取）与默认权重、说话人配色 |
| Soniox | API Key、上下文四栏（General / Text / Terms / Translation terms）与 10000 字计数 |
| OpenAI / 兼容接口 | API Key、Base URL、自定义模型名、Prompt、Keywords |
| 豆包 | API Key、文件大小与时长限制提示 |
| 腾讯云 | SecretId 与 SecretKey、COS URL 提示 |
| 本地模型 | 运行环境状态行（跳转到设置）、设备、对齐模型；不需要 Key |
| FireRed | 设备、自动加标点（ct-punc） |
| 必剪 | 免 Key、仅支持中文的说明 |

不需要 Key 的服务商，摘要里不显示 Key 的状态标签。

## 7. 视觉规范（原型阶段的令牌）

- **颜色**：令牌集中在原型的 `tokens.css`。正式实现时映射到 `launcher.css` 现有的变量名（`--accent`、`--bg-panel` 等），不另起一套命名。
- **圆角**：卡片 14px，输入框和按钮 9px，标签 999px。
- **控件高度**：输入框和按钮 36px，主按钮 42px，小按钮 30px。
- **间距**：卡片之间 14px，卡片内边距 18–20px，分组标题上方 18px、下方 10px。
- **字号**：
  - 正文 14px，卡片标题 15px，页面标题 20px；
  - 标签、提示、说明 13px；
  - 徽标 12px，导航角标数字 11px；
  - 不使用更小的字号。
- **文字颜色层级**：
  - `--text`：正文；
  - `--text-2`：标签与说明；
  - `--text-3`：次要信息（对比度 ≥ 4.5:1）；
  - `--text-4`：只用于占位符和拖拽手柄。
- **图标**：统一使用线性 SVG sprite（线宽 1.8，24 视口），替代 emoji 和 keycap 图标。

## 8. 待定项的结论（2026-10-14 第二轮）

1. 拖放区插画：暂不处理，代码里留注释说明替换位置。
2. 帮助菜单：先只做 UI，菜单项暂时不可点击（禁用并标「即将推出」），功能以后再接；菜单项只保留**新功能、使用指南、教程视频、报告问题、GitHub**，去掉「系统诊断」和「意见反馈」。其中「使用指南」「教程视频」「GitHub」已有链接，可以直接可点，以实施时确认的现有链接为准。
3. 窄窗口（< 760px）：导航收成只显示图标。
4. 最近工程：在转写完成、工具箱输出、工程页打开这三处都记录；每一项都可以「用作工具箱输入」，一键填入工具箱的处理文件。
5. 文案：实施时顺手精简冗余、啰嗦的提示。原则是删掉重复说明（同一信息只在一处出现，比如抽屉标题已说明处理对象，面板里不再重复）、内部实现细节和过长举例，保留会影响用户决定的事实（是否覆盖源文件、是否发送到云端、费用与风险提示）。中英文同步修改；被测试断言的文案同步更新断言。
6. 「可用于自动后处理」开关放在工具卡片底部，不放卡片头（2026-10-14 第三轮）。
7. 工具箱媒体工具补回共享的「媒体文件」输入；输出模式只在字幕类工具显示（2026-10-14 第三轮）。

## 9. 实施约束

- 不引入前端框架。继续用 `web/launcher-scripts.txt` 清单和 esbuild 装配 bundle；改了 JS 或清单后要重建，并运行 `pnpm run check:launcher`。
- 尽量保留现有元素 id 和 `data-i18n` 键，避免 `forms/*`、`launcher-state.js` 和 e2e 大面积改动。新增文案加进 `launcher-strings.js`，中英文同步。
- AI 处理拆成独立工具后，前端不再展示「任务」下拉，但仍可以复用原来 `postprocessOperation` 的取值，避免改后端协议。
- 「可用于自动后处理」开关需要新增一项本机偏好；默认值按第 5.2 节。
- 「最近工程」需要新增本机存储，只存路径和时间，不存内容；服务仍然只监听 localhost。
- 建议分阶段提交：
  1. 令牌与基础组件（只换皮）；
  2. 导航与页面骨架（工具箱和设置从抽屉、弹窗迁成页面）；
  3. 转写页的状态切换与配置抽屉、AI 工具拆分；
  4. 批量页与工程页（含最近工程）。

  每个阶段都跑受影响的 e2e，并截图自查明暗两套主题。
- 有用户能感知的变化，按 CHANGELOG 规则汇总记录。

## 10. 后续：颜色令牌统一（开发清单）

目标：Launcher 与编辑器共用一套颜色令牌，日后改色只改令牌层。2026-10-14 已完成令牌层对齐（两边的背景、文字、边框、按钮、强调色同值；编辑器默认强调色为品牌色）。以下不急于一次完成，按区域逐步推进：

- [ ] 盘点 `web/editor.css`、`web/waveform.css`、`web/launcher/launcher.css` 中令牌块以外的硬编码颜色（编辑器约 375 处），按语义归类：中性灰、强调、状态（成功 / 警告 / 危险 / 信息）、说话人与字幕调色板、波形与空隙、阴影与遮罩。
- [ ] 能对应现有令牌的直接改用 `var(--…)`；重复出现但没有令牌的，新增语义令牌（同时给出暗色与亮色值），不新增只用一次的令牌。
