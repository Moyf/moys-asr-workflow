# 现代 Final Cut Pro 工程交接：FCPXML 导出开发计划

状态：M1 仅标题原型已实现，未接入编辑器、未实机放行。原提案核对基线：`main` / `c9602cc0`，2026-11-24。

已知证据：据维护者反馈，参考项目 Subtitle Studio 已由用户在 Mac 上实测，可作为原生标题交接的可行性证据。**不设独立的开工前 Mac 验证门**；可直接开发 MAW 的生成与打包。参考项目的 1.8 实测不替代 MAW 自产 1.13 包及带媒体模式的发布验收。

## 1. 交付目标

在 MAWE 本地编辑器新增 **「Final Cut Pro 工程（FCPXML）」**。Final Cut Pro for Mac 直接导入，在库中创建一条 Project 时间线；字幕是可编辑的标题片段，而非图片或封闭字幕轨。**首个完整版本包含「仅标题」和「源媒体与标题（原始时间线）」，两个范围单独验收。** 若带媒体未通过，可先以 **「Final Cut Pro 可编辑标题」** 发布已通过的模式，关闭带媒体选项，不宣传完整工程交接。随后交付「源媒体与标题（去空隙）」：用选中的原素材区间搭剪辑，不重编码。

| 导出范围 | 原始时间线 | 去空隙时间线 |
| --- | --- | --- |
| 仅标题 | 首版默认。占位 gap 承载主、副、叠加标题；无媒体引用。 | 首版。标题跟随 MAW 压缩时间；提示配对去空隙素材或同一剪辑，不自动加载原视频。 |
| 源媒体与标题 | 首版。引用一个已绑定的受支持源视频及其音频，带标题和全长时间线；不复制素材。 | 第二阶段。把 MAW 保留区间编成连续的源媒体剪辑，标题与这些**实际输出切点**共用时钟；不引用一条尚未生成的“去空隙视频”。首版不显示这个组合为可用。 |

**不做：** `.fcpbundle` 原生库文件、FCPXML 导入或写回 MOSP、往现有 FCP 项目自动插轨、多源工程、代理素材打包、原生字幕角色/封闭字幕、逐字动画或 ASS 像素级还原、表情包与标记、CLI、便携 HTML、Premiere/Resolve 兼容承诺。现有 FCP 7 XML、SRT、ASS、OTIO/OTIOZ 保持原行为。

### 格式选择

- 首版固定 **FCPXML 1.13**，交付 `<工程名>.fcpxmld/Info.fcpxml`。1.13 是 Final Cut Pro 11 引入的格式；普通标题和单媒体剪辑不需要追最新 DTD。目标兼容性由实测决定，不宣称所有 11.x 及后续版本都已通过。
- 浏览器下载 `<工程名>-final-cut.fcpxmld.zip`；下载按钮旁注明 **「先解压，再导入 `.fcpxmld`」**。ZIP 只做运输，不是导入文件。首版不提供裸 `.fcpxml` 或版本选择；后续若提供裸文件，复用同一序列化器并走同一实机矩阵，不靠改扩展名或 `version` 声称兼容。
- [Apple 版本记录](https://support.apple.com/en-us/102825) · [FCPXML Bundle](https://developer.apple.com/documentation/professional-video-applications/fcpxml-bundle-reference) · [创建 FCPXML 文档](https://developer.apple.com/documentation/professional-video-applications/creating-fcpxml-documents) · [在 Final Cut 导入 XML](https://support.apple.com/guide/final-cut-pro/use-xml-to-transfer-projects-verdbd66ae/mac)。

## 3. 产品与数据契约

### 用户操作

1. 从「更多导出 → Final Cut Pro 工程（FCPXML）」打开专用弹窗；不改现有「FCP 7 XML」入口。去空隙导出菜单如已有统一入口模式，可链接同一弹窗并预选去空隙，不另造流程。
2. 选时间线（默认原始）、范围（默认仅标题）、轨道（默认导出有内容且启用的主/副/叠加）、FPS 与画幅。仅标题允许无媒体；有合法媒体元数据优先预填，否则提示用户确认 30 fps / 1920×1080 等回退。明确提示去空隙配对、范围差异与样式降级。
3. 确认时提交行内、字幕面板和副轨正在编辑的文本，冻结项目、媒体绑定和参数。绑定在异步探测/保存期间改变则中止，不混入新工程。显示下载发起、取消、失败的区别；文件已保存才显示“已保存”。导出不会保存或改写 MOSP。
4. 解压后在 Final Cut 选择 **文件 → 导入 → XML**。仅标题工程不带视频；含源媒体版本保留文件引用，换机器时需要对应素材并按需重新链接。

### 字幕与样式

- 由 MAW 现有正文投影决定输出：禁用或空句不出、关闭轨道不出、AI 局部删字与还原跟现有导出一致。首版 UI 支持主轨、当前副轨、叠加轨；若共享计划把多条副轨合并为一组，先以活动副轨 ID 过滤不可变输入，不能无提示合并非活动轨。只有副轨或叠加轨有内容时仍能导出；所选轨无可导出标题时不生成空工程。
- 每句一个可编辑 `title`。原始换行保留，XML 1.0 文本与属性分别做正确转义；拒绝不可序列化字符并明确提示。区分主、副、叠加的默认垂直位置，重叠使用稳定的 lane 分配，按照「叠加层在主层上，副层独立」安排，同 lane 不重叠。lane 只定义时间线层级，不保证画面文字一定避让。
- 首版只用一款内置标题模板。字体、字号、文字颜色、对齐、位置、描边或字重都是候选映射；**只承诺在该模板中已通过写入、横竖屏显示和回导验证的属性**。字号、位置按 MAW 画幅和样式坐标转换；未验证属性使用模板默认并明确降级。ASS 动画、逐字效果、复杂局部覆盖不承诺等价；不分发字体、Motion 模板。
- 以目标版本从 FCP 导出的参考包锁定一款模板的 `effect` UID 与参数白名单，可在 M1 并行收集，在发布前验证固定 UID；不用本地化显示名猜模板。目标机缺少字体时由 FCP 替换，文档说明如何检查。

### 时序、媒体与路径

- 以 MAW 导出投影后的整数毫秒为输入；**输出 FPS 不是读取 `start_frame` 的时钟**。首版仅标题复用现有帧率档位；遇到 23.976 等当前没有的档位显式提示，不悄悄当 24。含媒体首版锁定已验证的 CFR 媒体画像（容器、编码、零起点、单音轨或无音轨），**输出 FPS 必须与源 FPS 的有理数完全相同**。源尾帧从可信视频帧计数或可独立验证的精确视频流时长与帧率得出，不从取整后的容器毫秒时长或字幕末尾猜。若时长/帧数证据不足、VFR、非零源 timecode、多音轨或格式未验证，明确提示改用仅标题。
- 以帧区间 `[startFrame,endFrame)` 定义所有剪辑和标题。标题起点向下、终点向上取整，钳制到输出范围；零长结果丢弃并计数。若相邻标题经量化重叠，不移动它们来隐藏问题，使用稳定 lane 并覆盖 1 帧边界测试。`frameDuration`、`offset`、`start`、`duration` 写成有理秒，非整数帧率用如 `1001/30000s` 的基准；所有子 title 的 offset 都相对正确的父容器时间域。无媒体时使用显式已知时长；未知则从有效标题尾与有效 Gap 端点推导源范围，并提示仅标题的结尾不保证与素材尾部一致。
- 原始带媒体：`resources` 生成独立 format、内置 effect 与带 `media-rep kind="original-media"` 的 asset，`spine` 一个全长媒体片段，标题作为已验证的连接节点。`source` 与 `output` 范围不要套用短标题尾作为工程尾。以系统验证过的真实绑定路径构造 `file:` URI，UTF-8 百分号编码**一次**；Windows 本地媒体不能假装在目标 Mac 可访问，明确提示准备相同媒体和可能需要重连；无 Mac 路径文件引用支持证据时不把跨机自动重连写成保证。不强制读取或复制素材内容来生成 ZIP。
- 去空隙带媒体：先用 MAW 的有效 `keptIntervals`，把每个**源剪切边界**用同一确定的帧量化策略投影（拟用最近帧，平局向后；测试后锁定）。统一顺序去重、剔除零长、合并量化后相接区间，再按保留**帧数**累加输出起点。将**压缩前的有效源 cue** 量化后与最终保留源帧求交，再映射输出帧；不要先用毫秒压缩计划过滤 cue，因为切点对齐后，毫秒上全删的 cue 仍可能与保留帧相交。跨接缝按连接节点限制拆分，不恢复 AI 已删文字；按最终帧区间判断完全移除。输出序列长等于保留帧总和，音视频切点与标题共用该映射。仅标题压缩继续用现有 MAW 毫秒投影，文档明确配对方式，不承诺与逐帧剪辑版本完全相同。

## 4. 实现切分

| 模块 | 实现与边界 |
| --- | --- |
| 共享计划适配 | 在 `web/shared/utils/` 增加 FCPXML 模块，经 `web/shared/editor-utils.js` 接入。复用文本和 Gap 语义，新增 FCP 专用、可单测的帧级 IR：序列规格、时钟、连接点、片段、选中轨和样式。原始项目与现有格式输出不变。 |
| 纯序列化器 | 从帧级 IR 生成 UTF-8/LF `Info.fcpxml`；测试稳定的资源 ID、IDREF、节点顺序、时间及固定 effect 白名单。序列化层不读文件、不查 DOM、不探测媒体。 |
| 本地 Editor Server | 借用既有 OGraf ZIP 下载模式：前端发结构化、限大小的 IR 加绑定令牌，服务端只接受固定版本/字段与值域，服务端从当前绑定提供媒体事实，不信任任意路径、URL、XML 或归档项；由唯一序列化器生成 XML，ZIP 仅有固定根包下的 `Info.fcpxml`。实现时建议把纯序列化器放 Python `maw/fcpxml.py`，JS 只产 IR；不做两套 serializer。用标准库 `zipfile` 返回下载流，不新开用户路径写接口。对超限、异常、绑定失效给可翻译错误。 |
| UI / 宿主 | 新领域文件放 `web/editor/io/`，按现有初始化/装配规则注册；小范围接菜单、弹窗 DOM、i18n、服务器 capability 和既有下载契约。复用同一下载链路，不要求 Windows 能运行 Final Cut。 |
| 维护 | 首版不改 MOSP schema、不加运行时第三方依赖、不改 FCP 7/OTIO 架构。功能交付时更新编辑器指南、FAQ（包怎么解压、媒体怎么重连）、CHANGELOG；官网涉及的源文档按仓库标准验证。 |

## 5. 里程碑、测试与放行

1. **M1：共享规划 + 纯生成 + 受控打包（约 2–3 人日，可直接开始）。** 做原始和压缩仅标题、原始带媒体；并行准备带内置标题、重叠层和视频的 FCP 参考包，记录官方 1.13 DTD 的确切来源、许可与验证命令，不在运行时联网下载。开发先从合成样本开始，不等 Mac。JS 单测覆盖 25 / 30 / `30000/1001`、工程 30 fps + 素材 25 fps、短句、相邻、长时轴、多层重叠、禁用轨、空句、AI 局部删字/还原、无媒体、Gap 与尾帧证据不足时的拒绝。Python 测试覆盖 DTD、IDREF、XML 字符、bundle 固定结构、路径编码、大小上限及无越权路径；用独立样例断言帧数，不用生成器自己的映射当唯一基准。
2. **M2：接 UI，验收首版（约 1–2 人日，另计实测）。** Chromium/Electron 覆盖入口、中英文、选项联动、下载和取消、工程切换、旧菜单回归。在已授权的 Mac 上导入 **MAW 自产**的横竖屏合成包，不以 FCP 自己导出的参考包替代验收。仅标题逐项核对文字、层级、首末帧、样式、改字、保存重开和回导 XML。含媒体额外必测 **Windows 生成 → Mac 导入 → 手动重连同一源文件**，用烧录帧号和音频标记核对首末帧、音画及标题。另跑既有 FCP 7 XML、OTIO/SRT 和 AI 导出定向回归。
3. **M3：增加去空隙带媒体（约 2–3 人日，另计 Mac 实测）。** 锁定接缝归属与跨接缝标题规则；用独立预期帧号覆盖切口前后、跨接缝、毫秒视角全删但仍与保留帧相交、量化后零帧及长项目漂移。Mac 用带烧录帧号和音频标记的素材核对接缝前后音画和标题、最终帧数，再回导检查资源与裁剪点。未通过继续关闭该组合，不以未剪原视频搭配压缩标题作为替代。

### 证据与发布门

- 自动校验：新增定向 Node/Python 套件、DTD 验证和 Playwright；按仓库规则走有界 `scripts/run_check.py`，记录精确命令与 SHA。改前端执行 `pnpm run build:editor` 和 `pnpm run check:editor`；不重生成仓库内便携 HTML。
- 实机校验：开发时并行落实已授权 Mac 与验收负责人。按 **确切 FCP 版本 × 原始仅标题 / 压缩仅标题 / 原始带媒体 / 压缩带媒体** 记录通过、失败或未测，以及平台、合成输入、期望帧、实测及回导证据。只实测某一版本就只称该版本已验证；要承诺 11.x 下限，必须测承诺的确切最低版本。普通 CI 的 DTD 检查不是导入证据；没 Mac 不阻塞开工，但未验收的模式不公开。
- 放行标准：结构、模板缺失或自动修复警告判失败；跨机带媒体的预期离线提示可接受，但要实际重连成功并核对音画。标题须可单独改字、保存重开，时间符合既定帧位，已承诺样式须显示及回导一致。长项目记录生成耗时、ZIP 体积与 FCP 导入耗时。若仅标题通过、含媒体未通过，按「可编辑标题」发布通过的模式，不把它宣传成完整工程交接。
- 回滚：隐藏独立入口/撤下 capability 即可；不迁移用户数据，不影响已导出的包、现有格式或工程兼容性。

**第一项可执行任务：用一份 10–15 秒的合成双语样本，先实现共享源 cue → 仅标题帧级计划 → `.fcpxmld.zip` 的最小链路。** 并行收集目标 Mac 的 1.13 参考包；正式发布前，用 MAW 自产包跑对应能力的验收矩阵。
