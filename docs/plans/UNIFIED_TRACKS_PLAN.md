# 统一字幕轨道实施方案

状态：格式与消费链接入正在整合，尚未完成。本文记录 2.0 的目标契约和待实施工作，不代表现有代码已满足这些要求。决策依据为 [Issue #311 的维护者意见](https://github.com/Moyf/moys-asr-workflow/issues/311#issuecomment-6470711705)。

## 目标与版本边界

主字幕、双语副字幕和叠加字幕统一存入 `tracks[]`，运行态以轨道对象为唯一真源。角色表达现有产品语义，不按数组下标识别主轨。本轮不开放多副轨功能，也不引入多素材剪辑或音频混音。

格式演进为：无 schema 或 `moy.asr.project.v1` 的旧容器 → `moy.asr.project.v1.5` 的稳定颜色 / 贴纸组 → `moy.asr.project.v2` 的统一轨道与 CueRef。PR #239 的分组契约（合入提交 `f3dfb60a`）和 PR #312 的轨道读取层均已合入 `2.0dev`，整合以当前上游代码为基线。历史 v3 草案不是当前格式目标。

导入需识别 v1、v1.5 和 v2。旧工程可在内存迁移，但首次写为 v2 必须显式另存，取消或失败不得覆盖原文件；自动保存、媒体关联与其他写入路径不能绕过此保护。未来或未知版本须在迁移、修复、媒体绑定及写入之前拒绝。

## 轨道与关系

- 工程有且只有一个 `main` 轨；角色使用 `main`、`secondary`、`overlay`。新建工程也有空主轨，删除唯一主轨应清空内容而非留下无主轨工程。
- 轨道持有稳定 ID、名称、角色与字幕。语言、来源、断句方式及其他轨道元数据跟随轨道；媒体、时间基准、标记及工作区等仍是工程属性。媒体音轨不是字幕轨。
- 使用 `{track_id, segment_id}` 表示 CueRef。绑定用具名 `source` 和 `target` 两个 CueRef，分别指向主轨和副轨的字幕；检查端点存在、角色和当前一对一关系。不要把单轨数组索引当作跨轨身份。
- 交换主副轨是可撤销事务，交换角色和绑定端点时保留轨道及字幕身份、颜色 / 贴纸组和来源元数据；失败时不得留下半次交换。移动、复制、拆分和合并须更新相关引用，保留适用的稳定 ID 与组关系。
- `enabled`、`preview_visible` 和 `export.enabled` 分别表达轨道启用、预览可见与导出选择；不能互相覆盖或因隐藏而删除轨道与数据。与附件、烧录和各导出入口的行为一并验证。
- 副轨关闭或隐藏不删除其字幕、绑定、样式及来源信息。多副轨操作留待独立功能设计；迁移已有数据时不得静默丢弃。

## 组、样式与时间

`subtitle_groups` 延续 v1.5 的稳定组契约：字幕引用颜色或贴纸组 ID，组范围由成员推导。导入 v1 时先在原轨道和原数组中解析 `color`、`sticker` 及 `headIdx`，再迁移；禁用首句、未知字段及自定义组值都须保留。坏引用应返回可定位错误，不静默改为默认颜色。

轨道样式采用工程内样式快照；共享样式的联动编辑与写时分离已确定，仍须实现并验证。主副交换不得覆盖另一轨的样式、字幕属性或组关系。所有轨道的单句定位也已确定，仍须接入编辑、预览与导出；不得仅在主轨生效。

所有 cue 和 items 时间继续使用源媒体整数毫秒，帧字段及 fps 沿用现有语义。身份、样式或轨道操作不得改写字词时间。轨内保持现有顺序和非重叠约束，跨轨可重叠；零时长标点 item 保持既有兼容行为。去空隙只映射派生播放 / 导出的时间，不修改源时间。

## 导出

普通 SRT 按现有规则包含主轨和启用的叠加字幕；新增 overlay 变体默认不进入主 SRT。副轨和其他导出模式须按明确选择处理，保存工程不能以导出选择过滤轨道。预览、烧录和各格式的轨道选择与三种开关分别核对。

PR #239 采用 Resolve 外部协议 v2，颜色与贴纸按组区间导出；OTIO 也按组的连续区间输出。相关消费链要保留实际组区间与间隙。烧录保持源媒体时间与既有首句对齐选项的语义。

## 导入、保存与接口

处理顺序为：识别版本 → 深拷贝候选 → 验证原格式 → 明确迁移 → 验证 v2 → 一次提交运行态。迁移返回工程与变更信息；失败不得改变输入、当前工程、撤销栈、媒体绑定或磁盘。v1.5 的组表及跨轨引用必须保留；旧轨内 ID 和跨轨关系按 CueRef 迁移，碰撞处理及引用更新须在同一事务完成。未知字段，包括 false、0 和空容器，应保留；键冲突须报告，不静默覆盖。

保存时验证并序列化统一工程，剥离既定运行缓存，不在保存过程中修复当前状态。本地写入采用同目录临时文件与原子替换；服务器继续保留备份、保存锁、工程绑定检查和保存确认后的脏状态比较。保存期间继续编辑或切换工程，旧确认不得清除新修改或覆盖新绑定。

Python 和 JavaScript 应对同一输入给出一致的迁移与校验结果。读取层通过轨道 ID 和 CueRef 访问原对象；旧容器只在导入适配边界读取，业务代码不长期伪造第二套状态。最终检查 ASR、后处理、翻译、服务器、编辑器、预览及导出入口，避免新旧结构混用。

## 待实施与验证

1. 对齐 Python / JS 的 v1、v1.5、v2 校验与迁移，接通具名双端点 CueRef、唯一主轨和三种轨道开关。旧工程显式另存保护覆盖所有写盘入口。
2. 接通轨道样式快照、联动与写时分离，以及所有轨道的单句定位；主副交换、撤销和恢复保留身份、组、样式及元数据。
3. 接通预览、普通 SRT、其他字幕导出、烧录、Resolve v2 和 OTIO 的选择及组区间语义。新增 overlay 变体默认不进入主 SRT。
4. 使用共享夹具覆盖旧工程迁移、跨轨组、ID / CueRef 悬空或冲突、未来版本拒绝、完整字段保留与往返；验证输入不变、失败不写盘。
5. 验证轨道操作、主副交换、撤销重做、三个开关组合、旧工程取消另存、保存并发及迟到确认。覆盖禁用组首句、组连续区间和间隙、字词时间不变、字幕源时间与去空隙映射。
6. 对 ASR、后处理、服务器打开 / 另存和浏览器加载分别运行目标测试；编辑器变更后构建并检查，开展真实浏览器和导出人工验收。自动化结果与人工验收分别记录。

最小可交付是旧工程安全打开 → 统一轨道编辑与撤销 → 显式另存 v2 → 重开 → 主要预览和导出链正确。仅有迁移 helper 或新格式外壳不能视为完成。
