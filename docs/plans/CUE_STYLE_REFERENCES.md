# 单句 ASS 样式引用（2.0 草案）

[议题 434](https://github.com/Moyf/moys-asr-workflow/issues/434) 描述了修改样式库后需逐句重选的问题。此草案把工程内引用、样式更新和旧工程迁移放在同一次格式变更中。

## 工程与编辑语义

工程用 `cue_styles` 存单句定义，每句只记一个 ID。轨道样式表要求条目有名称，且按参数匹配库样式；旧单句样式允许缺少名称和 ID，也支持第三方字段。独立表使两套已有数据都能无损读取。单句条目把工程 ID、可选库 ID 和原始定义分开，详见[工程契约](../engineering/JSON_SCHEMA.md)。

- 新选样式默认跟随。按库 ID 联动当前窗口的修改和改名；固定时只切换当前句引用。手工替换工程字体也会固定被替换的单句样式。
- 打开已有工程始终使用工程定义。本机库存在较新或不同的定义时，可显式批量更新；来源缺失时继续渲染保存的样式。旧快照一律固定，重新选样式才建立跟随。
- 旧快照按完整 JSON 内容和跟随状态去重，保留未知字段；三轨共用一张表。跨工程导入副字幕时重新映射引用，避免同名工程 ID 冲突。JS 与 Python 在输入边界迁移；编辑器预览、导出以及 Python 工程烧录都从工程解析参数。
- 撤销同时恢复字幕引用和样式表。重新打开只显示差异，撤销工程样式更新不修改用户级库。编辑器保存时移除未被引用的单句条目。

## 草案评审决定

旧样式迁移为固定、新选择默认跟随、重开手动更新是本草案采用的交互。请维护者确认这三项默认行为。使用新格式保存的 v2 文件需要支持单句引用的客户端才能正确还原样式；1.x 工程及带旧内联快照的 v2 工程首次保存时须另存新文件，取消或失败保留原件。

## 验收

1000 句相同旧快照只产生一项，迁移前后导出保持一致。另查三个轨道角色的固定与跟随、换机打开、撤销重做、拆分合并和跨工程导入。[人工核验](../logs/release1.11.2/261123_单句样式引用/单句样式.checklist.md)
