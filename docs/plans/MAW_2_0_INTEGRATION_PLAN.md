## 1. 已确认的产品与分支决策

### 1.1 产品目标

**完整 MAW 2.0 = 当前破坏性重构 + Launcher 改版 + Electron MOSE 桌面版 + Windows Installer 安装包。**

Starlight 是计划中的抢先体验渠道，可提前提供可测试的 2.0。它不是一套永久独占 Electron 的产品代码，也不是要求所有业务长期留在旧 `starlit` 分支。

| 对象 | 本计划中的职责 | 不应承担的职责 |
| --- | --- | --- |
| `main` | 当前公开稳定线；暂缓新功能，仅收维护者选定的必要修复 | 持续接收大量新功能，使 2.0 永远追赶 |
| 远端 `2.0dev` | 完整 2.0 的集成与验收基线 | 永远只承载轨道重构，不接产品交付能力 |
| 本地 `dev/v2.0` | 本次工作树的本地分支名；写计划时等于远端 `2.0dev` | 被误认为另一个独立产品或远端同名分支 |
| 旧 `starlit` / `merge/starlit-main` | 找回 Electron、Installer 及历史设计的只读来源 | 整条硬合进新基线，或未经保存就清理旧合并现场 |
| 新 Starlight 渠道 | 从验收过的 2.0 提交构建、分发、反馈 | 另养一套长期分叉的编辑器和工程 schema |

```text
main（1.x 稳定线） ──必要修复──> 2.0dev（完整 2.0）
                                   ▲       ▲
                        Launcher 改版   Electron / Installer 迁移
                                   │
                                   ├──验收过的快照──> Starlight 抢先体验
                                   └──正式验收后───> main / 2.0 正式版
```

**方向约束**：2.0 正式发布前不把破坏性重构反向带进 1.x main；最终回 main 是独立、需维护者授权的发布动作。功能修复回到 `2.0dev`，不能只留在渠道分支。

### 1.2 范围与非目标

本轮首批桌面交付验收以 **Windows x64** 为落地点。现有 macOS / Linux 的 CLI、Server、源码与打包支持不得回归；新 Electron 三端能力是否随首版 Starlight 一起交付，由维护者确认，不能把旧 CI 接线等同于原生验收完成。

| 必须包含 | 不自动包含 |
| --- | --- |
| v2 工程安全、现有 ASR / 编辑 / 导出工作流 | 更多 ASR 引擎、模型下载管理平台 |
| 新 Launcher 的真实配置、批量和工程操作 | 再做一次视觉重设计或引入前端框架 |
| Electron 壳及当前 Server 共用业务 | Tauri / Rust 双后端或另一份编辑器前端 |
| Installer 安装、升级、卸载与文件打开 | SDK、插件系统、通用快捷键自定义 |
| 可追溯的 Starlight 测试包与渠道隔离 | 支付、账号、DRM、授权服务或自动更新系统重写 |

旧更新器是可复用参考，不是 Installer 的同义词。**Installer 必须可安装；软件内自动更新可单独后续交付**，不得为赶首版而无校验地下载执行程序。

### 3.1 付费抢先体验的边界

GitHub 的 prerelease 标记**不提供付费访问控制**；公开仓库的公开附件不能被当作受限下载。D4 未确认时不得把候选包公开上传，也不得临时发明支付 / token 服务。

项目现有 AGPL 许可与第三方声明仍适用。付费可围绕提前获得官方构建 / 服务设计，但不能据此删除许可证、承诺收件人无再分发权，或忽略相应源码义务。分发承诺由维护者核对，AI 不自行改变许可。

## 4. 所有阶段共同遵守的硬要求

### 4.1 数据与格式不变量

1. v2 工程以 `tracks[]` 为字幕真源，引用使用稳定轨道 / 字幕 ID；旧容器仅在导入边界读取，不能为了迁就旧桌面代码恢复双真源。
2. v1、v1.5 及需要升级的早期 v2 首次写出新格式必须显式另存；取消、失败、自动保存、媒体重绑定与桌面入口均不能覆盖原件。未知未来版本在任何写盘前拒绝。
3. 字幕 / items 使用源媒体整数毫秒；迁移、换轨、身份和窗口动作不改变字幕时间。主、副、叠加当前仍各最多一条，不能暗中放开多副轨。
4. 说话人身份与颜色分开；同名同色不是同一身份。按维护者 2026-11-13 的[主轨权威决定](SPEAKER_IDENTITY_CORE_PLAN.md)，主轨分配或清除身份、分类颜色时单向同步显式绑定的副字幕（含隐藏轨），普通赋值不因时间重叠扩展范围。主轨来源身份一致即可联动合并；沿用显式绑定或至少 500ms 重叠的副轨收集规则，副轨合并结果采用主轨身份（主轨均未分配则副轨结果也未分配），实际改变副轨身份时提示。主轨自身跨身份、独立副轨与叠加轨跨身份合并仍拒绝；换轨、撤销、保存重开保留组、绑定、扩展字段与身份。
5. 波形 / 缩略图是可重建缓存；保存期间的新编辑不得被旧确认清掉，保存失败不得被当作成功离开窗口。

### 4.2 单一实现与安全边界

1. `web/` 是唯一前端，`server-editor/serve.py` 是唯一编辑后端；Electron 仅提供宿主能力。不得复制完整 Python / Rust 编辑后端或 fork 一份前端。
2. 服务只监听 `127.0.0.1`。Electron 保持 contextIsolation、sandbox、关闭 nodeIntegration，限制导航和 IPC 来源；不向页面开放通用文件读写 / shell 执行接口。
3. 桌面页面访问令牌与仅主进程持有的写命令密钥分离；秘密不进 URL、argv、Renderer 配置、日志或工程。路径来自受限原生选择 / 已登记引用，不相信网页任意传入的路径。
4. 进程清理只针对本实例实际拥有的 PID / 子树；不能按 python、node、MOSE 等名称全局结束进程。浏览器 Server 和桌面模式的权限必须分别测试。
5. 不读取、打印或提交维护者 `.env`；测试配置使用明确的虚构标记和隔离目录。提交文档不含个人路径、真实媒体、用户工程或账户 token。

### 4.3 工具、构建与协作

1. Windows 使用 pwsh 7.6+；长文本、中文正文、Markdown 反引号和多行脚本走 UTF-8 文件通道。全部文本保持 UTF-8 / LF。
2. 自动检查经 `scripts/run_check.py`，Python 业务测试经 `scripts/run_tests.py`；不搬运整份日志。Agent 的 uv 命令使用 `uv run --no-sync`，不自行同步共享 venv。
3. 改编辑器 / Launcher JS 或清单必须重建对应 bundle 并检查新鲜度；bundle 与 meta 不进 Git。新增模块必须检查装配顺序、ESM 工厂 / classic 边界与类型声明。
4. UI 明暗主题、中英文、焦点和键盘操作不能遗漏；相邻新增 UI 实测垂直间距至少 8px，截图自查。Mock 页面不能替代真实 pywebview / Electron / 安装版。
5. 不在有用户 WIP 的目录 rebase / reset / checkout 覆盖。默认用临时整合分支；Orca 工作树操作先加载 `orca-cli`，创建时显式选择 2.0 基线，不误从 main 或旧 starlit 开始。

2.0（含预发布）不生成、打包和部署独立 HTML / 在线编辑器；历史文件保留。此规则按**应用元数据版本**生效，而不是按分支名生效。不能误删本地应用共用的 HTML 渲染、模板、导入保存、备份恢复和导出。

### 10.2 渠道隔离的实现参考

若 D2 采纳并行安装，需同一处定义渠道身份并传遍 Launcher、MAW 后端、Electron 和 Installer。不能只改窗口标题：

| 身份面 | 必须处理 |
| --- | --- |
| 安装 | AppId、AppName、默认目录、卸载键、开始菜单；同渠道 AppId 跨版本稳定，不随每次版本生成 |
| 文件关联 | 渠道 ProgID、图标和 open command；尊重用户选择；卸载只移除自己拥有的关联 |
| Electron | appId、userData 路径、单实例锁 / IPC 命名空间，稳定与体验版可同时运行 |
| MAW 用户配置 | 优先复用 `maw/app_paths.py` 的进程级 `MAW_APP_DATA_ROOT`；统一 Launcher / Server / worker 的配置根，不改全局环境 |
| 数据导入 | 默认不自动复制稳定版 Key 或用户工程；配置迁移若需要由维护者批准，不能后台读写真实 `.env` |

`MAW_ENV_FILE` 与便携包旁 `.env` 的优先级同样要审查；仅隔离默认配置根还不够。桌面模式接到另一个渠道已经运行的实例也属于隔离失败。

渠道只接受固定允许值，由可信构建元数据 / 启动入口决定；不能由网页 URL 参数任意指定用户数据目录。路径覆盖须在相关模块首次解析路径前设置，并明确传给 Launcher、Electron 和其拥有的子进程，不污染全局环境。

### 10.4 自动更新与发布安全

| 静态 / 构建 / 类型 | 能解析、装配、类型与 bundle 新鲜度 | 用户能正确保存、拖动或安装 |

| 浏览器 / Electron 自动化 | 产品实现的交互与 IPC / 写盘 | 桩代替的系统 UI、人工观感、真实模型质量 |
| 实际包 / Installer | 冻结程序与安装生命周期 | 其他平台或所有用户权限组合 |
| 人工 / CI / 分发 | 人工行为、目标平台、真实附件与服务结果 | 不同层或不同 SHA 的全面验证 |

具体命令见执行手册。缺测试文件先调查路径变化，不删验收项、不换成永远通过的文本断言。脚本 `--help` 和参数以当前基线为准。

### 12.2 回归与独立审查

每阶段按受影响范围先小后大，不为每个文件反复跑全量。进入验收时需要有对应基线的完整必需自动化结果；skip、xfail、超时、取消和缺环境分别列出。全量用时可能超过旧经验值，运行器超时要明确设置，不无上限循环重跑。

功能 / 行为改动在提交或 PR 前执行独立审查，适用根规则要求时用未参与实现的后台审查 agent。finding 必须有文件 / 行与实际证据；修复新增测试至少有一次真实旧红新绿对照。没有委派工具就记录审查阻塞，不能把自己读一遍当独立审查。

P1 在 `--no-commit` 状态下 HEAD 仍是旧提交；审查必须覆盖暂存与未暂存的实际整合结果，不能仅看 `git diff <基线>...HEAD` 后宣布“无改动”。尚未提交的测试证据要写清对应工作树 diff，提交后再核对最终提交与已验内容一致。

源代码变了，对应层的旧结果失效；源码与环境未变的证据可复用。CI 绿色不代表全量 Python、全量浏览器或人工验收通过。

## 13. 中断恢复、停止与回退

### 13.1 每次只处理一个当前小批次

每个小批次完毕立即写账：来源 / 基线、变更、验证、未验收、下一步。每完成 2–3 个问题写一次阶段摘要。新反馈用 `feedback-issue-triage` 按主题记录，不直接开改。

| 情况 | 必须停止 / 降级的动作 |
| --- | --- |
| 当前出现不认识的 WIP、分支或 HEAD 改变 | 重读 status / diff 与账本，确认归属，不覆盖继续 |
| 准备引入旧 schema、第二份前后端或任意路径写 API | 停止，回到契约 / 安全设计；不是“先跑通再说” |
| 连续两次相同验证失败或服务挂起 | 分类原因，按进程归属清理；环境阻塞可降级待人工，但不能宣布通过 |
| 安装 / 更新会碰日常系统或稳定配置 | 不执行；换授权隔离环境，不能绕过保护 |
| 需要改付款、许可、密钥、发布目的地或共享历史 | 请求维护者决策，不自行假定 |

### 13.2 回退原则

临时分支可以保留失败尝试，保留证据优先于清场。需要放弃当前 merge 时，先确认它确由本任务新发起、开始前无 WIP且无后来他人修改；得到明确允许后才可 abort。不对旧 starlit 现场应用这个例外。

已共享的改动如需撤回，另做正常 revert / 修复，经维护者授权，不 force-push。工程升级不承诺 v2 回写 v1；用户回稳定版应打开保留的旧工程，不能用降级程序覆盖新工程。

失败构建和安装测试先停止本实例进程、保留日志；需要删除临时文件遵守回收站规则，不做宽路径递归清理。
